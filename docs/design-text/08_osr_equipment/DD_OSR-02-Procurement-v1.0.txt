 1. Purpose
 OSR-02 defines the SOPHIX procurement process for equipment and stockable materials.

 It covers the flow from a stock need to a purchase order, approval, vendor order, delivery receipt, goods receipt into stock,
 serialized equipment import, discrepancy handling, and reporting.

 Use OSR-02 when:

   - central warehouse needs more ONTs, routers, STBs, splitters, drop cable, or smart cards;

   - procurement creates a purchase order for a vendor;

   - finance/procurement approval is needed before sending the order;

   - warehouse receives vendor delivery;

   - received quantity differs from ordered quantity;

   - serialized devices must be created in OSR-INSTANCE-01;

   - SKU quantity movements must be recorded in OSR-01.

 OSR-02 does not own stock balances. OSR-01 owns SKU/location quantity movement and balance. OSR-INSTANCE-01
 owns per-serial equipment records. Procurement is the business process that triggers those owning modules.



 2. Scope And Boundaries
  Capability                                                        Owner

  Procurement request, PO, vendor delivery, receipt workflow        OSR-02

  SKU catalog and serialization flag                                PLM-CFG-06

  Stock movements and balances                                      OSR-01

  Serialized equipment instance creation/lifecycle                  OSR-INSTANCE-01

  Contractor/vendor/staff reference data                            EM-02 / EM business registry

  Procurement permissions                                           EM-CFG-03

  Configurable procurement approval                                 EM-CFG-04

  Operator-variable procurement rules                               Drools

  Notifications to procurement/warehouse teams                      ICN-01

  Procurement KPIs                                                  REP-01


 Boundary rules:

   - OSR-02 must not directly update stock_balance.

   - OSR-02 records goods receipt, then calls OSR-01 POST /api/stock-movements for quantity stock.

   - For serialized SKUs, OSR-02 calls OSR-INSTANCE-01 POST /api/equipment-instances/bulk-import or POST
     /api/equipment-instances.

   - Approval steps are owned by EM-CFG-04. OSR-02 stores only approval references and final outcome.

   - Camunda is used only when EM-CFG-04 selected policy mode is BPMN.

   - Drools is used for configurable vendor/order/discrepancy policy, not fixed validation.

 4. Status Models
 4.1 Procurement Order Status
  Status                                                          Meaning

  DRAFT                                                           PO is being prepared.

  VALIDATED                                                       SKU/vendor/basic checks passed.

  PENDING_APPROVAL                                                EM-CFG-04 approval request is open.

  APPROVED                                                        PO is approved but not sent.

  SENT_TO_VENDOR                                                  PO was sent to vendor.

  PARTIALLY_RECEIVED                                              Some lines received.

  RECEIVED                                                        All expected lines received.

  CLOSED                                                          PO closed after receipt or business decision.

  CANCELLED                                                       PO cancelled before completion.

  REJECTED                                                        Approval rejected.



 4.2 Goods Receipt Status
  Status                                                          Meaning

  DRAFT                                                           Receipt capture started.

  VALIDATED                                                       Receipt lines passed checks.

  POSTED                                                          OSR-01/OSR-INSTANCE writes completed.

  DISCREPANCY_PENDING                                             Quantity/serial/vendor discrepancy requires review.

  CANCELLED                                                       Receipt voided before posting.

 8. Rule Engine Guidance
 Use Drools for configurable procurement decisions:

  Rule file                                                                 Purpose

  procurement-order-approval.drl                                            Decide approval policy based on amount, vendor, SKU family, requester, and
                                                                            destination.

  goods-receipt-discrepancy.drl                                             Decide whether discrepancy is tolerable, blocked, or approval-required.

  vendor-risk-policy.drl                                                    Apply operator-specific vendor risk controls.


 Example:
              package com.sophix.osr.procurement

              rule "High value procurement requires finance approval"
              when
                $po : ProcurementOrderFact(totalAmount >= 1000000.00, currencyCode == "KES")
                $decision : ProcurementDecision()
              then
                $decision.setApprovalRequired(true);
                $decision.setApprovalPolicyCode("PROCUREMENT_HIGH_VALUE_FINANCE");
                $decision.addReason("HIGH_VALUE_PO");
              end

 11. Infrastructure Recommendations
 Run OSR-02 inside the OSR/equipment API deployment with OSR-01 and OSR-INSTANCE for a medium budget
 deployment.

  Component                                                      Recommendation

  API                                                            Add procurement endpoints to OSR API service.

  Database                                                       PostgreSQL OSR schema.

  Workers                                                        Shared OSR worker handles outbox and receipt posting retries.

  Files                                                          Use foundation file storage for uploaded delivery notes or serial CSV/XLSX.

  Approval                                                       EM-CFG-04 shared service.

  Rules                                                          Drools/KIE for configurable procurement rules.


 AWS notes: use ECS/EKS OSR service, RDS PostgreSQL, S3 for vendor documents/serial uploads, MSK/Kafka for events,
 Secrets Manager for vendor/API credentials.



 12. Acceptance Criteria
   - PO lifecycle APIs exist and are idempotent.

   - PO approval uses EM-CFG-04; OSR-02 does not hardcode approver steps.

   - Goods receipt posts accepted quantity through OSR-01 stock movements.

   - Serialized accepted units are created through OSR-INSTANCE-01.

   - Receipt discrepancies are tracked and resolvable with approval where configured.
