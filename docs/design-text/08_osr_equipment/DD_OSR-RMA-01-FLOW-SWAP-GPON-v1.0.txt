 1. What this flow is
 When a customer's GPON ONT fails — or NOC detects an imminent failure, or the customer requests an in-tech upgrade —
 there are two paths:

   - Remote-first (preferred): NOC unassigns the old ONT serial in the NMS (Network Management System for the OLT),
     couriers / customer-picks-up a new ONT, customer self-installs the new ONT in their existing fiber socket, NMS
     auto-discovers the new ONT serial and binds it. No truck roll. Recovery of the defective unit happens at next courier
     exchange or shop visit.

   - Field fallback: if customer can't or won't self-swap (elderly customer, customer doesn't open door for courier, customer
     reports doesn't understand the installation steps, etc.), the BPMN advances to field-visit pattern (same as SWAP-HFC but
     with NMS calls instead of Broadhub).

 Either path drives a HomePass update: the HomePass's network_path terminal node carries the ONT serial as its code;
 after the swap, that code must be updated to the new ONT serial. The homepass-network-path-update worker handles
 this at TARGET_PLACED.


SOPHIX BSS Design Documents                                                                                                                 Page 3
 A GPON swap creates two swap_kind values: GPON_REMOTE is created when the BPMN starts (default for GPON), and the
 swap-request is updated in-place to GPON_FIELD if/when the BPMN crosses the field-fallback boundary. Both kinds share
 the same equipment_swap_request row; only the swap_kind discriminator and
 flow_payload.remoteAttemptCount differ.

 What this flow does NOT do
   - Does not handle HFC equipment swaps. Use swap_kind=HFC_FIELD (separate FLOW-SWAP-HFC satellite).

   - Does not handle equipment termination retrieval — that's EQP_TERMINATION (separate FLOW-EQP satellite).

   - Does not validate slot/port preservation. GPON doesn't bind to a chassis slot/port for authorization (the OLT
     auto-discovers the serial). The OLT F/S/P (Frame/Slot/Port) is recorded as instance metadata but is not
     preservation-required; if the customer relocates within the same building and the new ONT lands on a different OLT port,
     the swap still completes (the OLT auto-discovery handles it). Relocation across HomePasses is a different flow
     (subscription relocation, not swap).

   - Does not handle the courier / shop pickup logistics. That's a separate workflow (TBD pending workshops on
     Wananchi's self-install kit fulfillment chain). This flow assumes the new ONT lands in the customer's hands via some
     out-of-band channel and the customer self-installs.

 Glossary additions (specific to this flow)
  Term                                                            Meaning

  OLT F/S/P                                                       OLT Frame / Slot / Port — the physical port on the GPON Optical Line Terminal
                                                                  to which the customer's fiber drop is connected. Used as instance metadata for
                                                                  traceability; not used for authorization.

  NMS remote unassign                                             The NMS API call that removes an ONT serial's authorization from the OLT.
                                                                  The fiber link remains; the ONT just stops being recognized.

  NMS auto-discovery                                              When a new ONT is powered on at a customer's premises and the OLT detects
                                                                  its serial, NMS auto-binds it if the serial is pre-registered. Wananchi runs the
                                                                  malogs portal (malogs.wananchi.com/gpon_auto_find/) which lists
                                                                  discovered ONTs with their F/S/P.

  Self-install kit                                                A pre-packaged box with new ONT + cables + 1-page instructions, sent to the
                                                                  customer via courier (or picked up at a Wananchi shop). Customer plugs in the
                                                                  new ONT; the OLT auto-discovers + NMS auto-binds (if the serial is
                                                                  pre-registered for the customer's account).

  Customer self-swap                                              Customer physically replaces the ONT themselves following the self-install kit
                                                                  instructions. Does not require a Wananchi technician on site.

 4. Rules (GPON-specific)
  Rule                                                                    Description

  R-GPON-1                                                                Source equipment_kind MUST be ONT. Eligibility worker rejects with
                                                                          failureCode=NOT_GPON_FAMILY otherwise.

  R-GPON-2                                                                Source network_slot_metadata.olt MUST be non-null. Eligibility worker
                                                                          rejects with failureCode=MISSING_OLT_REF otherwise — NMS adapter
                                                                          can't address the unbind without OLT identity.

  R-GPON-3                                                                NMS remote unassign retry: up to flow_payload.maxRemoteAttempts
                                                                          (default 3) attempts before transitioning to field fallback. Each retry increments
                                                                          remoteAttemptCount.

  R-GPON-4                                                                Self-install timeout: 14-day boundary timer on customer-ont-online
                                                                          message catch. If timer fires, BPMN transitions to field fallback (NOT to FAILED
                                                                          — Wananchi prefers to escalate to truck roll rather than abandon the customer).

  R-GPON-5                                                                HomePass terminal-node update (R-OSR-RMA-16 enforces):
                                                                          homepass-network-path-update worker MUST succeed at
                                                                          TARGET_PLACED. If it fails (HomePass not found, PATCH rejected by
                                                                          HomePass-CFG, etc.), swap-request → FAILED with
                                                                          transition_reason=HOMEPASS_NETWORK_PATH_UPDATE_FAILED.
                                                                          Source instance state rolled back to IN_FIELD_DEFECTIVE. NMS bind not
                                                                          rolled back (the customer's new ONT is online; manual reconciliation step
                                                                          needed to fix HomePass — Ops escalation).

  R-GPON-6                                                                If account is not bound to a HomePass (no account.homepass_id — rare,
                                                                          possibly migration data), homepass-network-path-update worker skips
                                                                          the call and writes networkPathUpdated=false with
                                                                          reason=NO_HOMEPASS_BINDING. Swap proceeds to COMPLETED. ICN-01
                                                                          notifies swap-dispatchers of the unbound account for review.

 7. Worked end-to-end example — Wanjiku's ONT swap (remote-first
 happy path)
 Customer: Wanjiku, WIK fiber subscriber (GPON, single-play internet, in warranty — purchased 6 months ago). Account
 acct_01HZ_WANJIKU bound to HomePass hp_01HZ_NRB_KILELESHWA_42B. ONT inst_01HZ_ONT_WANJIKU_OLD
 serial 48575443ABCD1234, on OLT nrb-olt-01 F1/S2/P3. Recovery contractor: wik-internal-tech-team (internal
 team handles GPON remote swaps in Nairobi central). New ONT inst_01HZ_ONT_WANJIKU_NEW (serial
 48575443BEEF5678) is in WIK main warehouse, pre-registered for Wanjiku's account.

 Day 0 — 09:15: NOC receives Wanjiku's call (ONT power LED off). NOC agent posts POST /api/swap-requests/gpon.
 Response 201: state ELIGIBILITY_CHECK.

 Day 0 — 09:15:30: Eligibility worker reads source instance metadata (OLT present), validates target SKU (Huawei
 EG8145V5 = same model), confirms warranty (purchase < 1 year, in warranty). Sets chargeable=false,
 chargeCode=null. Builds flow_payload. State advances directly to AWAITING_SLOT (no pay-first because not
 chargeable).

 Wait — that's wrong for the remote path. Remote-first doesn't reserve a slot. Eligibility worker recognizes GPON_REMOTE
 and advances directly to REMOTE_UNASSIGN_IN_PROGRESS (skipping AWAITING_SLOT). State machine allows
 ELIGIBILITY_CHECK → REMOTE_UNASSIGN_IN_PROGRESS for GPON_REMOTE per framework.

 Day 0 — 09:15:35: Worker nms-remote-unassign-stub fires:
          POST /nms-adapter/v1/ont/unassign
