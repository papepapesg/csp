 MVP simplification baseline: FA-01, FA-02, and FA-03 must be implemented as one field-audit capability in the first release,
 with audit_type driving type-specific rules, checklists, and routing. Do not create three services or three independent
 databases.



 1. Purpose
 FA-03 defines field audit of customer identity, KYC evidence, contactability, address/location match, consent, and customer
 presence/occupancy.

 Use FA-03 when:

   - KYC documents submitted during sales/order need field verification;

   - a customer record has duplicate, suspicious, incomplete, or expired KYC data;

   - installation/support teams must confirm customer identity at site;

   - compliance needs a campaign to verify customer records in an area;

   - contact/address mismatch blocks activation, billing, support, or recovery;

   - a rejected/incomplete KYC case needs field evidence before approval.

 FA-03 does not own customer master data. ILM-CFG-01 owns customer, account, KYC, contact methods, and address
 records. FA-03 stores audit tasks/evidence and requests approved ILM corrections.

   - FA-03 does not directly edit ILM customer/KYC records.

   - FA-03 stores field evidence and discrepancy decisions.

   - ILM-CFG-01 applies approved KYC/contact/address corrections.

   - FUL-02-STEP-KYC remains the owner of order-time KYC task state.

   - WO-01 owns dispatch if a field visit is required.

   - KYC documents must be stored through foundation file storage with restricted access.

 3. Process Overview
            flowchart LR
              A["Backoffice creates KYC audit"] --> B["FA-03 loads ILM customer/KYC snapshot"]
              B --> C["Assign task or create WO"]
              C --> D["Field user verifies customer/site/evidence"]
              D --> E["FA-03 compares expected vs observed"]
              E --> F{"Issue?"}
              F -- "No" --> G["Close audit verified"]
              F -- "Yes" --> H["Open discrepancy"]
              H --> I["Drools route"]
              I --> J["ILM correction / TCK case / approval / notification"]

 7. Rules And Drools
 Recommended packages:

   - rules.field_audit.kyc.scope

   - rules.field_audit.kyc.severity

   - rules.field_audit.kyc.routing

   - rules.field_audit.kyc.approval
          package rules.field_audit.kyc.severity

          rule "Identity mismatch is critical"
          when
            $f : KycFieldAuditFact(discrepancyType == "IDENTITY_MISMATCH")
            $d : KycFieldAuditDecision()
          then
            $d.setSeverity("CRITICAL");
            $d.route("REQUEST_KYC_REVIEW");
          end

          package rules.field_audit.kyc.routing

          rule "Address mismatch requests ILM correction"
          when
            $f : KycFieldAuditFact(discrepancyType == "ADDRESS_MISMATCH",
                                   evidenceComplete == true)
            $d : KycFieldAuditDecision()
          then
            $d.route("REQUEST_ILM_CORRECTION");
            $d.requireApproval("KYC_FIELD_AUDIT_ADDRESS_CORRECTION");
          end

 9. Security And Privacy
   - Do not store raw ID numbers in FA-03 tables.

   - Store KYC/identity photos in restricted file storage only.

   - Mask sensitive fields in snapshots.
