 MVP simplification baseline: EM-03 starts as rule-based CVM queues, offers, outcomes, and activity tracking. Do not build an
 ML platform, campaign automation suite, or separate analytics warehouse for CVM in the first release. Use
 REP-01/BIL/SUB/TCK inputs and call owning module APIs for actions.



 1. Purpose
 EM-03 defines customer value management processes for retention, recovery, churn prevention, upsell/cross-sell targeting,
 win-back, and customer outreach activity management.

 Use EM-03 when:

   - a customer enters dunning or repeated payment risk;

   - a subscription is downgraded, restricted, suspended, cancelled, or at churn risk;

   - a customer repeatedly opens support complaints or installation issues;

   - commercial teams want retention offers, recovery activities, or win-back campaigns;

   - marketing/CVM needs to create targeted customer cohorts and assign outbound activities;

   - the system must track offer outcomes and customer interaction history.

 EM-03 does not own customer master, billing, subscription state, campaigns, discounts, or notification delivery. It consumes
 events and calls owning module APIs.

 Boundary rules:

   - EM-03 does not directly apply discounts. It calls SIP-03 or campaign/discount APIs.

   - EM-03 does not directly resume, restrict, or cancel subscriptions. It calls SUB/BIL workflows.

   - EM-03 does not send SMS/email directly. It requests NOT-01 notification.

   - EM-03 writes interaction/activity events to CUST-INT-01.

   - EM-CFG-04 is used for non-standard retention offers, manual overrides, or high-value discounts.

 6. Rules And Drools
 Recommended packages:

   - rules.cvm.segmentation

   - rules.cvm.activity

   - rules.cvm.offer

   - rules.cvm.approval
          package rules.cvm.segmentation

          rule "High risk dunning customer"
          when
            $f : CvmCustomerFact(dunningLevel >= 2,
                                 complaintCount90d >= 2)
            $d : CvmDecision()
          then
            $d.addSegment("RETENTION_HIGH_RISK");
            $d.createActivity("PAYMENT_RECOVERY", "HIGH");
          end

          package rules.cvm.offer

          rule "Retention discount needs approval above threshold"
          when
            $f : CvmOfferFact(offerType == "RETENTION_DISCOUNT",
                               discountPercent > 10)
            $d : CvmDecision()
          then
            $d.requireApproval("CVM_HIGH_VALUE_RETENTION_OFFER");
          end

 8. Implementation Notes
   - Start with rules-based segmentation before ML scoring.

   - Keep score explanations visible; do not create unexplained retention actions.

   - CVM workers can be consolidated with reporting/event consumers if volume is low.

   - All customer contact attempts must write to CUST-INT-01.

   - Use REP-01 for dashboards; EM-03 should not build its own BI store.



 9. Test Scenarios
   1. Dunning event updates signal profile.

   2. High-risk customer enters retention segment.

   3. CVM activity is idempotent by source event.

   4. Offer over threshold calls EM-CFG-04.

   5. Accepted discount offer calls SIP-03, not DIS-OP directly.

   6. Notification request goes through NOT-01.

   7. Interaction is written to CUST-INT-01.
