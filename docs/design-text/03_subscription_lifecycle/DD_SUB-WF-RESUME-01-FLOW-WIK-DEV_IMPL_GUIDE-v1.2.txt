 DEV_IMPL_GUIDE - SUB-WF-RESUME-01-FLOW-WIK
 1. Purpose
 This guide explains how to implement and test the WIK resume BPMN as the flow executes at runtime.

 Use it with:

   - DD_SUB-WF-RESUME-01-FLOW-WIK-v1.2.md

   - DD_SUB-WF-RESUME-01-Subscription_Resume-v1.2.md

   - DD_SUB-WF-FRAMEWORK-01-Subscription_Workflow_Framework-v1.0.md

   - DD_SUB-WF-FRAMEWORK-01-WORKERS-v1.0.md

 This guide is specific to the BPMN process file:
            sub-resume-wik.bpmn



 2. Runtime Actors
  Runtime component                                              Role in this flow

  subscription-workflow-api pod                                  Receives WIK resume request and calls the shared operation framework.

  SUB-LM service/module                                          Provides authoritative subscription summary and status mutation APIs.

  Pause/history persistence                                      Provides and closes the open pause-history row.

  Drools                                                         Evaluates rules.subscription.resume.wik.

  Camunda                                                        Runs process sub-resume-wik.

  Worker apps                                                    Execute external task topics from the BPMN. One app can handle many topics.

  BIL-01                                                         Evaluates RESUME_INTENT or RESUME_NP_INTENT.

  BIL-04                                                         Calls dunning resume after debt settlement.

  FUL-03                                                         Reactivates service.

  Message correlators                                            Correlate payment and fulfillment messages back to Camunda.

  NOT-01                                                         Sends customer notification after success.

  FOUNDATION_SCHEDULER                                           Calls scheduled auto-resume when a pause row is due.

 5. Step 2 - API Pod Validates Shape And Idempotency
 The subscription-workflow-api pod validates:

  Field                                                          Validation

  operatorCode                                                   Required and must be WIK for this BPMN.

  resumeTrigger                                                  One of the four parent DD trigger values.

  resumeReasonCode                                               Required.

  dunningCycleReference                                          Required when trigger is DUNNING_RESUME.

  adminForceResumeReason                                         Required when admin force-resuming SUSPEND_NP.


 Idempotency behavior:

   - First request inserts the operation and starts BPMN.

   - Same Idempotency-Key with same request hash returns the existing operation response.

   - Same Idempotency-Key with a different request hash must return 409 IDEMPOTENCY_KEY_REUSED.

 Implementation note:

 Do not insert a new operation before checking existing key and request hash. Use a transaction or unique constraint on the
 idempotency key plus operator/operation scope so concurrent duplicate requests cannot create two operations.

 8. Drools Rules To Configure
 8.1 Suspended Subscription
          rule "WIK resume requires suspended subscription"
          when
            $req: ResumeRequestFact()
            $sub: SubscriptionStateFact(subscriptionId == $req.subscriptionId, statusCode != "SUSPENDED")
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("INVALID_STATE_FOR_RESUME")
            }
          end


 8.2 Open Pause Row
          rule "WIK resume requires open pause history"
          when
            $req: ResumeRequestFact(eligible == null)
            not (PauseHistoryFact(subscriptionId == $req.subscriptionId, actualResumeAt == null))
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("NO_OPEN_PAUSE_HISTORY")
            }
          end


 8.3 Trigger Role Gating
          rule "WIK customer resume allowed roles"
          when
            $req: ResumeRequestFact(
               resumeTrigger == "CUSTOMER_REQUESTED_RESUME",
               eligible == null,
               initiatingActorRole not in ("CUSTOMER_SELF_SERVICE", "CALL_CENTER", "SUBSCRIPTION_OPERATOR")
            )
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("ROLE_NOT_AUTHORIZED_FOR_TRIGGER")
            }
          end

          rule "WIK admin force resume allowed roles"
          when
            $req: ResumeRequestFact(
               resumeTrigger == "ADMIN_FORCE_RESUME",
               eligible == null,
               initiatingActorRole not in ("SUBSCRIPTION_ADMIN", "SUBSCRIPTION_OPERATOR")
            )
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("ROLE_NOT_AUTHORIZED_FOR_TRIGGER")
            }
          end

          rule "WIK dunning resume requires billing internal"
          when
            $req: ResumeRequestFact(
               resumeTrigger == "DUNNING_RESUME",
               eligible == null,
               initiatingActorRole != "BILLING_INTERNAL"
            )
          then
            modify($req) {

 8.4 Origin-Intent Gating
          rule "WIK customer cannot resume admin pause"
          when
            $req: ResumeRequestFact(resumeTrigger == "CUSTOMER_REQUESTED_RESUME", originGatingAllowed == null)
            $pause: PauseHistoryFact(subscriptionId == $req.subscriptionId, actualResumeAt == null, originIntent == "ADMIN_PAUSE")
          then
            modify($req) {
               setOriginGatingAllowed(false);
               setOriginGatingReasonCode("ADMIN_PAUSE_BLOCKS_CUSTOMER_RESUME")
            }
          end

          rule "WIK customer cannot resume non payment suspension"
          when
            $req: ResumeRequestFact(resumeTrigger == "CUSTOMER_REQUESTED_RESUME", originGatingAllowed == null)
            $pause: PauseHistoryFact(subscriptionId == $req.subscriptionId, actualResumeAt == null, originIntent == "SUSPEND_NP")
          then
            modify($req) {
               setOriginGatingAllowed(false);
               setOriginGatingReasonCode("SYSTEM_MANAGED_SUSPENSION")
            }
          end

          rule "WIK dunning resume only resumes non payment suspension"
          when
            $req: ResumeRequestFact(resumeTrigger == "DUNNING_RESUME", originGatingAllowed == null)
            $pause: PauseHistoryFact(subscriptionId == $req.subscriptionId, actualResumeAt == null, originIntent != "SUSPEND_NP")
          then
            modify($req) {
               setOriginGatingAllowed(false);
               setOriginGatingReasonCode("NOT_A_DUNNING_SUSPENSION")
            }
          end

          rule "WIK scheduled auto resume blocks non payment suspension"
          when
            $req: ResumeRequestFact(resumeTrigger == "SCHEDULED_AUTO_RESUME", originGatingAllowed == null)
            $pause: PauseHistoryFact(subscriptionId == $req.subscriptionId, actualResumeAt == null, originIntent == "SUSPEND_NP")
          then
            modify($req) {
               setOriginGatingAllowed(false);
               setOriginGatingReasonCode("NOT_A_SCHEDULED_RESUME")
            }
          end

          rule "WIK scheduled auto resume requires resume scheduled at"
          when
            $req: ResumeRequestFact(resumeTrigger == "SCHEDULED_AUTO_RESUME", eligible == null)
            $pause: PauseHistoryFact(subscriptionId == $req.subscriptionId, actualResumeAt == null, resumeScheduledAt == null)
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("NO_SCHEDULED_RESUME_TIME")
            }
          end

 14. Step 10 - BPMN Evaluates Optional Payment Gateway
 Gateway condition:
          ${requiresReconnectionFeePayment == true}

 For WIK v1.2 default config:
          requiresReconnectionFeePayment == false

 So the BPMN skips payment and continues to FUL-03.

 If future WIK config enables a reconnection fee, the BPMN runs:
          bil01-charge-pre-authorize
          wait payment-confirmed with boundary timer P7D
          bil01-confirm-charge

 Payment timeout route:
          bil01-revert-pending-charge
          sub-lm-revert-to-prior
          kafka-emit SubscriptionResumeRejected
          subscription-operation-finalize FAILED

 These names are worker topics or BPMN message names, not shell commands.

 22. Compensation Flow Details
 22.1 Drools Rejection
 No mutation should have happened yet.

 Flow:
           kafka-emit SubscriptionResumeRejected
           subscription-operation-finalize FAILED


 22.2 Billing Or Debt Failure
 If BIL-01 reports debt still open:
           sub-lm-revert-to-prior
           kafka-emit SubscriptionResumeRejected with DEBT_NOT_CLEARED
           subscription-operation-finalize FAILED

 If a reconnection fee charge exists or payment times out:
           bil01-revert-pending-charge
           sub-lm-revert-to-prior
           kafka-emit SubscriptionResumeRejected
           subscription-operation-finalize FAILED


 22.3 Fulfillment Failure
 If FUL-03 returns fulfillment-failed:
           bil01-revert-pending-charge if billableEventId exists
           sub-lm-revert-to-prior
           kafka-emit SubscriptionResumeRejected
           subscription-operation-finalize FAILED


 22.4 Commit Failure After Network Reactivation
 If pause-history close-out or sub-lm-commit-state repeatedly fails, route to manual recovery.

 Reason:

 The network may already be active. Automatic rollback can be unsafe because the workflow may not know whether
 downstream reactivation fully completed.

 25. Common Mistakes
   - Treating worker-topic names as shell commands.

   - Reading current subscription status from cache.

   - Starting BPMN without loading the open pause-history row.

   - Writing resume_reason_code = resumeTrigger; use resumeReasonCode.

   - Letting customers self-resume SUSPEND_NP.

   - Letting BIL-04 dunning-resume voluntary pauses.

   - Removing the payment gateway because WIK default has no reconnection fee.

   - Closing pause history before FUL-03 succeeds.

   - Emitting SubscriptionResumed before sub-lm-commit-state.

   - Failing the whole operation because NOT-01 notification failed.
