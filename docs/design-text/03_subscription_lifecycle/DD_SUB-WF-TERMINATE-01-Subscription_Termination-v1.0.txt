 DD_SUB-WF-TERMINATE-01 - Subscription Termination
 Developer implementation guide: DD_SUB-WF-TERMINATE-01-DEV_IMPL_GUIDE-v1.0.md.


 1. Purpose
 SUB-WF-TERMINATE-01 defines permanent subscription termination.

 Termination moves a subscription to:
           TERMINATED

 TERMINATED is a terminal state. A terminated subscription must not be activated, paused, resumed, suspended, or restricted
 again. A new service for the customer must use a new subscription.

 Use this operation when:

   - A customer requests cancellation.

   - A BO admin closes a subscription.

   - BIL-04 reaches final dunning termination.

   - A contract-expiry scheduler terminates an expired contract.


 2. Mental Model
 Termination is a saga:
           flowchart LR
               API[Terminate endpoint] --> INT[Interrupt in-flight operation]
               INT --> FW[SUB-WF framework]
               FW --> BPMN[Terminate BPMN]
               BPMN --> RULES[Drools validation]
               BPMN --> PEND[SUB-LM PENDING_TERMINATION]
               BPMN --> BIL[Billing termination intent]
               BPMN --> FUL[FUL-05 revoke service]
               BPMN --> HP[Release HomePass]
               BPMN --> LM[SUB-LM TERMINATED]
               BPMN --> EVT[Kafka event]
               EVT --> RMA[Equipment collection]
               BPMN --> NOTIF[Notification]

 The most important output is not only the status. It is the combination of:

   - final status TERMINATED

   - termination master fields on subscription

   - billing settlement

   - network/service revocation

   - HomePass release

   - equipment disposition

   - SubscriptionTerminated event

 Termination is not a standalone service.

   - Terminate route/controller in SUB-WF API.

   - Termination config migration.

   - Termination BPMN, such as sub-terminate-wik.

 6. Equipment Disposition
 Equipment disposition tells downstream systems what to do with customer-premise equipment.

  Disposition                                 Meaning                                               Typical downstream behavior

  CUSTOMER_RETAINS                            Customer keeps equipment.                             No collection work order.

  WRITTEN_OFF                                 Equipment is written off.                             No collection attempt, finance/reporting audit.

 7. Data Model
 7.1 subscription_termination_config
 What this table is for:

 subscription_termination_config stores operator-level termination policy. It controls cooling-off behavior, default
 equipment handling, dunning write-off behavior, self-service enablement, supervisor override, and churn-save routing.

 Use this table when:

   - Validating customer self-service termination.

   - Resolving default equipment disposition.

   - Deciding whether dunning termination can auto write off debt/equipment.

   - Computing cooling-off window.

   - Deciding whether supervisor override or churn-save step is needed.

 Do not use this table for:

   - Current subscription status.

   - Actual billing settlement calculation.

   - Actual equipment inventory ownership.

   - Network revocation decisions.
           CREATE TABLE subscription_termination_config (
              operator_code                       TEXT PRIMARY KEY,
              cooling_off_window_days             INTEGER NOT NULL DEFAULT 7,
              default_equipment_disposition       TEXT NOT NULL DEFAULT 'PENDING_COLLECTION',
              dunning_equipment_disposition       TEXT NOT NULL DEFAULT 'PENDING_COLLECTION',
              dunning_auto_write_off_threshold    NUMERIC(18,2) NULL,
              dunning_auto_write_off_currency     TEXT NULL,
              customer_self_service_enabled       BOOLEAN NOT NULL DEFAULT FALSE,
              cooling_off_supervisor_override     BOOLEAN NOT NULL DEFAULT FALSE,
              churn_save_attempt_enabled          BOOLEAN NOT NULL DEFAULT FALSE,
              updated_at                          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
              updated_by                          TEXT NOT NULL,
              CHECK (default_equipment_disposition IN ('CUSTOMER_RETAINS','PENDING_COLLECTION','WRITTEN_OFF')),
              CHECK (dunning_equipment_disposition IN ('CUSTOMER_RETAINS','PENDING_COLLECTION','WRITTEN_OFF')),

 7.2 Subscription Termination Master Fields
 What this data is for:

 Termination writes final audit fields onto the subscription master record. SUB-LM owns the actual subscription table and
 state machine.

 Use this data when:

   - Showing support why a subscription was terminated.

   - Preventing future lifecycle operations on a terminated subscription.

   - Building events and reports.

   - Auditing dunning/admin/customer termination.

 Fields written by termination:

  Field                                               Purpose                                                   Sample

  terminated_at                                       Actual termination timestamp.                             2026-07-20T14:30:18Z

  termination_trigger                                 Trigger that started termination.                         CUSTOMER_REQUESTED

  termination_reason_code                             Operator/CVM reason.                                      CUSTOMER_MOVED_NO_COVERAGE

  prior_status_at_termination                         Status before termination saga started.                   ACTIVE

  contract_started_at                                 Contract start snapshot.                                  2024-01-20T10:00:00Z

  contract_end_at                                     Contract end snapshot, if applicable.                     2026-01-20T10:00:00Z

  contract_minimum_term_months                        Contract minimum term.                                    12




 8. Business Rules
 8.1 State And Concurrency Rules
  Rule                                                                            Description

  R-TERM-S-1                                                                      Termination rejects subscriptions already TERMINATED with 409
                                                                                  ALREADY_TERMINATED.




SOPHIX BSS Design Documents                                                                                                                                Page 4
  Rule                                                         Description

  R-TERM-S-2                                                   Termination is terminal. No future lifecycle operation may mutate the
                                                               subscription after success.

  R-TERM-S-3                                                   Termination may interrupt another in-flight state operation on the same
                                                               subscription.

  R-TERM-S-4                                                   If another operation is in-flight, framework sends
                                                               external-cancel-requested, waits up to 60 seconds, then starts
                                                               termination after cancellation acknowledgement.

  R-TERM-S-5                                                   During the saga, subscription moves to PENDING_TERMINATION before final
                                                               TERMINATED.



 8.2 Trigger Rules
  Rule                                                         Description

  R-TERM-T-1                                                   Trigger must be one of the four values in section 5.

  R-TERM-T-2                                                   Actor role must match the trigger role set.

  R-TERM-T-3                                                   CUSTOMER_SELF_SERVICE requires operator config enabled.

  R-TERM-T-4                                                   terminationReasonCode is required and passed through to reporting/CVM.



 8.3 Cooling-Off Rules
  Rule                                                         Description

  R-TERM-C-1                                                   Cooling-off applies only to CUSTOMER_REQUESTED.

  R-TERM-C-2                                                   A termination is in cooling-off when activated_at +
                                                               cooling_off_window_days >= requestTime.

  R-TERM-C-3                                                   Cooling-off result is sent to BIL-01 in TERMINATION_INTENT.

  R-TERM-C-4                                                   If cooling_off_supervisor_override = true, BPMN includes a
                                                               supervisor decision step.



 8.4 Settlement Rules
  Rule                                                         Description

  R-TERM-B-1                                                   BPMN sends TERMINATION_INTENT to BIL-01.

  R-TERM-B-2                                                   BIL-01 returns line items, totals, refund amount, early termination fee, and
                                                               write-off marker.

  R-TERM-B-3                                                   Settlement result is included in SubscriptionTerminated.

  R-TERM-B-4                                                   Termination does not hand-code billing amounts in SUB-WF.



 8.5 Fulfillment And Equipment Rules
  Rule                                                         Description

  R-TERM-F-1                                                   BPMN calls FUL-05 to revoke network/service access.

  R-TERM-F-2                                                   BPMN calls HomePass release worker after service revoke succeeds.

  R-TERM-F-3                                                   Equipment bindings are passed to FUL-05 and included in the event.

  R-TERM-F-4                                                   OSR-RMA-01 creates pickup work order from SubscriptionTerminated
                                                               when disposition is PENDING_COLLECTION.

 14. Infrastructure Recommendations
 Termination does not need separate infrastructure from SUB-WF.

 Deploy:

  Artifact                                                          Where

  Terminate endpoint/controller                                     SUB-WF API pods.

  Termination config migration                                      Application DB migration pipeline.

  Termination BPMN files                                            Camunda deployment pipeline.

  Termination Drools packages                                       Drools/KIE deployment pipeline.

  Termination worker usage                                          Worker pods/apps from worker DD.


 Monitor:

   - Termination request count by trigger.

   - Termination failure count by rejection code.

   - In-flight interruption failures.

   - FUL-05 revocation failures.

   - HomePass release failures/stub usage.

   - Operations stuck in PENDING_TERMINATION.

   - Outbox backlog for subscription.terminated.

 Medium budget deployment recommendation:

   - Run termination API inside existing SUB-WF API pods.

   - Run termination workers inside the shared subscription worker deployment.

   - Do not create a dedicated termination worker pod unless volume, security, or operational isolation requires it.

   - Add alerts for terminal-state failures because manual recovery is harder after network revocation starts.
