 DEV_IMPL_GUIDE - FE-APP-02 Outdoor Sales Franchise
 App
 1. Implementation Objective
 Implement the outdoor sales/franchise app for lead capture, territory work, HomePass/package lookup, customer/order
 capture, payment handoff, document upload, and order status tracking.

 3. Build Order
   1. Implement login, operator/franchise context, and territory assignment display.

   2. Implement lead capture and follow-up through SALES-01.

   3. Implement HomePass/serviceability search through RLM.

   4. Implement package selection through SIP.

   5. Implement customer/KYC capture through ILM and file storage.

   6. Submit converted order to FUL-02.

   7. Show payment instructions/status through BIL/PAY-GW.

   8. Show order status from FUL-02.

   9. Add offline draft support only for lead/order draft data, never for committed business state.


 4. MVP Scope
 Start with lead capture, serviceability check, package selection, customer/order capture, payment handoff, and order status.
 Advanced commissions, complex campaign logic, and territory optimization are later scope.


 5. Tests
   - Lead creation and conversion to order.

   - Duplicate lead/customer handling.

   - HomePass unavailable path.

   - Offline draft save/resume.

   - Payment status refresh.

   - Order submission idempotency.

 7. Offline Draft State
 Store only sales drafts locally:
            type SalesDraft = {
               localDraftId: string;
               leadId?: string;
               status: "DRAFT" | "READY_TO_SUBMIT" | "SYNCING" | "CONFLICT" | "SUBMITTED";
               customer: {
                  fullName: string;
                  phone: string;
                  idNumber?: string;
                  preferredLanguage?: string;
               };
               location: {
                  gps?: { lat: number; lng: number; accuracyM?: number };
                  addressText?: string;
                  selectedHomepassId?: string;
               };
               packageRef?: string;
               accountIntent: "NEW_ACCOUNT" | "EXISTING_ACCOUNT";
               attachments: Array<{ localUri: string; filePurpose: "ID" | "PROOF_OF_ADDRESS" | "OTHER" }>;
               idempotencyKey: string;
               updatedAt: string;
            };

 Never store committed customer/account/subscription state as truth. After sync, reload the created order/customer/account
 from ILM/FUL APIs.


 8. Flow - Lead To Order
   1. Sales agent creates or updates a lead in SALES-01.

   2. App checks serviceability through RLM-CFG-01 using GPS/address/homepass reference.

   3. App loads eligible packages from SIP-01 for operator, region, channel, and HomePass capabilities.

   4. App captures customer/KYC data and uploads documents through FOUNDATION_FILE_STORAGE.

   5. App submits order to FUL-02:
            POST /api/orders
            Idempotency-Key: sales-order:{localDraftId}
            Content-Type: application/json

            {
                 "operatorCode": "WIK",
                 "salesChannel": "OUTDOOR_FRANCHISE",
                 "franchiseId": "fr_001",
                 "leadId": "lead_01HZ",
                 "customer": {
                    "fullName": "Mary Wanjiku",
                    "phone": "+254700000001",
                    "preferredLanguage": "en"
                 },
                 "account": {
                    "accountLabel": "Home",

 9. Conflict Handling
  Conflict                                                    UI handling

  Duplicate phone/customer                                    Show matched customer candidates from ILM; agent chooses reuse or continue
                                                              with supervisor permission if allowed.

  HomePass became unavailable                                 Mark draft CONFLICT; force serviceability refresh and package revalidation.

  Package retired while offline                               Mark draft CONFLICT; reload SIP packages and require new selection.

  Order idempotency replay                                    Show existing order returned by FUL-02; do not submit a second order.
