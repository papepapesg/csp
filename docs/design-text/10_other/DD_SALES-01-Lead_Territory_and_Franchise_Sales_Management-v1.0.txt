 1. Purpose
 This DD defines the commercial sales module used by the Outdoor Sales / Franchise App.

 SALES-01 owns commercial leads, lead assignment, sales territories, franchise sales teams, sales activity tracking, and
 lead-to-order conversion references. It prevents the sales frontend from storing leads locally or misusing FUL-02 as a lead
 CRM.

 FUL-02 remains the owner of submitted customer orders. SALES-01 owns the pre-order commercial pipeline.

 Commission scope decision: SALES-01 records attribution events needed for future commission reporting, but it does not
 calculate payable commissions or create settlement/payroll obligations in v1. Commission payout is deliberately deferred to a
 future finance/commission DD so the first release can support sales attribution without introducing payroll liability logic.


 3. Relationship To EM-02
 EM-02 already owns contractor, staff, team, and agent registry. SALES-01 does not duplicate those records.

 SALES-01 references EM agents/teams:

  SALES concept                                                   Source

  Sales agent user                                                em_agent where agent_kind = 'sales-rep' and linked to
                                                                  FOUNDATION_AUTH user id.

  Sales team                                                      em_team where team_kind is sales/franchise sales.

  Franchise/contractor entity                                     em_contractor where contractor type is FRANCHISE or configured
                                                                  commercial partner type.

  Supervisor/team lead                                            em_agent_team_membership with role lead or supervisor mapping.


 Rule: do not create separate sales-user tables unless they store sales-specific state. Person/team identity remains in EM.


 4. Frontend Usage
 Primary frontend:

   - FE-APP-02 Outdoor Sales / Franchise App

 9. Integration Rules
  Rule                                                                 Description

  SALES-1                                                              Lead creation must check for duplicate active lead by phone/homepass before
                                                                       insert. Same idempotency key returns same lead.

  SALES-2                                                              Lead conversion must be transactional inside SALES-01 for lead
                                                                       status/conversion row, but FUL-02 remains order owner. If FUL order creation
                                                                       fails, lead stays QUALIFIED with conversion failure detail.

  SALES-3                                                              SALES-01 must call ILM/RLM/SIP APIs for qualification. It must not read their
                                                                       DBs.

  SALES-4                                                              FE-APP-02 offline drafts are not authoritative leads until submitted to
                                                                       SALES-01.

  SALES-5                                                              Commission payout must not be calculated from mutable lead fields. Use
                                                                       immutable sales_attribution_event.

  SALES-6                                                              A converted lead cannot be reassigned unless supervisor explicitly corrects
                                                                       attribution through an audited endpoint.

  SALES-7                                                              If a duplicate customer/order is found, return a structured conflict and link to
                                                                       allowed existing record details.

 14. Implementation Notes
 Start with:

   1. Create territory and lead tables.

   2. Implement create/list/detail/update lead APIs.

   3. Integrate EM agent/team lookup.

   4. Implement duplicate detection by phone and HomePass.

   5. Implement qualification wrapper calling RLM/SIP/ILM.

   6. Implement convert-to-order with FUL-02.

   7. Emit lead and attribution events through outbox.

   8. Add FE-APP-02 screen mappings and E2E tests.
