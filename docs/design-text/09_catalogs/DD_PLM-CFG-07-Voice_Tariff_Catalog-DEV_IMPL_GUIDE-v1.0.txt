 1. How To Read This Guide
 This guide follows the flow a developer should implement.

 The catalog does not rate CDRs. It only stores and exposes tariff data. RAT-01 calls the lookup API and performs the charge
 calculation.

 3.1 Prefix Match Logic
 Use longest-prefix match.

 Pseudo-code:
          public function resolveZone(string $operatorCode, string $calledNumber, Carbon $callStartedAt): ?DestinationZone
          {
              return VoiceDestinationPrefix::query()
                  ->where('operator_code', $operatorCode)
                  ->where('status', 'ACTIVE')
                  ->where('effective_from', '<=', $callStartedAt)
                  ->where(function ($q) use ($callStartedAt) {
                      $q->whereNull('effective_to')->orWhere('effective_to', '>', $callStartedAt);
                  })
                  ->whereRaw('? like prefix || \'%\'', [$calledNumber])
                  ->orderByRaw('length(prefix) desc')
                  ->orderByDesc('match_priority')
                  ->first()?->zone;
          }

 If no prefix is found, return no zone. RAT-01 must quarantine the CDR instead of rating it.

 6.1 Validate Rate Overlap
 Before activation, reject two active or draft rates that overlap for:
          operator_code
          tariff_plan_id
          zone_id
          time_band_id
          call_direction
          effective date range

 Pseudo-code:
          public function assertNoRateOverlap(VoiceTariffRate $candidate): void
          {
              $overlap = VoiceTariffRate::query()
                  ->where('operator_code', $candidate->operator_code)
                  ->where('tariff_plan_id', $candidate->tariff_plan_id)
                  ->where('zone_id', $candidate->zone_id)
                  ->where('time_band_id', $candidate->time_band_id)
                  ->where('call_direction', $candidate->call_direction)
                  ->whereIn('status', ['DRAFT', 'ACTIVE'])
                  ->where('rate_id', '<>', $candidate->rate_id)
                  ->where('effective_from', '<', $candidate->effective_to ?? '9999-12-31')
                  ->whereRaw('coalesce(effective_to, timestamp \'9999-12-31\') > ?', [$candidate->effective_from])
                  ->exists();

               if ($overlap) {
                   throw new DomainException('VOICE_RATE_OVERLAP');
               }
          }

  SERVICE                                                         Fallback if package has no binding.




 9. Step 8 - Activate Plan
 Validation before activation:

   1. Plan has at least one active/future rate.

   2. Every chargeable active zone used by prefixes has at least one rate.

   3. Emergency zone has zero-rated rate.

   4. No rate overlaps.

   5. Currency is valid for operator.

   6. Binding references valid package/service/subscription.

 10. Step 9 - RAT-01 Performs Lookup
 When RAT-01 receives a mediated CDR, it calls:
           POST /api/plm/voice-rating/lookup
           Content-Type: application/json

           {
               "operatorCode": "WIK",
               "subscriptionId": "SUB-700045",
               "packageRef": "pkg_INET_VOICE_STD",
               "serviceRef": "svc_VOIP_STD",
               "calledNumberNormalized": "+254711222333",
               "callDirection": "OUTBOUND",
               "callStartedAt": "2026-06-02T10:15:00+03:00"
           }

 Lookup logic:

   1. Resolve tariff plan by binding priority.

   2. Resolve destination zone by longest-prefix match.

   3. Resolve time band using operator timezone.

   4. Resolve active rate by plan, zone, time band, direction, and call start time.

   5. Return rate payload.

 Response:
           {
               "tariffPlanCode": "WIK_RES_VOICE_STD_2026",
               "zoneCode": "KE_MOBILE",
               "timeBandCode": "ANYTIME",
               "chargePolicy": "CHARGEABLE",
               "unitType": "MINUTE",
               "unitPrice": 3.0,
               "currency": "KES",
               "initialIncrementSeconds": 60,
               "subsequentIncrementSeconds": 60,
               "setupFeeAmount": 0.0,
               "minimumChargeAmount": 0.0,
               "taxableKind": "SERVICE",
               "taxableRef": "svc_VOIP_STD"
           }

 If no prefix or rate is found:
           {
               "errorCode": "VOICE_TARIFF_NOT_FOUND",
               "reason": "No active destination prefix for +998..."
           }

 RAT-01 must quarantine the CDR.

 11. Step 10 - Rating Calculation Example
 PLM-CFG-07 response:
           {
               "unitType": "MINUTE",
               "unitPrice": 3.0,
               "initialIncrementSeconds": 60,
               "subsequentIncrementSeconds": 60,
               "setupFeeAmount": 0.0,
               "minimumChargeAmount": 0.0
           }

 Mediated CDR:
           {
               "durationSeconds": 75
           }

 RAT-01 calculates:
           initial increment covers first 60 seconds
           remaining actual seconds = 15
           subsequent increment rounds remaining 15 to 60
           billable seconds = 120
           billable units = 120 / 60 = 2 minutes
           charge = 2 * 3.00 + 0 setup fee = 6.00 KES

 PLM-CFG-07 does not persist this calculation. RAT-01 persists rated usage.



 12. Step 11 - Bulk Import Prefixes Or Rates
 Backoffice uploads CSV to:
           POST /api/plm/voice-destination-prefixes/bulk-import

 Example CSV:
           prefix,zone_code,effective_from,notes
           +2547,KE_MOBILE,2026-06-01T00:00:00Z,Kenya mobile
           +25420,KE_FIXED,2026-06-01T00:00:00Z,Nairobi fixed
           999,EMERGENCY,2026-06-01T00:00:00Z,Emergency

 Import rules:

   1. Validate required columns.

   2. Validate zone exists.

   3. Validate no duplicate active prefix for same operator/effective date.

   4. Insert in one batch transaction if file is small.

   5. For large files, create import job and process asynchronously.

   6. Emit prefix change event after success.



 13. Error Codes
  Error code                                                        Meaning

  VOICE_TARIFF_PLAN_NOT_FOUND                                       No applicable tariff plan binding.

  VOICE_DESTINATION_ZONE_NOT_FOUND                                  Called number did not match a prefix.

  VOICE_RATE_NOT_FOUND                                              Zone resolved but no active rate exists.

  VOICE_RATE_OVERLAP                                                Rate effective periods overlap.

  VOICE_PREFIX_DUPLICATE                                            Duplicate active prefix.

  VOICE_BINDING_REF_INVALID                                         Package/service/subscription binding reference is invalid.

  VOICE_TARIFF_BACKDATE_NOT_ALLOWED                                 User attempted backdated tariff change without permission.

  VOICE_PREMIUM_RATE_REQUIRED                                       Premium zone exists without explicit active rate.

  VOICE_EMERGENCY_ZERO_RATE_REQUIRED                                Emergency zone is not zero-rated.

 15. Minimum Implementation Order
 Build in this order:

   1. Migrations for tariff plan, zone, prefix, time band, rate, allowance, binding.

   2. CRUD APIs for zones and time bands.

   3. CRUD APIs for tariff plans and rates.

   4. Prefix longest-match resolver.

   5. Binding resolver.

   6. Time band resolver.

   7. Rate overlap validation.

   8. Rating lookup API.

   9. Activation/retirement API.

   10. Events for cache invalidation.

   11. Bulk import for prefixes.

   12. Bulk import for rates.

   13. Backoffice screens.

 17. Developer Checklist
 Before marking this catalog complete:

   - Longest-prefix matching is deterministic.

   - Rate overlap validation runs before activation.

   - Lookup API does not return draft rates.

   - Emergency zone validation enforces zero-rated config.

   - Premium zones require explicit rates.

   - Effective-date logic uses call start time.

   - Time band logic uses operator timezone.

   - Binding priority is implemented.
