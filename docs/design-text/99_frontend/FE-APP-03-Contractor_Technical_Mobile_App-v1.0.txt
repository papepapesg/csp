 1. Purpose
 This DD defines the Contractor Technical Mobile App.

 The app is used by field technicians, contractor team leads, and internal technical teams to receive assigned work orders,
 claim/start jobs, view customer/site context, capture checklist evidence, scan equipment serials, upload photos/signatures,
 submit finalization, and handle support/escalation messages.

 The app is Kenya/WIK-first but must support other operators through configuration: language, brand, work order types,
 checklist rules, evidence requirements, technician roles, and offline policy.


 2. Design Position
 FE-APP-03 is the mobile execution surface for work orders. It is not the Work Order system of record.

 Rules:

   - Cache assigned WO details needed for the day's work.

   - Capture photos/signatures/checklist/serial scans locally with local draft ids.

   - Upload files before sending WO finalization payload if finalization references file ids.

   - Preserve operation ordering: file upload -> OSR serial validation -> WO attachment/equipment binding -> WO finalization.

   - If server says WO was cancelled/reassigned/changed, stop sync and show conflict resolution.

   - A locally completed job is shown as Pending Sync, not Completed.

 Allowed offline:

  Item                                           Offline allowed?                                    Notes

  Assigned WO cache                              Yes                                                 Cache only jobs assigned/team-visible to the user.

  Checklist answers                              Yes                                                 Pending until synced.

  Notes                                          Yes                                                 Queue with idempotency key.

  Photos/signatures                              Yes                                                 Store encrypted local file until upload succeeds.

  Serial scan                                    Yes, as draft                                       Must validate with OSR before final server
                                                                                                     submission.

  Item                                        Offline allowed?                                  Notes

  Equipment binding                           Limited                                           Can draft offline; server binding requires online
                                                                                                OSR/WO validation.

  Finalization                                Limited                                           Can queue as pending sync, but not show
                                                                                                completed until WO accepts it.

  Claim/start                                 No, unless online                                 Avoid two technicians claiming same WO offline.

  Cancellation/reassignment                   No                                                Must be online and role-authorized.


 Sync order:

   1. Refresh WO detail and verify assignment/status still allows updates.

   2. Upload files and get file refs.

   3. Validate serials/equipment with OSR.

   4. Submit WO notes/attachments/equipment bindings.

   5. Submit finalization if still valid.

   6. Mark local draft synced only after server confirms.

 12. Security And Privacy
 Rules:

   - Cache only jobs visible to the authenticated user/team.

   - Encrypt local job/evidence cache where supported.

   - Clear local cache on logout, user switch, or app wipe policy.

   - Do not store raw customer ID documents unless the WO explicitly requires it.

   - Do not expose customer phone/address to users outside assigned team/role.

   - Evidence downloads/uploads must use authorized file APIs.

   - A locally cached WO must be revalidated before mutation.

   - Do not allow one contractor/franchise to view another contractor's queue unless role/config explicitly allows it.

 15. Implementation Notes
 Recommended build order:

   1. Implement app shell, auth, runtime config, profile/team context.

   2. Implement job list and WO detail.

   3. Implement local job workspace and sync queue.

   4. Implement evidence capture/upload.

   5. Implement notes and checklist capture.

   6. Implement serial scan and OSR validation.

   7. Implement equipment binding/recovery.

   8. Implement finalization submit and correction handling.

   9. Implement messages/inbox.

   10. Add offline sync and E2E tests.

 Do not implement finalization before evidence and equipment sync ordering is stable. Otherwise the app can close WOs
 without the data the downstream modules need.


 16. Acceptance Checklist
   - [ ] Every screen/action names its module API owner.

   - [ ] WO-01 is the only owner of WO lifecycle state.

   - [ ] OSR validates equipment before server-side binding/recovery.
