 1. Purpose
 This rewritten DD is the developer-facing version of the module contract
 DD_FUL-07-HomePass_Lifecycle_Fulfillment-v1.0.md.

 Verdict: ■ New | Wave: 1 | Group III: Fulfillment | Version: v1.0 Owns the HomePass-side lifecycle of subscription bindings.
 When a subscription activates at a HomePass: increments the HomePass's activeTerminationPoints and captures the
 last-mile port binding if captureMode = AT_INSTALLATION. When a subscription terminates (or relocates away, migrates
 to another HomePass, etc.): decrements the counter and releases the port binding. Called synchronously by

 suspension), and FUL-05 (network plane termination). FUL-07 is the HomePass-plane counterpart — different concern, same
 architectural pattern.

 The goal of this rewrite is to make the DD easier for a mid-level developer to implement without losing the detailed source
 contract.


 2. Implementation Scope
 This DD should be implemented as part of the owning SOPHIX capability, not as an isolated service unless the deployment
 architecture explicitly separates that capability.

 Implement this DD with these rules:

   - Use the owning module APIs/repositories for authoritative writes.

   - Use approved internal APIs/client wrappers when reading another module's data.

   - Do not query another module's database tables directly from business flow code.

   - Treat worker names as logical Camunda external-task topics, not separate deployments.

   - One worker application may handle multiple topics, but metrics, retries, and logs must remain visible per topic.

   - Emit success events only after the authoritative state commit succeeds.

   - Use outbox publishing for Kafka events.

 A — Target
 1. What this process is about
 SUB-WF-ACTIVATE-01 reaches the callFulfillment step in its saga, after FUL-03 has provisioned the network. The
 saga's ful-call-claim-homepass worker calls FUL-07 with intent=CLAIM. FUL-07 then:

 For CLAIM (subscription activating at a HomePass):

   1. Reads the HomePass via RLM-CFG-01 (captureMode, networkPath).

   2. Inserts a homepass_subscription_binding row tying the subscription to the HomePass.

   3. If captureMode = AT_INSTALLATION AND caller supplied portBinding updates: calls PATCH
     /api/homepasses/{id}/network-path/append (per RLM-CFG-01) to fill in the last-mile node(s) + port(s).

   4. Recomputes activeTerminationPoints for the HomePass (count of OPEN bindings).

   5. Emits HomePassActiveTerminationPointsChanged event (RLM-CFG-01 consumes to update its denormalized
     counter column).

   6. Emits HomePassSubscriptionClaimed event.

   7. Returns homepassClaimId, incrementedActiveTerminationPoints, terminal state.

 For RELEASE (subscription terminating / relocating / migrating away):

   1. Reads the HomePass + the open homepass_subscription_binding row for this subscription.

   2. If no open binding exists for this subscription, returns NO_OPEN_BINDING (informational; non-failing — the subscription
     may never have claimed, e.g., terminated before activation).

   3. If captureMode = AT_INSTALLATION AND releasePortBinding = true: clears the port(s) on the network_path
     via PATCH /api/homepasses/{id}/network-path/ports setting port=null for the released subscription's last-mile
     node(s).

   4. Soft-closes the binding row (sets released_at, release_reason).

   5. Recomputes activeTerminationPoints.

   6. Emits HomePassActiveTerminationPointsChanged event.

   7. Emits HomePassSubscriptionEnded event.

   8. Returns homepassReleaseId, decrementedActiveTerminationPoints, terminal state.

 Audit: Every attempt produces a homepass_lifecycle_ledger row with start/end timestamps, terminal state, failure
 reason if any. Indefinite retention.

 Return to caller: The framework worker's external task complete fires, returning the outputs to the BPMN.

 Out of scope
   - Network provisioning / deprovisioning — owned by FUL-03 + FUL-05. FUL-07 operates on the HomePass side only.

   - HomePass status transitions (NPL → SUR → ROE → BLD → RFS → WAI → ACT) — owned by RLM-CFG-01
     maker-checker workflow. FUL-07 doesn't change HomePass status; it only updates activeTerminationPoints
     (derived) and (for AT_INSTALLATION) the per-port assignment within the network_path.

   - HomePass CRUD — owned by RLM-CFG-01.

   - HomePass-level address / franchise / techregion changes — owned by RLM-CFG-01.

   - Equipment lifecycle — owned by OSR-INSTANCE-01. The ONT serial that ends up in the network_path's termination
     node is an equipment-instance reference; FUL-07 receives it as input from the caller (the workflow knows the equipment
     binding via OSR-INSTANCE-01) and writes it into the network_path; it does not manage equipment lifecycle.

   - Counter materialization on RLM-CFG-01's homepass.active_termination_points column — RLM-CFG-01
     owns the column; updates from the HomePassActiveTerminationPointsChanged Kafka event handler within
     RLM-CFG-01.

 #### Rule group RL — Release

  Rule                                 Description

  R-FUL-07-RL-1                        Release looks up the OPEN binding row for (subscriptionId,
                                       homepassId). If none exists, terminal state is NO_OPEN_BINDING
                                       (informational; non-failing per §1; the subscription may have terminated before
                                       activation, or already been released). The ledger row records this; no
                                       decrement happens; no events emitted.

  R-FUL-07-RL-2                        If releasePortBinding = true AND HomePass's captureMode =
                                       AT_INSTALLATION: FUL-07 calls PATCH
                                       /api/homepasses/{id}/network-path/ports per RLM-CFG-01 to set
                                       the released subscription's bound port(s) to null (freeing them for re-use by
                                       another subscription). The specific nodes to clear are looked up from the
                                       binding row's captured_port_bindings JSONB. On RLM-CFG-01 PATCH
                                       failure → fulfillment fails with PORT_RELEASE_PATCH_FAILED; the binding row
                                       is NOT closed.

  R-FUL-07-RL-3                        If releasePortBinding = false OR HomePass's captureMode =
                                       PRE_INSTALLATION: no port mutation. The ports stay bound on the
                                       HomePass's network_path (typical for PRE_INSTALLATION HomePasses
                                       where the port is intrinsic to the HomePass).

  R-FUL-07-RL-4                        Binding row updated: binding_status = CLOSED, released_at =
                                       NOW(), release_reason = caller-supplied.

  R-FUL-07-RL-5                        decrementedActiveTerminationPoints in the response = COUNT(*)
                                       FROM homepass_subscription_binding WHERE homepass_id = ?
                                       AND binding_status = 'OPEN' after the update.


 #### Rule group LE — Ledger

  Rule                                 Description

  R-FUL-07-LE-1                        One ledger row per fulfillment attempt in homepass_lifecycle_ledger.

 #### Rule group CO — Compensation

  Rule                                                            Description

  R-FUL-07-CO-1                                                   Compensation pattern: a CLAIM that fails after partial commit (e.g., port PATCH
                                                                  succeeded but binding INSERT failed, or vice versa) reverts via the inverse —
                                                                  calls PATCH /api/homepasses/{id}/network-path/ports to null the
                                                                  ports OR DELETEs the binding row, depending on which step succeeded.

  R-FUL-07-CO-2                                                   A RELEASE failure post-binding-close: the binding row stays CLOSED but the
                                                                  port PATCH didn't fire. Recorded in the ledger as
                                                                  RELEASED_PORT_PATCH_FAILED; manual NOC recovery via the
                                                                  manual-recovery-decision user task.

  R-FUL-07-CO-3                                                   A failed CLAIM does NOT trigger compensation against the network plane
                                                                  (FUL-03 already succeeded by the time FUL-07 runs in the ACTIVATE BPMN;
                                                                  the BPMN's own compensation path handles network-plane rollback if needed).
                                                                  FUL-07 only reverts its own writes.
