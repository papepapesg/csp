 Termination
 1. Purpose
 This guide explains termination implementation as the flow executes at runtime.

 2. Runtime Actors
  Runtime component                                              What it does

  subscription-workflow-api pod                                  Receives preview/terminate request, validates, starts operation.

  SUB-LM module/API                                              Provides authoritative subscription status and mutation APIs.

  SUB-WF framework                                               Handles idempotency, in-flight operation interruption, and Camunda start.

  BIL-01                                                         Computes TERMINATION_INTENT settlement.

  BIL-04                                                         Calls DUNNING_TERMINATION at final dunning step.

  FUL-05                                                         Revokes network/service access.

  FUL-07/HomePass release                                        Frees HomePass slot, or approved stub until FUL-07 ships.

  Drools                                                         Validates trigger, role, cooling-off, disposition, and routing.

  Camunda                                                        Runs termination BPMN.

  Worker apps                                                    Execute BPMN service task topics.

  OSR-RMA-01 EQP                                                 Creates equipment pickup work order from termination event.

  NOT-01                                                         Sends customer/admin notification after success/failure.




 3. Before The Request Can Work
 Required:

   - subscription_termination_config seeded.

   - SUB-LM supports PENDING_TERMINATION and TERMINATED.

   - SUB-LM supports termination master fields.

   - subscription_operation_config has (operator_code=WIK, operation_kind=TERMINATE) ->
     sub-terminate-wik.

   - Drools package rules.subscription.terminate.wik.

   - BPMN process sub-terminate-wik.

   - Worker apps subscribe to required topics.

   - BIL-01 supports TERMINATION_INTENT.

   - FUL-05 can revoke service.

   - HomePass release worker is implemented or approved stub is in place.

 The preview API:

   1. Loads subscription summary from SUB-LM.

   2. Loads termination config.

   3. Loads equipment bindings from OSR/asset inventory approved API.

   4. Calls Drools to compute cooling-off and disposition.

   5. Calls BIL-01 in preview/read-only mode for TERMINATION_INTENT.

   6. Returns preview response.

 Do not create subscription_operation. Do not start Camunda. Do not change subscription state.

 6. Step 3 - API Validates Shape And Idempotency
 Validate request shape:

  Field                                                           Validation

  operatorCode                                                    Required.

  terminationTrigger                                              One of CUSTOMER_REQUESTED, ADMIN_DECISION, DUNNING_TERMINATION,
                                                                  CONTRACT_EXPIRED.

  terminationReasonCode                                           Required.

  equipmentDisposition                                            Optional; if supplied must be CUSTOMER_RETAINS, PENDING_COLLECTION, or
                                                                  WRITTEN_OFF.

  customerNotes                                                   Optional free text.


 Idempotency behavior:

   - Same key and same request hash returns existing operation response.

   - Same key and different request hash returns 409 IDEMPOTENCY_KEY_REUSED.

   - Check existing key and hash before inserting a new operation.

   - Use a DB unique constraint or transaction guard so concurrent duplicate calls cannot create two operations.

 9. Step 6 - API Handles In-Flight Operation Interruption
 If another state-changing operation is in-flight for the subscription:

   1. Framework sends message external-cancel-requested to the active BPMN.

   2. Framework waits up to 60 seconds for cancellation acknowledgement.

   3. Existing operation runs its compensation path and finalizes as CANCELLED or configured interrupted state.

   4. Termination proceeds.

 If the active operation does not acknowledge cancellation:
            409 Conflict

            {
                "errorCode": "OPERATION_INTERRUPTION_FAILED",
                "activeOperationId": "subop_01HZ_KAMAU_PAUSE_PRIOR"
            }

 11. Drools Rules To Configure
 11.1 Already Terminated
          rule "terminate rejects already terminated subscription"
          when
            $req: TerminateRequestFact()
            $sub: SubscriptionStateFact(subscriptionId == $req.subscriptionId, statusCode == "TERMINATED")
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("ALREADY_TERMINATED")
            }
          end


 11.2 Trigger Role Gating
          rule "customer requested termination allowed roles"
          when
            $req: TerminateRequestFact(
               terminationTrigger == "CUSTOMER_REQUESTED",
               eligible == null,
               initiatingActorRole not in ("CUSTOMER_SELF_SERVICE", "CALL_CENTER", "SUBSCRIPTION_OPERATOR")
            )
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("ROLE_NOT_AUTHORIZED_FOR_TRIGGER")
            }
          end

          rule "admin decision termination requires admin"
          when
            $req: TerminateRequestFact(
               terminationTrigger == "ADMIN_DECISION",
               eligible == null,
               initiatingActorRole != "SUBSCRIPTION_ADMIN"
            )
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("ROLE_NOT_AUTHORIZED_FOR_TRIGGER")
            }
          end

          rule "dunning termination requires billing internal"
          when
            $req: TerminateRequestFact(
               terminationTrigger == "DUNNING_TERMINATION",
               eligible == null,
               initiatingActorRole != "BILLING_INTERNAL"
            )
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("ROLE_NOT_AUTHORIZED_FOR_TRIGGER")
            }
          end


 11.3 Equipment Disposition Resolution
          rule "caller supplied equipment disposition"
          when
            $req: TerminateRequestFact(equipmentDisposition != null, resolvedEquipmentDisposition == null)
          then
            modify($req) {
               setResolvedEquipmentDisposition($req.getEquipmentDisposition())
            }
          end

          rule "default dunning equipment disposition"
          when
            $req: TerminateRequestFact(
               terminationTrigger == "DUNNING_TERMINATION",
               equipmentDisposition == null,
               resolvedEquipmentDisposition == null
            )
            $cfg: TerminationConfigFact()

          then
            modify($req) {
               setResolvedEquipmentDisposition($cfg.getDunningEquipmentDisposition())
            }
          end

          rule "default non dunning equipment disposition"
          when
            $req: TerminateRequestFact(
               terminationTrigger != "DUNNING_TERMINATION",
               equipmentDisposition == null,
               resolvedEquipmentDisposition == null
            )
            $cfg: TerminationConfigFact()
          then
            modify($req) {
               setResolvedEquipmentDisposition($cfg.getDefaultEquipmentDisposition())
            }
          end


 11.4 Cooling-Off
          rule "customer termination inside cooling off"
          when
            $req: TerminateRequestFact(terminationTrigger == "CUSTOMER_REQUESTED")
            $sub: SubscriptionStateFact(activatedAt != null)
            $cfg: TerminationConfigFact()
            eval(java.time.Instant.parse($sub.getActivatedAt())
                  .plusSeconds($cfg.getCoolingOffWindowDays() * 86400L)
                  .isAfter(java.time.Instant.parse($req.getRuntimeNow())))
          then
            modify($req) {
               setCoolingOffApplicable(true)
            }
          end

          rule "cooling off supervisor decision required"
          when
            $req: TerminateRequestFact(coolingOffApplicable == true)
            $cfg: TerminationConfigFact(coolingOffSupervisorOverride == true)
          then
            modify($req) {
               setRequiresCoolingOffSupervisorDecision(true)
            }
          end

 14. Step 10 - BPMN Executes Worker Topics
  Order                                       BPMN service task does this                   Worker topic/message

  1                                           Re-check policy.                              drools-decide

  2                                           Optional churn-save or supervisor decision.   User task, if configured

  3                                           Put subscription in pending termination.      sub-lm-put-pending-status

  4                                           Compute cycle window.                         sub-lm-compute-cycle-window

  5                                           Ask billing for settlement.                   bil01-emit-intent

  6                                           Revoke service.                               ful-call-terminate

  7                                           Wait for fulfillment result.                  fulfillment-completed or
                                                                                            fulfillment-failed

  8                                           Release HomePass.                             ful-call-release-homepass

  9                                           Write termination master fields.              sub-lm-put-master-fields

  10                                          Commit subscription terminated.               sub-lm-commit-state

  11                                          Emit termination event.                       kafka-emit

  12                                          Notify customer.                              notification-send

  13                                          Finalize operation.                           subscription-operation-finalize


 These names are worker topics or BPMN message names, not shell commands.

 20. Step 16 - Success Event Is Emitted
 Event:
             SubscriptionTerminated

 Topic:
             sophix.subscription.subscription.terminated

 Emitted only after SUB-LM commits TERMINATED.

 OSR-RMA-01 consumes this event and creates a pickup work order when:
             equipmentDisposition == PENDING_COLLECTION
             AND equipmentBindings is not empty



 21. Compensation Flows
  Failure                                                           BPMN compensation

  Validation reject before pending                                  kafka-emit SubscriptionTerminationRejected, finalize failed.

  Billing settlement failure                                        sub-lm-revert-to-prior, emit rejected, finalize failed.

  FUL-05 failed before network revoke                               sub-lm-revert-to-prior, emit rejected, finalize failed.

  FUL-05 partial revoke or unknown state                            Manual recovery.

  HomePass release failed                                           Manual recovery or configured retry; do not commit terminal state until resolved.

  Master fields/commit failed after network revoke                  Manual recovery.

  Kafka emit failed                                                 Outbox retry.

  Notification failed                                               Log and continue.

 23. Common Mistakes
   - Reading current subscription status from cache.

   - Treating termination as reversible.

   - Starting termination without handling in-flight operations.

   - Putting billing formulas in SUB-WF instead of using BIL-01.

   - Ignoring equipment disposition in event payload.

   - Committing TERMINATED before FUL-05 revokes service.

   - Emitting SubscriptionTerminated before sub-lm-commit-state.

   - Treating worker-topic names as shell commands.

   - Failing the whole operation because NOT-01 notification failed.
