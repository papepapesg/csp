 DD_SUB-WF-PAUSE-01 - Subscription Pause
 Developer implementation guide: DD_SUB-WF-PAUSE-01-DEV_IMPL_GUIDE-v1.0.md.


 1. Purpose
 SUB-WF-PAUSE-01 defines voluntary subscription pause.

 Pause moves a subscription from:
          ACTIVE -> SUSPENDED

 It is used when the customer or an admin wants to temporarily stop service without terminating the subscription.

 Examples:

   - Customer vacation.

   - Customer temporarily away.

   - Financial hardship pause handled by call center.

   - Admin maintenance pause.

   - Admin compliance hold.

 Pause is different from non-payment suspension:
          PAUSE = voluntary/admin business pause
          SUSPEND_NP = billing/dunning-driven non-payment suspension

 Both may end in SUSPENDED, but they write different origin_intent values in subscription_pause_history.

 4. Deployment Unit Clarification
 Pause is not a standalone service.

 It is deployed as part of the subscription workflow capability:

   - Pause route/controller in SUB-WF API.

   - Pause config/catalog/history migrations.

   - Pause BPMN, such as sub-pause-wik.

   - Pause Drools package, such as rules.subscription.pause.wik.

   - Shared workers from the worker catalog.


 5. Triggers
  Trigger                                       Meaning                                               Allowed roles

  CUSTOMER_REQUESTED_PAUSE                      Customer requested pause through self-service, call   CUSTOMER_SELF_SERVICE, CALL_CENTER,
                                                center, or operator.                                  SUBSCRIPTION_OPERATOR

  ADMIN_PAUSE                                   Operator/admin pauses for maintenance,                SUBSCRIPTION_ADMIN,
                                                compliance, or operational reason.                    SUBSCRIPTION_OPERATOR


 CUSTOMER_SELF_SERVICE also requires:

   - subscription_pause_config.customer_self_service_enabled = true

   - pause_reason.customer_self_service_eligible = true

   - pause_reason.admin_only = false


 6. Duration Model
 Pause request must resolve to exactly one duration mode.

  Mode                                          Request shape                                         Meaning

  OPEN_ENDED                                    openEnded=true                                        No scheduled resume. Human/customer/admin
                                                                                                      resumes later.

  FIXED_DAYS                                    durationDays=N                                        System computes resume_scheduled_at = now
                                                                                                      + N days.

  SCHEDULED_RESUME_TIME                         resumeScheduledAt=<timestamp>                         Resume should be triggered at the supplied time.


 Rules:

   - Multiple duration fields are invalid.

   - No duration defaults to open-ended only if the reason allows open-ended.

   - Scheduled resume values must respect operator and reason limits.

 7.2 subscription_pause_history
 What this table is for:

 subscription_pause_history records every suspension-like period that RESUME must understand. PAUSE writes
 voluntary/admin rows. SUSPEND-NP writes non-payment rows. RESUME closes rows.

 Use this table when:

   - Creating a pause record after pause succeeds.

   - Checking whether a subscription already has an open pause/suspension row.

   - Showing pause history to support.

   - Letting RESUME decide whether a resume trigger is allowed.

   - Letting scheduler find rows with resume_scheduled_at.

 Do not use this table to replace subscription.status_code. Current status remains in SUB-LM.

            pause_id                           TEXT PRIMARY KEY,

 8. Business Rules
  Rule                                                                      Description

  R-PAUSE-S-1                                                               Pause requires subscription status ACTIVE.

  R-PAUSE-S-2                                                               Transition is ACTIVE -> PENDING_PAUSE -> SUSPENDED.

  R-PAUSE-S-3                                                               At most one open pause/suspension history row per subscription.

  R-PAUSE-T-1                                                               Trigger must be CUSTOMER_REQUESTED_PAUSE or ADMIN_PAUSE.

  R-PAUSE-T-2                                                               Trigger role must match allowed role set.




SOPHIX BSS Design Documents                                                                                                                     Page 6
  Rule                                                              Description

  R-PAUSE-T-3                                                       Customer self-service requires operator config enabled.

  R-PAUSE-T-4                                                       Customer self-service requires reason eligibility.

  R-PAUSE-R-1                                                       Pause reason must be active.

  R-PAUSE-R-2                                                       Reason row must be snapshotted into history.

  R-PAUSE-D-1                                                       Exactly one duration mode must be resolved.

  R-PAUSE-D-2                                                       Open-ended requires reason support.

  R-PAUSE-D-3                                                       Duration must respect min/max bounds.

  R-PAUSE-D-4                                                       Fixed days computes resume_scheduled_at.

  R-PAUSE-D-5                                                       Scheduler/RESUME handles actual scheduled resume.

  R-PAUSE-B-1                                                       BPMN sends PAUSE_INTENT to billing.

  R-PAUSE-B-2                                                       If fee applies and pay-first is required, BPMN waits for payment.

  R-PAUSE-F-1                                                       FUL-04 is called with intent=SUSPEND_SERVICE when fulfillment suspension
                                                                    is required.

  R-PAUSE-H-1                                                       Successful pause inserts open subscription_pause_history row.

  R-PAUSE-H-2                                                       Active restrictions are cleared when subscription becomes SUSPENDED.

 10. Worker Usage In This Operation
 The worker list is a logical BPMN task list, not a deployment list.

  Worker topic                                                         Why pause uses it

  drools-decide                                                        Validate status, reason, trigger, role, duration, fee applicability.

  sub-lm-put-pending-status                                            Move to PENDING_PAUSE.

  sub-lm-compute-cycle-window                                          Build billing context.

  bil01-emit-intent                                                    Ask billing to decide pause fee/cycle impact.

  bil01-charge-pre-authorize                                           Pay-first pause fee if applicable.

  bil01-confirm-charge                                                 Confirm pause fee after payment.

  bil01-revert-pending-charge                                          Compensation for fee payment timeout/failure.

  ful-call-restrict                                                    Call FUL-04 with SUSPEND_SERVICE.

  sub-lm-put-active-restrictions                                       Clear active restrictions after suspension.

  sub-lm-put-master-fields                                             Insert pause history row and update status timestamp.

  sub-lm-commit-state                                                  Commit subscription to SUSPENDED.

  sub-lm-revert-to-prior                                               Revert to ACTIVE during compensation.

  kafka-emit                                                           Emit pause success/rejected event.

  notification-send                                                    Notify customer/admin, reliability-isolated.

  subscription-operation-finalize                                      Mark operation terminal.
