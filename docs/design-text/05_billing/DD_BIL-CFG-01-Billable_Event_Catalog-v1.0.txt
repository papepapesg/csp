 This DD should be implemented as part of the owning SOPHIX capability, not as an isolated service unless the deployment
 architecture explicitly separates that capability.

 Implement this DD with these rules:

   - Use the owning module APIs/repositories for authoritative writes.

   - Use approved internal APIs/client wrappers when reading another module's data.

   - Do not query another module's database tables directly from business flow code.

   - Treat worker names as logical Camunda external-task topics, not separate deployments.

   - One worker application may handle multiple topics, but metrics, retries, and logs must remain visible per topic.

   - Emit success events only after the authoritative state commit succeeds.

   - Use outbox publishing for Kafka events.

 1. What this DD owns
   1. The billable_event_category table.

   2. The billable_event table.

   3. Rules governing trigger types, applicability, signed-amount semantics, state callbacks, eligibility filters, and operator
     scoping.

   4. The CRUD API for catalog management (admin-only).

   5. Kafka catalog-administration events (created/updated/activated/retired).

 What this DD does NOT own
   - Charging logic — BIL-01 (the engine that reads this catalog at runtime).

   - Service catalog — PLM-CFG-01 (service_refs[] entries on BillableEvents resolve to ONE_SHOT Services there).

   - Currency derivation — Services carry currency; BillableEvents inherit from referenced Services (R-B-4).

   - Tax computation — Services carry default tax-group refs; BIL-01 applies them per PLM-CFG-02.

   - Customer wallet / payment — handled downstream by BIL-01 + BIL-01-PAY-01.

   - State transitions — SUB-LM-01 owns the actual transition mechanism; this DD only declares transition codes
     BillableEvents may invoke via callback.

 Operator scoping
 Every BillableEvent and Category is scoped to one operator. KE WIK seeds one catalog; WUG/WTZ/YASSN seed their own.
 Each operator's deployment adds, retires, or modifies its own catalog entries without affecting other operators.
 Cross-operator references are rejected at create/update time.

 3. Rules
 3.1 BillableEvent integrity
  Rule                                                                  Description

  R-BIL-CFG-01-B-1                                                      BillableEvent code is unique per (operator_code, code) excluding retired.
                                                                        Convention: uppercase snake-case, max 64 chars.

  R-BIL-CFG-01-B-2                                                      code is immutable once any charge has been booked under the event. The
                                                                        code is the audit-trail key; renaming would break historical ledger entries.

  R-BIL-CFG-01-B-3                                                      A BillableEvent MUST reference at least one Service in service_refs[].
                                                                        Each Service ref MUST resolve to an ACTIVE Service in PLM-CFG-01 within
                                                                        the same operator, with consumption_model = ONE_SHOT. Continuous
                                                                        Services cannot be referenced — they belong to Packages, not BillableEvents.

  R-BIL-CFG-01-B-4                                                      currency is derived from Service refs at create/update time: all referenced
                                                                        Services share one currency, which becomes the BillableEvent's currency.
                                                                        Mixed-currency Service refs are rejected with 400 MIXED_CURRENCY_REFS.
                                                                        Currency is immutable thereafter.

  R-BIL-CFG-01-B-5                                                      applicability declares which subscription billing modes apply. Same shape
                                                                        as PLM-CFG-03's wallet applicability. BIL-01 filters at charge time: a
                                                                        PREPAID_ONLY event triggered against a postpaid subscription is skipped.

  Rule                        Description

  R-BIL-CFG-01-B-6            pay_first_required MUST be true for any BillableEvent with a
                              state_callback. The callback fires ONLY after successful charge
                              confirmation. Setting pay_first_required = false on an event with a
                              state_callback returns 400 PAY_FIRST_REQUIRED_FOR_STATE_CALLBACK.

  R-BIL-CFG-01-B-7            category_code MUST reference an ACTIVE row in
                              billable_event_category of the same operator. Cross-operator category
                              reference returns 400 CATEGORY_OPERATOR_MISMATCH.

  R-BIL-CFG-01-B-8            An ACTIVE BillableEvent cannot retire while any subscription has an in-flight
                              workflow that has resolved this event as a match. Admin must let the workflow
                              complete (or revert) before retirement.



 3.2 Amount sign policy
  Rule                        Description

  R-BIL-CFG-01-AS-1           amount_sign_policy ∈ {POSITIVE_ONLY, NEGATIVE_ONLY, SIGNED}.

  R-BIL-CFG-01-AS-2           POSITIVE_ONLY — BIL-01 emits a charge with positive amount. Used for fees:
                              RELOCATION_FEE, MIGRATION_FEE, INSTALLATION_FEE,
                              EQUIPMENT_REPLACEMENT_FEE, etc. The category's is_credit is typically
                              false.

  R-BIL-CFG-01-AS-3           NEGATIVE_ONLY — BIL-01 emits a credit with negative amount. Used for
                              refunds and committed credits: DOWNGRADE_PRORATE_CREDIT,
                              OLD_CYCLE_CREDIT, PREPAID_REFUND, SLA_COMPENSATION_DOWNTIME,
                              EQUIPMENT_BUYBACK_ONT. Category's is_credit is typically true.

  R-BIL-CFG-01-AS-4           SIGNED — BIL-01's pricing rule (in billing-rules KJAR) computes the sign
                              at runtime. Used for events where the direction depends on context, primarily
                              MIGRATION_PRORATE_DELTA: target Package may be priced higher than
                              source (charge) or lower (credit). The category.is_credit should be
                              false; signing is per-call. The runtime rule MUST produce a signed amount;
                              ambiguous outcomes return error.

  R-BIL-CFG-01-AS-5           The sign policy is immutable once ACTIVE. Changing requires retire +
                              re-create.



 3.3 Trigger taxonomy
  Rule                        Description

  R-BIL-CFG-01-T-1            trigger_type ∈ {SAGA_INTENT, LIFECYCLE_EVENT, ADMIN_ACTION,
                              CUSTOMER_PURCHASE, EXTERNAL_PAYMENT, SCHEDULED}.

  R-BIL-CFG-01-T-2            SAGA_INTENT — fires synchronously during a workflow's
                              bil01-emit-intent call. Requires trigger_intent_code matching one
                              of the canonical intents (§3.1 glossary). BIL-01 resolves matching
                              BillableEvents by (operatorCode, trigger_type=SAGA_INTENT,
                              trigger_intent_code) + filter rule, charges them in display_order then
                              code, returns the aggregated line items to the workflow.

  R-BIL-CFG-01-T-3            LIFECYCLE_EVENT — fires asynchronously on a Kafka event from SUB-LM-01
                              or other publishers (e.g., SubscriptionPaused,
                              SubscriptionTerminated). Requires trigger_event_type. Used for
                              post-commit reactive billing: notifications-with-billing, deferred ancillary fees.
                              MUST NOT carry state_callback (the lifecycle has already committed).

  R-BIL-CFG-01-T-4            trigger_filter_drl — optional Drools rule name for additional matching.
                              Rule receives the workflow's intentContext (or event payload for
                              LIFECYCLE_EVENT) and votes accept/reject. Storing logic as a rule rather
                              than inline JSONB keeps the rule engine consistent across decision points.

  R-BIL-CFG-01-T-5            ADMIN_ACTION / CUSTOMER_PURCHASE / EXTERNAL_PAYMENT — no intent
                              code or event type required. Invoked by direct call to BIL-01's charging endpoint
                              with the BillableEvent's code as the parameter.

  R-BIL-CFG-01-T-6            SCHEDULED — requires trigger_schedule as a cron expression. A BIL-01
                              background job evaluates the schedule per operator and fires the event against
                              each eligible customer.

  R-BIL-CFG-01-T-7            Multiple BillableEvents may share the same trigger_intent_code (different
                              filter rules). BIL-01 charges them in display_order then code order. Same
                              for shared trigger_event_type on LIFECYCLE_EVENT triggers.

  R-BIL-CFG-01-T-8            trigger_type is immutable once ACTIVE. Switching trigger model requires
                              retire + re-create.



 3.4 State callbacks

SOPHIX BSS Design Documents                                                                             Page 9
  Rule                                                         Description

  R-BIL-CFG-01-SC-1                                            state_callback is OPTIONAL JSONB {transitionCode,
                                                               targetStatus, callbackMetadata?}. The callback invokes SUB-LM-01's
                                                               transition mechanism after successful charge. The callback is named by
                                                               transition code, NOT by URL — SUB-LM-01 owns the mapping.

  R-BIL-CFG-01-SC-2                                            transitionCode MUST be one of the registered transition codes published
                                                               by SUB-LM-01. Validated against a known list. New codes require a
                                                               coordinated update with SUB-LM-01.

  R-BIL-CFG-01-SC-3                                            When a state callback is declared, pay_first_required MUST be true.
                                                               The callback fires only on successful charge. On charge failure, the callback is
                                                               NOT fired and the BillableEvent outcome event carries
                                                               stateCallbackInvoked = false.

  R-BIL-CFG-01-SC-4                                            callbackMetadata (optional) is carried verbatim to SUB-LM-01. Used for
                                                               custom transition reasons, actor identity, channel hints.

  R-BIL-CFG-01-SC-5                                            If the callback invocation fails (SUB-LM-01 unreachable, transition rejected), the
                                                               charge is NOT rolled back. The BillableEvent emits
                                                               BillableEventStateCallbackFailed for alerting; admin intervention
                                                               reconciles. Money in the till is prioritized over state consistency; the rollback
                                                               alternative is more complex than the recovery scenario warrants.



 3.5 Eligibility filters
  Rule                                                         Description

  R-BIL-CFG-01-EL-1                                            eligibility_franchise_refs[] (optional) restricts the BillableEvent to
                                                               subscriptions whose HomePass is in one of the listed Franchises. Empty /
                                                               NULL = all. Allows regional pricing variations within an operator.

  R-BIL-CFG-01-EL-2                                            eligibility_package_refs[] (optional) restricts to specific Packages.
                                                               Allows tier-specific fees.

  R-BIL-CFG-01-EL-3                                            eligibility_segment_refs[] reserved for CVM customer segments
                                                               (future). Not enforced in v1.0.
