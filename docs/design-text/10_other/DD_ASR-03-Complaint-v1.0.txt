 escalation rules, and optional approval/credit hooks. It is not a separate complaint service, database, or deployment in the
 first release.



 1. Purpose
 ASR-03 defines how SOPHIX handles customer complaints.

 A complaint is a customer expression of dissatisfaction that needs investigation, accountability, response, and sometimes
 corrective action. It is more than an information request because the customer says something is wrong, unfair, delayed,
 repeated, badly handled, or unacceptable.

 Examples:

   - customer says an invoice charge is wrong;

   - customer says the same technical fault keeps returning;

   - customer says installation was delayed without explanation;

   - customer complains about technician or franchise behavior;

   - customer disputes a rejected KYC or order decision;

   - customer says the service quality is consistently poor;

   - customer asks for compensation or escalation;

   - customer reports that support promised an action but it was not done.

 This DD does not create a new ticketing engine. Complaints are implemented as configured TCK-01 ticket types/categories
 with ASR-specific investigation, escalation, resolution-action, and compensation recommendation tables.

 3. When To Use This Flow
 Use ASR-03 when the expected outcome is investigation plus formal response, not only an answer or operational task.

  Scenario                                                                              Use

  Customer asks a neutral question                                                      ASR-02 Information Request

  Customer reports service down or degraded now                                         ASR-01 Technical Trouble

  Customer requests an operational action without dissatisfaction                       ASR-04 Service Request

  Customer says a bill, support action, field visit, staff action, delay, or repeated   ASR-03 Complaint
  issue is unacceptable

  Customer requests money correction or compensation                                    ASR-03 plus BIL-02-ADJ-01 request if justified

 13. Testing Requirements
 13.1 Unit Tests
   - Complaint guidance resolves category config.

   - Investigation required blocks closure.

   - Customer response required blocks closure.

   - Supervisor review rule triggers correctly.

   - Compensation recommendation maps to BIL adjustment request payload.

   - Customer-visible response redaction blocks internal-only terms.

   - Duplicate complaint detection links related cases.

 13.2 Integration Tests
   - Create complaint through TCK and load ASR guidance.

   - Start/complete investigation using BIL invoice source refs.

   - Create compensation recommendation and BIL adjustment request.

   - Escalate to supervisor and approve/reject escalation.

   - Send customer response through TCK comment and NOT event.

   - Resolve ticket only after closure conditions pass.

 13.3 End To End Tests
   - Billing dispute validated, credit request created, customer response sent, complaint resolved.

 14. Definition Of Done
   - Complaint categories are seeded in TCK.

   - ASR complaint config exists per operator/category.

   - Complaint APIs support guidance, investigation, resolution action, escalation, compensation recommendation, customer
     response, and closure validation.

   - Closure rules block premature resolution.

   - BIL adjustment integration is request-only from ASR and approval/application remains in BIL.

   - Backoffice can process the complaint lifecycle end to end.

   - Self-care can show customer-safe complaint status and response if enabled.

   - Events are emitted for reporting and customer timeline.

   - Tests cover billing, technical, staff conduct, and invalid complaint paths.
