 DEV_IMPL_GUIDE - SUB-WF-TERMINATE-01-FLOW-WIK
 1. Purpose
 This guide explains how to implement and test the WIK termination BPMN as the flow executes at runtime.

            sub-terminate-wik.bpmn



 2. Runtime Actors
  Runtime component                                              Role in this flow

  subscription-workflow-api pod                                  Receives WIK termination request and calls the shared operation framework.

  SUB-LM service/module                                          Provides authoritative subscription summary and status mutation APIs.

  Drools                                                         Evaluates rules.subscription.terminate.wik.

  Camunda                                                        Runs process sub-terminate-wik.

  Worker apps                                                    Execute external task topics from the BPMN. One app can handle many topics.

  BIL-01                                                         Computes TERMINATION_INTENT settlement.

  FUL-05                                                         Revokes service.

  FUL-07/HomePass release                                        Releases HomePass slot or records durable stub request.

  Message correlators                                            Correlate fulfillment messages back to Camunda.

  OSR-RMA-01 EQP                                                 Creates pickup work order from SubscriptionTerminated.

  NOT-01                                                         Sends customer notification after success.

 5. Step 2 - API Pod Validates Shape And Idempotency
 The subscription-workflow-api pod validates:

  Field                                                          Validation

  operatorCode                                                   Required and must be WIK for this BPMN.

  terminationTrigger                                             One of the four parent DD trigger values.

  terminationReasonCode                                          Required.

  equipmentDisposition                                           Optional; if supplied must be CUSTOMER_RETAINS, PENDING_COLLECTION, or
                                                                 WRITTEN_OFF.


 Idempotency behavior:

   - First request inserts the operation and starts BPMN.

   - Same Idempotency-Key with same request hash returns the existing operation response.

   - Same Idempotency-Key with a different request hash must return 409 IDEMPOTENCY_KEY_REUSED.

 Implementation note:

 Do not insert a new operation before checking existing key and request hash. Use a transaction or unique constraint on the
 idempotency key plus operator/operation scope so concurrent duplicate requests cannot create two operations.

 9. Drools Rules To Configure
 9.1 Eligibility
          rule "WIK termination rejects already terminated"
          when
            $req: TerminateRequestFact()
            $sub: SubscriptionStateFact(subscriptionId == $req.subscriptionId, statusCode == "TERMINATED")
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("ALREADY_TERMINATED")
            }
          end

          rule "WIK customer requested termination allowed roles"
          when
            $req: TerminateRequestFact(
               terminationTrigger == "CUSTOMER_REQUESTED",
               eligible == null,
               initiatingActorRole not in ("CALL_CENTER", "CUSTOMER_SELF_SERVICE", "SUBSCRIPTION_OPERATOR")
            )
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("ROLE_NOT_AUTHORIZED_FOR_TRIGGER")
            }
          end

          rule "WIK customer self service termination requires config"
          when
            $req: TerminateRequestFact(initiatingActorRole == "CUSTOMER_SELF_SERVICE", eligible == null)
            $cfg: OperatorConfigFact(customerSelfServiceEnabled == false)
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("CUSTOMER_SELF_SERVICE_NOT_ENABLED")
            }
          end


 9.2 Cooling-Off
          rule "WIK cooling off applies only inside configured window"
          when
            $req: TerminateRequestFact(terminationTrigger == "CUSTOMER_REQUESTED")
            $sub: SubscriptionStateFact(activatedAt != null)
            $cfg: OperatorConfigFact()
            eval(java.time.Instant.parse($sub.getActivatedAt())
                  .plusSeconds($cfg.getCoolingOffWindowDays() * 86400L)
                  .isAfter(java.time.Instant.parse($req.getRuntimeNow())))
          then
            modify($req) {
               setCoolingOffApplicable(true)
            }
          end




SOPHIX BSS Design Documents                                                                                   Page 4
 9.3 Equipment Disposition
          rule "WIK caller supplied equipment disposition wins"
          when
            $req: TerminateRequestFact(equipmentDispositionRequested != null)
          then
            modify($req) {
               setEquipmentDisposition($req.getEquipmentDispositionRequested())
            }
          end

          rule "WIK dunning write-off disposition"
          salience 10
          when
            $req: TerminateRequestFact(terminationTrigger == "DUNNING_TERMINATION", equipmentDispositionRequested == null)
            $intent: BillingIntentDecisionFact(writeOffMarker == true)
          then
            modify($req) {
               setEquipmentDisposition("WRITTEN_OFF")
            }
          end

          rule "WIK default equipment disposition"
          salience -100
          when
            $req: TerminateRequestFact(equipmentDisposition == null)
            $cfg: OperatorConfigFact()
          then
            modify($req) {
               setEquipmentDisposition($cfg.getDefaultEquipmentDisposition())
            }
          end

 24. Compensation Flow Details
  Failure                                                            BPMN compensation

  Drools rejection                                                   kafka-emit SubscriptionTerminationRejected, finalize failed.

  Billing settlement failure                                         sub-lm-revert-to-prior, emit rejected, finalize failed.

  FUL-05 failed before network change                                sub-lm-revert-to-prior, emit rejected, finalize failed.

  FUL-05 partial/unknown revoke                                      Manual recovery.

  HomePass release failed                                            Retry or manual recovery unless durable stub accepted the request.

  Master-field write or commit failed after network revoke           Manual recovery.

  Notification failed                                                Log and continue.

   16. Confirm operation final state is COMPLETED.


 26. Common Mistakes
   - Treating worker-topic names as shell commands.

   - Reading current subscription status from cache.

   - Forgetting to interrupt in-flight operations.

   - Computing settlement inside SUB-WF instead of BIL-01.

   - Removing the cooling-off supervisor user task from WIK.

   - Committing TERMINATED before FUL-05 revokes service.

   - Emitting SubscriptionTerminated before sub-lm-commit-state.

   - Dropping HomePass release failures without a durable retry/stub.

   - Failing the whole operation because NOT-01 notification failed.
