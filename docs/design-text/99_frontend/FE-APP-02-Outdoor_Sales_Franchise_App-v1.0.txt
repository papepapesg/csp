 1. Purpose
 This DD defines the Outdoor Sales / Franchise App.

 The app is used by door-to-door sales agents, franchise sales teams, and sales supervisors to capture prospects, check
 serviceability, select packages, upload KYC/consent evidence, convert qualified leads into FUL-02 orders, and track the order
 until handoff to fulfillment.

 The app is Kenya/WIK-first but must remain deployable for other operators through configuration: language, currency, brand,
 feature flags, sales territories, KYC requirements, package availability, and payment instructions.


 2. Design Position
 FE-APP-02 is a mobile-first operational sales app. It is not a generic CRM and it is not the order orchestration engine.

 Rules:

   - Store drafts in encrypted local storage where platform supports it.

   - Generate stable local draft ids and idempotency keys.

  New lead draft                                   Yes                                                 Stored locally until synced to SALES-01.

  Lead activity                                    Yes                                                 Queue with idempotency key.

  KYC/consent file capture                         Yes                                                 Store encrypted local file until upload succeeds.

  Item                                           Offline allowed?                                  Notes

  HomePass/package cached lookup                 Limited                                           Cache recent lookups with freshness marker.

  Lead qualification                             No                                                Must call SALES-01 because duplicate and eligibility
                                                                                                   require server state.

  Convert to order                               No                                                Must be online.

  Payment confirmation                           No                                                Must come from BIL/FUL status, not local claim.


 Conflict handling:

  Conflict                                                             App behavior

  Duplicate lead                                                       Show existing lead if user is authorized; offer follow-up or supervisor escalation.

  Existing customer                                                    Show warning and route to allowed customer/order path.

  HomePass no longer sellable                                          Block conversion and keep lead as follow-up/lost.

  Package no longer active                                             Ask agent to select another package.

  File upload failed                                                   Keep draft pending; do not convert until required files are uploaded.

 12. Security And Privacy
 Rules:

   - Store only necessary draft data locally.

   - Encrypt local drafts/files where supported.

   - Clear local data on logout, account switch, or app wipe policy.

   - Do not expose customer ID documents in logs.

   - Do not use public object URLs for KYC/consent files.

   - Do not allow one franchise to see another franchise's leads unless role/config allows it.

   - Show customer phone/ID details only according to role and masking rules.

   - Never treat offline state as final server state.

 14. E2E Scenarios
 Required from DD_QA-01:

  Scenario                                                              Expected result

  New WIK customer activation                                           Lead converted, order created, payment/KYC/install/activation complete.

  Offline lead draft sync                                               Draft survives offline capture, syncs once, idempotent retry safe.

  Duplicate lead conflict                                               Duplicate warning shown, no duplicate server lead created.

  Package/HomePass not eligible                                         Conversion blocked with module error mapped to user message.

  Supervisor reassignment                                               Lead owner changes, old owner cannot mutate lead, new owner can continue.




 15. Implementation Notes
 Recommended build order:

   1. Implement app shell, auth, runtime config, operator branding.

   2. Implement local draft and sync queue foundation.

   3. Implement Today list from SALES daily work API.

   4. Implement create lead online and offline.

   5. Implement HomePass/package lookup screens.

   6. Implement KYC/consent file capture and upload.

   7. Implement qualify and convert-to-order flow.

   8. Implement order tracking.

   9. Implement supervisor board and reassignment.

   10. Add E2E tests and offline sync tests.

 Do not start with order submission before lead ownership and offline draft behavior are implemented. Otherwise the app will
 push incomplete prospects into FUL-02.
