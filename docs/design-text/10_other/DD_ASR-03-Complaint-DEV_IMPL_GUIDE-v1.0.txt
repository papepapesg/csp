 1. How To Read This Guide
 Complaint is a TCK ticket flow. It is not a separate complaint engine.

 The flow creates a TCK complaint ticket, loads ASR complaint rules, records an investigation, records resolution actions,
 optionally requests BIL adjustment, sends a customer-visible response, then resolves the TCK ticket.

 ASR-03 can request actions in other modules. It does not directly change invoices, wallets, subscriptions, work orders, or
 customer master data.

 15. Alternative Flow - Complaint Not Valid
 If investigation shows the invoice is correct:

   1. Complete investigation with validityCode = NOT_VALID.

   2. Create EXPLANATION resolution action.

   3. Do not create compensation recommendation.

   4. Send customer response explaining the finding.

   5. Resolve with NOT_VALID_EXPLAINED.

 Example final response:
          {
              "resolutionCode": "NOT_VALID_EXPLAINED",
              "responseBody": "We reviewed the invoice and confirmed that the package charge and taxes match your active subscription
          }




 16. Alternative Flow - Technical Complaint
 If the complaint is repeated technical fault:

   1. Create TCK complaint with category REPEATED_TECHNICAL_FAULT.

   2. Load ASR guidance.

   3. Start complaint investigation.

   4. Pull previous ASR-01 diagnostics and WO support history.

   5. If repair is needed, create/link ASR-01 or support WO using TCK/WO APIs.

   6. Keep complaint ticket WAITING_WORK_ORDER if TCK policy says closure depends on WO result.

   7. After WO result, complete investigation with root cause.

   8. Recommend compensation only if policy and outage evidence support it.

   9. Send formal customer response.

   10. Resolve complaint.

 The complaint ticket tracks dissatisfaction and formal response. ASR-01/WO track technical restoration.

 18. Error Codes
  Code                                                            Meaning

  ASR_COMP_CATEGORY_NOT_CONFIGURED                                TCK category has no ASR complaint config.

  ASR_COMP_INVESTIGATION_ALREADY_EXISTS                           Ticket already has an investigation.

  ASR_COMP_INVESTIGATION_REQUIRED                                 Cannot resolve because investigation is required and missing.

  ASR_COMP_INVESTIGATION_NOT_COMPLETE                             Cannot resolve because investigation is still open.

  ASR_COMP_CUSTOMER_RESPONSE_REQUIRED                             Cannot resolve without customer-visible response.

  ASR_COMP_SUPERVISOR_REVIEW_REQUIRED                             Cannot proceed until supervisor review is approved.

  ASR_COMP_COMPENSATION_NOT_ALLOWED                               Category does not allow compensation recommendation.

  ASR_COMP_BIL_ADJUSTMENT_FAILED                                  BIL adjustment request failed.

  ASR_COMP_INVALID_RESOLUTION_CODE                                Resolution code is not allowed for category.

  ASR_COMP_INTERNAL_TEXT_IN_CUSTOMER_RESPONSE                     Response contains blocked internal-only wording.

   - TCK status remains open.

 21. Developer Checklist
   - Complaint flow uses TCK ticket lifecycle.

   - ASR complaint tables do not duplicate TCK status, assignment, or comments.

   - Source data is pulled through owning module APIs only.

   - Investigation records root cause and validity.

   - Customer response is stored and also added as TCK customer-visible comment.

   - Financial correction is requested through BIL-02-ADJ-01 only.

   - Closure validation blocks incomplete complaints.
