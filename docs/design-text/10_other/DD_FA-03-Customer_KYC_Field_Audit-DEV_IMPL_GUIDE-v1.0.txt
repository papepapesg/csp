 1. Goal
 Implement field verification for customer KYC, address, contact, consent, and duplicate-risk cases.

 FA-03 records audit evidence and discrepancy routing. ILM-CFG-01 remains the customer/KYC source of truth.

 3. Step 1 - Migrations
 Create:

   - kyc_field_audit_campaign

   - kyc_field_audit_task

   - kyc_field_audit_expected_snapshot

   - kyc_field_audit_observation

   - kyc_field_audit_discrepancy

 Security requirements:

   - Do not store raw ID numbers.

   - Store only masked KYC values in snapshots.

   - Store file ids, not binary files.

 7. Step 5 - Submit And Compare
 On submit:

   1. Load masked ILM snapshot.

   2. Load observations.

   3. Create discrepancies for IDENTITY_MISMATCH, ADDRESS_MISMATCH, CONTACT_MISMATCH, MISSING_CONSENT,
     DUPLICATE_SUSPECTED, or CUSTOMER_REFUSED.

   4. Run Drools for severity/routing.

   5. Close if clean.



 8. Step 6 - Drools
           public record KycFieldAuditFact(
                String operatorCode,
                String discrepancyType,
                boolean evidenceComplete,
                boolean customerConfirmed,
                boolean fraudSuspected,
                boolean orderBlocked
           ) {}

           package rules.field_audit.kyc.severity

           rule "Identity mismatch critical"
           when
             $f : KycFieldAuditFact(discrepancyType == "IDENTITY_MISMATCH")
             $d : KycFieldAuditDecision()
           then
             $d.setSeverity("CRITICAL");
             $d.route("REQUEST_KYC_REVIEW");
           end

           package rules.field_audit.kyc.routing

           rule "Address correction needs approval"
           when
             $f : KycFieldAuditFact(discrepancyType == "ADDRESS_MISMATCH",
                                    evidenceComplete == true)
             $d : KycFieldAuditDecision()
           then
             $d.route("REQUEST_ILM_CORRECTION");
             $d.requireApproval("KYC_FIELD_AUDIT_ADDRESS_CORRECTION");
           end

 10. Tests
   1. Snapshot masks sensitive fields.

   2. Raw ID values are rejected.

   3. Duplicate mobile submit is idempotent.

   4. Address mismatch creates discrepancy.

   5. Identity mismatch is critical.

   6. ILM correction is called only after required approval.

   7. Ticket creation uses TCK API.

   8. Interaction is written to CUST-INT.
