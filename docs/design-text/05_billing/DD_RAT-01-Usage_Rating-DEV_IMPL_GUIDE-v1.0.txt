 1. How To Read This Guide
 This guide follows the runtime flow.

 MED-01 sends a clean mediated usage record. RAT-01 rates it, stores the result, and settles it depending on billing mode.

 Do not read raw CDR files in RAT-01. Do not hardcode rates. Do not directly update wallet balances or invoice tables.



 2. Step 1 - Receive Mediated Usage
 RAT-01 receives UsageMediated:
          {
              "eventType": "UsageMediated",
              "operatorCode": "WIK",
              "mediatedUsageId": "med-20260602-000001",
              "usageType": "VOICE_CALL",
              "subscriptionId": "SUB-700045",
              "customerId": "CUS-100045",
              "accountId": "ACC-900045",
              "serviceRef": "svc_VOIP_STD",
              "packageRef": "pkg_INET_VOICE_STD",
              "calledNumberNormalized": "+254711222333",
              "callDirection": "OUTBOUND",
              "callStartedAt": "2026-06-02T10:15:00+03:00",
              "durationSeconds": 75
          }

 First check idempotency:
          select *
          from rated_usage_record
          where mediated_usage_id = 'med-20260602-000001';

 If a row exists, return or ack without rating again.



 3. Step 2 - Resolve Billing Mode
 RAT-01 needs to know whether the subscription is PREPAID or POSTPAID at usage time.

 Resolution can come from subscription read API or a cached subscription snapshot:
          {
              "subscriptionId": "SUB-700045",
              "billingMode": "PREPAID",
              "walletId": "WAL-200045",
              "cycleRef": "2026-06"
          }

 If billing mode cannot be resolved:
          reason_code = BILLING_MODE_NOT_FOUND

 Create rating quarantine.

 6. Step 5 - Apply Allowance
 Load eligible allowances from PLM-CFG-07 response or allowance config cache.

 If an allowance applies, lock bucket:
          select *
          from usage_allowance_bucket
          where operator_code = 'WIK'
            and subscription_id = 'SUB-700045'
            and allowance_code = 'ONNET_100_MIN'
            and cycle_ref = '2026-06'
          for update;

 If bucket does not exist, create it from PLM-CFG-07 allowance definition.

 Example:
          insert into usage_allowance_bucket (
             bucket_id,
             operator_code,
             subscription_id,
             tariff_plan_code,
             allowance_code,
             cycle_ref,
             included_seconds,
             consumed_seconds,
             remaining_seconds,
             status,
             created_at,
             updated_at
          ) values (
             'uab-202606-sub700045-onnet',
             'WIK',
             'SUB-700045',
             'WIK_RES_VOICE_STD_2026',
             'ONNET_100_MIN',
             '2026-06',
             6000,
             0,
             6000,
             'ACTIVE',
             now(),
             now()
          );

 Consumption example:
          actual duration = 75 seconds
          allowance remaining = 60 seconds
          allowance applied = 60 seconds
          paid seconds before rounding = 15 seconds

 Update bucket:
          update usage_allowance_bucket
          set consumed_seconds = consumed_seconds + 60,
              remaining_seconds = remaining_seconds - 60,
              status = case when remaining_seconds - 60 <= 0 then 'EXHAUSTED' else status end,
              updated_at = now()
          where bucket_id = 'uab-202606-sub700045-onnet';

 Allowance consumption must happen in the same transaction as rated usage creation or with a compensating rollback if
 settlement fails before final commit.

 7. Step 6 - Round Billable Duration
 Use tariff increment fields.

 For 75 seconds with 60/60 increment and no allowance:
          first 60 seconds -> 60 billed
          remaining 15 seconds -> round to next 60
          billable duration = 120 seconds

 Pseudo-code:
          function billableSeconds(int $paidActualSeconds, int $initialIncrement, int $subsequentIncrement): int
          {
              if ($paidActualSeconds <= 0) {
                  return 0;
              }

                if ($paidActualSeconds <= $initialIncrement) {
                    return $initialIncrement;
                }

                $remaining = $paidActualSeconds - $initialIncrement;
                $roundedRemaining = (int) ceil($remaining / $subsequentIncrement) * $subsequentIncrement;

                return $initialIncrement + $roundedRemaining;
          }




 8. Step 7 - Calculate Gross Amount
 For unit type MINUTE:
          billable_seconds = 120
          unit_price = 3.00 KES per minute
          billed_minutes = 120 / 60 = 2
          gross_amount = 2 * 3.00 = 6.00 KES

 Then apply setup fee and minimum charge:
          gross_amount = max(gross_amount + setup_fee_amount, minimum_charge_amount)

 12. Step 11 - Handle PREPAID Insufficient Balance
 If BIL-05 returns:
          {
              "errorCode": "INSUFFICIENT_BALANCE",
              "currentBalance": 3.00,
              "shortfall": 3.96
          }

 Do not delete the rated usage. Update:
          update rated_usage_record
          set settlement_status = 'FAILED'
          where rated_usage_id = 'rated-20260602-000001';

 Record attempt:
          target_module = BIL-05
          status = FAILED_FINAL
          error_code = INSUFFICIENT_BALANCE

 Emit PrepaidUsageDebitFailed.

 Downstream dunning/restriction policy should consume this event or read wallet state. RAT-01 does not decide service
 restriction.

 15. Suggested Worker Commands
 These are Laravel commands or queue jobs and can be consolidated into billing worker pods.
            rat:consume-mediated-usage
            rat:rate-pending
            rat:retry-settlement
            rat:replay-quarantine --id=urq-20260602-000001
            rat:expire-allowance-buckets
            rat:postpaid-cycle-readiness-check --cycle=2026-06

 Recommended schedule:

  Command                                                         Frequency

  rat:consume-mediated-usage                                      Continuous Kafka consumer.

  rat:rate-pending                                                Every minute if polling MED-01.

  rat:retry-settlement                                            Every 5 minutes for retryable target failures.

  rat:replay-quarantine                                           Manual or event-driven after catalog repair.

  rat:expire-allowance-buckets                                    Daily.

  rat:postpaid-cycle-readiness-check                              Before invoice generation.

 16. Error Codes
  Error code                                                      Meaning

  RAT_MEDIATED_USAGE_NOT_FOUND                                    MED-01 record cannot be loaded.

  RAT_DUPLICATE_MEDIATED_USAGE                                    Record already rated.

  RAT_BILLING_MODE_NOT_FOUND                                      Subscription billing mode cannot be resolved.

  RAT_TARIFF_LOOKUP_FAILED                                        PLM-CFG-07 lookup failed.

  RAT_RATE_NOT_FOUND                                              No applicable rate exists.

  RAT_TAX_COMPUTE_FAILED                                          PLM-CFG-02 tax compute failed.

  RAT_WALLET_NOT_FOUND                                            PREPAID subscription has no wallet.

  RAT_WALLET_DEBIT_FAILED                                         BIL-05 debit failed.

  RAT_INSUFFICIENT_BALANCE                                        BIL-05 returned insufficient balance.

  RAT_POSTPAID_ALREADY_INVOICED                                   Attempt to mark usage invoiced twice.




 17. Minimum Implementation Order
 Build in this order:

   1. Migrations for rated usage, allowance bucket, allowance consumption, rating quarantine, settlement attempt, rating job.

   2. Consumer for UsageMediated.

   3. Idempotency check on mediated_usage_id.

   4. Subscription billing-mode resolver.

   5. PLM-CFG-07 rating lookup client.

   6. Duration rounding calculator.

   7. Allowance bucket create/consume logic.

   8. PLM-CFG-02 tax compute client.

   9. Rated usage writer.

   10. PREPAID BIL-05 debit client.

   11. POSTPAID usage read and mark-invoiced APIs.

   12. Rating quarantine and replay APIs.

   13. Settlement retry worker.

   14. Backoffice read APIs.

 19. Developer Checklist
 Before marking RAT-01 complete:

   - No raw CDR parsing exists in RAT-01.

   - Rates are looked up from PLM-CFG-07.

   - Tax is computed by PLM-CFG-02.

   - mediated_usage_id uniqueness prevents double rating.

   - Allowance bucket updates are locked and atomic.

   - Rated usage is immutable after creation.

   - Wallet debit uses stable idempotency key.

   - Settlement attempts are recorded.

   - Postpaid invoice handoff prevents double invoicing.

   - Rating quarantine and replay work.
