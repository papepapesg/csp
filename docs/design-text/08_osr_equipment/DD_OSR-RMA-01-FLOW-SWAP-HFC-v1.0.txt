 1. What this flow is
 When a customer's HFC cable modem (or hybrid chassis with MTA, or STB, or smart card) fails — or NOC proactively
 detects an imminent failure, or the customer requests an in-tech upgrade — a technician must visit the premises with a
 replacement unit, retrieve the defective unit, and rebind the new device's CM-MAC at the SAME CMTS slot/port as the old
 one (UC-PR4: HFC modem authorization is bound to slot/port, moving the modem to a different port breaks authorization).

 This flow is *always* field-visit (no remote-swap path for HFC — DOCSIS modems can't be unprovisioned remotely without
 the unit being physically present for the swap), and it's *always* contractor-routed (the tech who recovers the old modem
 becomes the recovery contractor; the defective unit routes back to that contractor's van, not main warehouse — the
 Wananchi 40+ stale-equipment fix).




SOPHIX BSS Design Documents                                                                                                                 Page 3
 When the source instance is a hybrid chassis (HYB equipment_kind, modeled per workshop 2026-04-29 as CM-MAC +
 MTA-MAC + optional CPMAC for static-IP packages), the Broadhub double-config path applies: Broadhub + Clearcable
 NOMS are both reconfigured by the serial-rebind-broadhub-stub worker.

 What this flow does NOT do
   - Does not handle GPON ONT swaps. Use swap_kind=GPON_REMOTE or GPON_FIELD (separate FLOW-SWAP-GPON
     satellite). HFC and GPON have different provisioning adapters and different OLT-side semantics.

   - Does not handle equipment termination retrieval — that's EQP_TERMINATION (separate FLOW-EQP satellite).

   - Does not orchestrate the WO itself. WO creation calls WO-01; WO lifecycle (claim, dispatch, finalize) is WO-01's
     concern. This flow reacts to wo-finalized message catch.

   - Does not own the contractor-stock-routing logic. Uses framework worker contractor-stock-route which
     encapsulates the Wananchi-fix routing decision (defective unit → recovering contractor's van).

   - Does not handle HomePass. HFC equipment-to-HomePass binding is NOT modeled in HomePass-CFG
     network_path today (HomePass.network_path is GPON-centric, terminal ONT node). HFC swaps therefore do not call
     homepass-network-path-update.

 Glossary additions (specific to this flow)
  Term                                                           Meaning

  CMTS slot/port                                                 The physical CMTS (Cable Modem Termination System) chassis card slot and
                                                                 port number to which the HFC modem is bound for authorization. Format
                                                                 {cmts:'nrb-cmts-01', slot:3, port:12}.

  UC-PR4 (slot/port preservation)                                Workshop 2026-04-30 rule: HFC modem authorization MUST stay at the same
                                                                 slot/port across a swap. Moving the new modem to a different slot/port breaks
                                                                 Broadhub authorization. The rebind call MUST carry the source's slot/port
                                                                 verbatim.

  Double-config (static-IP HFC)                                  For static-IP HFC packages, two provisioning systems must be reconfigured:
                                                                 Broadhub (subscriber + CM-MAC binding) AND Clearcable NOMS (the CPMAC
                                                                 public-IP binding). Single rebind call exposes both; adapter handles the dual
                                                                 write.

  Hybrid chassis                                                 An HFC equipment chassis carrying both a cable modem (CM-MAC) and an
                                                                 MTA voice port (MTA-MAC). Per workshop 2026-04-29, MTA-MAC = CM-MAC
                                                                 + 2 (computed). Some hybrid chassis also carry a CPMAC for static-IP carriage.

 4. Rules (HFC-specific)
  Rule                                                                   Description

  R-HFC-1                                                                Source equipment_kind MUST be CABLE_MODEM, MTA, STB, SMART_CARD,
                                                                         or HYB. Eligibility worker rejects with failureCode=NOT_HFC_FAMILY
                                                                         otherwise.

  R-HFC-2                                                                Source network_slot_metadata.cmts, slot, port MUST be non-null.
                                                                         Eligibility worker rejects with failureCode=MISSING_SLOT_PORT otherwise
                                                                         — slot/port preservation impossible without source values.

  R-HFC-3                                                                Target instance MUST have an SKU compatible with the source's
                                                                         equipment_kind (e.g., source CM → target CM; source HYB → target HYB;
                                                                         cross-kind rejected). Future enhancement: explicit upgrade-compatibility matrix
                                                                         per operator in PLM-CFG-06.

  R-HFC-4                                                                Hybrid chassis target MUST carry CM-MAC + MTA-MAC + (CPMAC if source
                                                                         had CPMAC). Eligibility worker validates;
                                                                         failureCode=HYB_MAC_INCOMPLETE.

  R-HFC-5                                                                serial-rebind-broadhub-stub worker MUST receive slotPort
                                                                         matching flow_payload.{cmts,slot,port} from source. Worker-side
                                                                         assertion; mismatch results in immediate FAILED transition with
                                                                         reason=SLOT_PORT_MISMATCH_AT_REBIND (R-OSR-RMA-8 enforces).

  R-HFC-6                                                                Static-IP packages require doubleConfig=true in flow_payload; adapter
                                                                         receives the dual-write signal. Eligibility worker derives this from subscription
                                                                         metadata; if metadata is missing, conservative default is FALSE (single-write).

  R-HFC-7                                                                Rebind retry: up to 3 attempts before transitioning to FAILED. Each retry
                                                                         triggers a new lifecycle event row (PROVISIONING_RETRY_<n>). Final failure
                                                                         rolls back source instance to van (IN_CONTRACTOR_STOCK) and target
                                                                         instance to van (IN_CONTRACTOR_STOCK); no customer-side change.

  R-HFC-8                                                                If source CMTS slot/port differs from any of the operator's known active CMTS
                                                                         chassis (operator-config cmts_registry), eligibility fails with
                                                                         failureCode=CMTS_UNKNOWN. Prevents swap creation against stale or
                                                                         migrated CMTS references.
