 1. Purpose
 This DD defines the Customer Self-Care Frontoffice App.

 The app gives customers a simple way to view their account, subscriptions, invoices, payments, wallet/top-up information,
 installation/order status, support tickets, notifications, and limited self-service actions.

 The app is Kenya/WIK-first but must support future operators through configuration: language, currency, brand, legal text,
 payment instructions, tax labels, feature flags, and support categories.


 2. Design Position
 FE-APP-04 is customer-facing. It must hide internal workflow complexity and show clear customer-safe states.

 Allowed local state:

  Session tokens                                Yes                                                 Follow OIDC security policy.

  Last selected account/subscription            Yes                                                 No sensitive details beyond ids/display labels.

 Rules:

   - Do not show stale cached balance as final.

   - Payment and service status must be refreshed after customer action.

   - If one panel fails, show a local panel error and keep the rest of the app usable.

 11. Security And Privacy
 Rules:

   - Customer JWT must map to allowed customer/account scope.

   - Customer cannot pass arbitrary customerId to read another account.

   - Mask sensitive ID/KYC fields by default.

   - Invoice PDFs and support attachments must use authorized APIs.

   - Do not expose internal notes/comments on tickets.

   - Do not expose internal module names, worker names, or stack traces.

   - Do not allow customer self-service actions unless backend policy exposes them.

   - Logout must clear local cache and drafts.

 14. Implementation Notes
 Recommended build order:

   1. Implement app shell, auth, runtime config, account selector.

   2. Implement customer/account/profile panels from ILM.

   3. Implement subscription/service list from SUB-LM.

   4. Implement billing invoice list/detail/PDF from BIL.

   5. Implement support ticket create/list/detail from TCK.

   6. Implement notification preferences.

   7. Implement order/install tracking.

   8. Add limited self-service subscription actions only after backend policy is confirmed.

   9. Add E2E tests for dashboard, invoice/payment, and ticket creation.

 Do not implement local payment confirmation, local subscription status changes, or local ticket status changes. Those states
 belong to BIL, SUB, and TCK.


 15. Acceptance Checklist
   - [ ] Every screen/action names its module API owner.

   - [ ] ILM owns profile/account/contact/preferences source data.

   - [ ] SUB owns subscription status and self-service operations.

   - [ ] BIL owns invoices, PDFs, payments, wallet, and dunning visibility.

   - [ ] TCK owns customer support tickets and timeline.

   - [ ] File downloads/uploads use authorized file APIs.

   - [ ] Customer scope is enforced by backend and not only hidden in UI.

   - [ ] Payment confirmation comes only from BIL.

   - [ ] Kenya/WIK labels, legal text, payment instructions, currency, and language are configurable.

   - [ ] E2E tests cover invoice/payment and support ticket creation.
