 MVP simplification baseline: RAT-01 is offline/batch rating only in this design. Implement after MED-01, wallet/payment
 basics, and tariff catalog are stable. Do not implement online rating/session control in the first release.



 1. Purpose
 RAT-01 defines how SOPHIX rates mediated usage records and turns them into billable financial results.

 The first required use case is voice usage rating:
            MED-01 mediated CDR
              -> RAT-01 tariff lookup, allowance consumption, tax computation
              -> PREPAID wallet debit or POSTPAID rated usage for invoice generation

 RAT-01 exists because usage charging is different from lifecycle charging. BIL-01 handles lifecycle/business-intent charges
 such as activation, migration, relocation, fees, and proration. RAT-01 handles high-volume usage records such as CDRs.



 2. Ownership Boundary
  Concern                                                             Owner

  Raw CDR import, normalization, duplicate detection, quarantine      MED-01

  Tariff plans, zones, prefixes, rates, allowances definitions        PLM-CFG-07

  Usage rating execution, rated usage ledger, allowance consumption   RAT-01

  Tax computation for usage charge                                    PLM-CFG-02 called by RAT-01

  PREPAID wallet debit                                                BIL-05 called by RAT-01

  POSTPAID invoice generation from rated usage                        BIL-02-GEN-01 reads or consumes RAT-01 rated usage

  Tax invoice after payment/topup/invoice                             BIL-02-TAX-01

  Wallet balance and wallet ledger                                    BIL-05


 Rule: RAT-01 must not parse raw CDR files. It consumes only mediated usage from MED-01.

 Rule: RAT-01 must not own wallet balances or invoice numbering. It calls the owning modules.



 3. Scope
 3.1 In Scope
   - Consume UsageMediated events or poll MED-01 records.

   - Rate voice calls using PLM-CFG-07 tariff lookup.

   - Apply call duration rounding rules.

   - Apply charge policy:

   - CHARGEABLE;

   - BLOCKED;

   - Manage per-subscription allowance buckets and allowance consumption.

   - Compute tax using PLM-CFG-02.

   - Store immutable rated usage records.

   - Debit PREPAID wallets via BIL-05.

   - Expose POSTPAID rated usage to invoice generation.

   - Destination prefix catalog maintenance.

   - Wallet topup handling.

   - External payment gateway callbacks.

   - Dunning decisions after insufficient wallet balance.

   - Invoice PDF generation.

   - Tax authority signing.

 5. Core Concepts
 5.1 Rated Usage
 A rated usage record is the immutable financial result of rating one mediated usage record.

 Example:
           {
               "ratedUsageId": "rated-20260602-000001",
               "mediatedUsageId": "med-20260602-000001",
               "subscriptionId": "SUB-700045",
               "usageType": "VOICE_CALL",
               "zoneCode": "KE_MOBILE",
               "actualDurationSeconds": 75,
               "billableDurationSeconds": 120,
               "grossAmount": 6.00,
               "taxAmount": 0.96,
               "netAmount": 6.96,
               "currency": "KES",
               "settlementStatus": "SETTLED"

 5.2 Allowance Bucket
 An allowance bucket tracks remaining included usage for a subscription and cycle.

 Example:
            100 on-net minutes per bill cycle

 PLM-CFG-07 defines the allowance. RAT-01 creates and consumes the runtime bucket.

 5.3 Settlement
 Settlement is what happens after rating:

  Billing mode                                                             Settlement

  PREPAID                                                                  Immediate wallet debit through BIL-05.

  POSTPAID                                                                 Rated usage remains pending for invoice generation.

  ZERO_RATED                                                               No settlement, but record is stored for audit/reporting.

 12. Infra Recommendation
 12.1 Medium Budget Deployment
  Component                                                        Recommendation

  API pods                                                         2 pods, 1 vCPU, 1.5 GB RAM each.

  Rating workers                                                   1-2 workers, 2 vCPU, 4 GB RAM each.

  Settlement workers                                               1 worker, 1 vCPU, 2 GB RAM.

  DB                                                               Billing PostgreSQL schema usage_rat; partition rated usage monthly.

  Cache                                                            Redis/local cache for tariff lookup and tax config, invalidated by catalog events.

  Kafka                                                            Consume UsageMediated, emit rating/settlement events.



 12.2 Recommended Partitions
 Partition monthly:

   - rated_usage_record

   - usage_settlement_attempt

   - usage_rating_quarantine

   - usage_allowance_consumption

 Allowance bucket table is current-state plus cycle history and does not need partitioning at launch.

 12.3 OS Recommendation
 Use Ubuntu Server 24.04 LTS for VPS deployments or hardened Debian/Ubuntu slim base images for containers.

 Rating workers should run near the database and cache. They do not need public internet exposure.

 14. Testing Requirements
 14.1 Unit Tests
   - 75 seconds with 60/60 increments becomes 120 billable seconds.

   - 61 seconds with 1/1 increments remains 61 billable seconds.

   - Zero-rated rate creates zero gross/tax/net.

   - Allowance reduces paid seconds.

   - Allowance bucket lock prevents over-consumption.

   - Tax compute response is stored in rated usage.

   - Duplicate mediated usage returns prior rated result.

 14.2 Integration Tests
   - UsageMediated event rates successfully.

   - PLM-CFG-07 missing rate creates rating quarantine.

   - PREPAID rated usage debits BIL-05 exactly once.

   - BIL-05 insufficient balance marks settlement failed.

   - POSTPAID rated usage is returned to invoice generation and marked invoiced.

   - Retry settlement uses same idempotency key.

 14.3 End To End Tests
   - Raw CDR from MED-01 becomes wallet debit for PREPAID customer.

   - Raw CDR from MED-01 becomes invoice line source for POSTPAID customer.

   - Duplicate CDR does not create second wallet debit.

   - Tariff update effective tomorrow does not change today's CDR rating.



 15. Definition Of Done
 RAT-01 is complete when:

   - It consumes mediated usage from MED-01.

   - It looks up tariffs through PLM-CFG-07.

   - It applies duration rounding and allowances.

   - It computes tax through PLM-CFG-02.

   - It stores immutable rated usage records.

   - PREPAID settlement debits BIL-05 idempotently.

   - POSTPAID rated usage can be consumed once by invoice generation.

   - Rating quarantine and replay are implemented.

   - Settlement retry is implemented.

   - Backoffice can inspect rated usage, allowance buckets, quarantine, and settlement failures.
