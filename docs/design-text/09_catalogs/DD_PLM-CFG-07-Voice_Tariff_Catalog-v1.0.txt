 1. Purpose
 PLM-CFG-07 defines the configurable voice tariff catalog used to rate voice usage records.

 It answers these questions:

   - Which tariff plan applies to a voice service or package?

   - Which destination zone does a called number belong to?

   - What rate applies for that zone, time period, and call type?

   - What rounding increment is used?

   - Which calls are free, blocked, zero-rated, or premium-rated?

   - Are there bundled free minutes or allowances?

 This DD is required before usage mediation and rating can be implemented. MED-01 will normalize CDRs. RAT-01 will rate
 those mediated CDRs. PLM-CFG-07 supplies the tariff configuration that rating uses.

 3. When To Use This Catalog
 Use PLM-CFG-07 when:

   - A new voice product is launched.

   - A voice package needs a different local/international rate plan.

 5. Core Concepts
 5.1 Tariff Plan
 A tariff plan is the rated price structure for a voice service.

 Example:
          WIK_RES_VOICE_STANDARD_2026

 It may contain rates for local mobile, local fixed, on-net, East Africa, international, premium, toll-free, and emergency
 destinations.

 5.2 Destination Zone
 A destination zone groups dialed numbers that share rating behavior.

 Examples:

   - WIK_ON_NET

   - KE_MOBILE

   - KE_FIXED

   - EA_REGION

   - INTERNATIONAL_ROW

   - TOLL_FREE

   - EMERGENCY

   - PREMIUM

 5.3 Prefix Mapping
 Prefix mapping converts a normalized called number into a destination zone using longest-prefix match.

 Example:
            +2547 -> KE_MOBILE
            +25420 -> KE_FIXED
            999 -> EMERGENCY


 5.4 Rate
 A rate defines price per unit for a tariff plan, destination zone, call type, time band, and effective date.

 Example:
            KE_MOBILE, PEAK, 3.00 KES per minute, 60/60 billing increment


 5.5 Allowance
 An allowance is an included quantity, such as 100 on-net minutes per month.

 Allowance consumption is performed by RAT-01, but the allowance definition is stored here.

 9. Sample Rating Calculation
 Input CDR after mediation:
          {
              "operatorCode": "WIK",
              "subscriptionId": "SUB-700045",
              "serviceRef": "svc_VOIP_STD",
              "calledNumberNormalized": "+254711222333",
              "durationSeconds": 75,
              "callStartedAt": "2026-06-02T10:15:00+03:00"
          }

 Catalog lookup returns:
          unit_price = 3.00 KES per minute
          initial_increment_seconds = 60
          subsequent_increment_seconds = 60

 Rating calculation performed by RAT-01:
          75 actual seconds -> rounded to 120 billable seconds
          120 / 60 = 2 billed minutes
          2 * 3.00 = 6.00 KES

 PLM-CFG-07 supplies the data. RAT-01 performs this calculation and creates the usage charge/debit.

 11. Frontend Usage
 FE-APP-01 Backoffice uses PLM-CFG-07 for:

   - Voice tariff plan list/detail.

   - Destination zone management.

   - Prefix import and validation.

   - Rate import and overlap validation.

   - Allowance setup.

   - Tariff binding to package/service.

   - Activation/retirement workflow.

 Self-care and sales apps normally do not manage tariffs. They may display customer-friendly price summaries from package
 APIs, not raw tariff tables.



 12. Infra Recommendation
 PLM-CFG-07 is a catalog service feature, not a high-throughput runtime service by itself.

 Recommended medium deployment:

  Component                                                         Recommendation

  API pods                                                          Use existing PLM/catalog API pods. No dedicated service required unless
                                                                    catalog load grows.

  DB                                                                Existing catalog PostgreSQL schema.

  Cache                                                             Redis or local cache for rating lookup. RAT-01 should cache tariff lookup results
                                                                    with event invalidation.

  Workers                                                           Optional import validation worker for large prefix/rate uploads.


 Recommended partitions:

   - No partition required for core catalog tables at launch.

   - Keep audit/history tables if catalog framework already supports them.

   - Prefix imports should be batch-tracked for rollback and validation.

 OS recommendation:

   - Same as catalog service baseline: Ubuntu Server 24.04 LTS for VPS, or hardened Debian/Ubuntu slim images in
     containers.

 14. Testing Requirements
 14.1 Unit Tests
   - Longest-prefix match picks most specific prefix.

   - Rate overlap validation rejects ambiguous rates.

   - Emergency zone returns zero-rated policy.

   - Premium zone requires explicit rate.

   - Effective-date lookup selects historical rate.

   - Binding priority selects subscription override before package binding.

 14.2 Integration Tests
   - Create draft tariff plan, add zones, add prefixes, add rates, activate plan.

   - Bulk prefix import rejects duplicate active prefixes.

   - Rating lookup returns correct rate for package/service/called number/time.

   - Rate change event invalidates rating cache.

 14.3 End To End Tests With RAT-01
   - 75-second mobile call rates as 2 billed minutes.

   - Emergency call produces zero charge.

   - Unknown prefix quarantines CDR in RAT-01.

   - Package-bound allowance is consumed before paid rate.



 15. Definition Of Done
 PLM-CFG-07 is complete when:

   - Tariff plan, zone, prefix, time band, rate, allowance, and binding tables are implemented.

   - Admin APIs can create, validate, activate, and retire tariff plans.

   - Rating lookup API returns deterministic tariff data.

   - Longest-prefix match works.

   - Effective-date rating lookup works.

   - Rate overlap validation works.

   - Events are emitted for cache invalidation.

   - Backoffice can manage the catalog.

   - RAT-01 can use the lookup API without reading catalog tables directly.
