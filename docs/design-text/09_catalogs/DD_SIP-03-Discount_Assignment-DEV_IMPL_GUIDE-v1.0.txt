 1. How To Read This Guide
 Discount assignment is the operational layer between the discount catalog and billing runtime.

 PLM-CFG-04 says what the discount is. SIP-03 says who gets it and when. DIS-OP-01 later decides how the active
 assignment is applied to a charge/invoice/wallet event.

 Do not put invoice amount calculation in SIP-03.

 Do not hardcode approval steps in SIP-03. Configurable approvals are owned by EM-CFG-04. SIP-03 calls EM-CFG-04 to
 evaluate/start approval, then waits for an approval outcome callback. Camunda is involved only when the selected
 EM-CFG-04 policy uses approvalMode = BPMN.



 2. Step 1 - Validate Discount Catalog Item
 When a user creates an assignment, first load the discount:
           GET /api/discounts/RETENTION_10PCT_3M

 Expected:
           {
               "discountId": "disc-1001",
               "discountCode": "RETENTION_10PCT_3M",
               "effectiveStatus": "ACTIVE",
               "flavor": "PRICE_REBATE",
               "type": "PERCENTAGE",
               "value": 10,
               "eligiblePackageRefs": ["pkg-fiber-100m", "pkg-fiber-200m"],
               "eligibleBillableEventRefs": ["RECURRING_MRC"],
               "startDate": "2026-01-01",
               "endDate": "2026-12-31"
           }

 Reject assignment when:

   - discount does not exist;

   - discount is not ACTIVE;

   - requested validity does not fit policy;

   - discount flavor or billable event does not match intended usage.

 6. Step 5 - Runtime Query
 DIS-OP-01 calls SIP-03 when rating/charging an event:
          GET /api/discount-assignments/effective?operatorCode=WIK&subscriptionId=SUB-700045&eventCode=RECURRING_MRC&onDate=2026-06-

 SIP-03 query logic:
          select *
          from discount_assignment
          where operator_code = 'WIK'
            and status = 'ACTIVE'
            and valid_from <= date '2026-06-30'
            and (valid_to is null or valid_to >= date '2026-06-30')
            and (
              (scope_type = 'SUBSCRIPTION' and scope_ref_id = 'SUB-700045')
              or (subscription_id = 'SUB-700045')
            )
          order by priority desc, created_at asc;

 SIP-03 returns assignments only. DIS-OP-01 loads discount catalog details and computes actual application.



 7. Step 6 - Cancel Assignment
 Cancel future use:
          POST /api/discount-assignments/da-001/cancel
          Content-Type: application/json

          {
              "reasonCode": "CUSTOMER_NO_LONGER_ELIGIBLE",
              "effectiveDate": "2026-07-01",
              "comment": "Customer changed package."
          }

 Patch:
          update discount_assignment
          set status = 'CANCELLED',
              cancelled_at = now(),
              metadata_json = metadata_json || '{"cancelReasonCode":"CUSTOMER_NO_LONGER_ELIGIBLE","cancelEffectiveDate":"2026-07-01"
          where assignment_id = 'da-001'
            and status in ('ACTIVE', 'SUSPENDED', 'PENDING_APPROVAL');

 Important: do not reverse already issued invoices. If a past invoice must be corrected, create a BIL-02-ADJ-01 adjustment
 request.

 9. Suggested Worker Commands
 These can run inside the existing catalog/commercial worker pool.
          discount-assignment:expire
          discount-assignment:batch-run
          discount-assignment:approval-reminder
          discount-assignment:runtime-cache-refresh

  Command                                                        Purpose

  discount-assignment:expire                                     Marks assignments EXPIRED after valid_to.

  discount-assignment:batch-run                                  Validates and processes batch items.

  discount-assignment:approval-reminder                          Alerts approval queues about pending approvals.

  discount-assignment:runtime-cache-refresh                      Refreshes active assignment read model/cache for DIS-OP.

 10. Drools Rule Samples
 Use Drools for configurable assignment eligibility, stacking, and approval decisions.
          package rules.commercial.discount_assignment

          rule "Target package must be eligible for discount"
          when
            $a : DiscountAssignmentFact(packageEligible == false)
            $out : DiscountAssignmentDecision()
          then
            $out.reject("DA_TARGET_NOT_ELIGIBLE");
          end

          rule "Same stacking group conflict blocks assignment"
          when
            $a : DiscountAssignmentFact(hasActiveStackingConflict == true)
            $out : DiscountAssignmentDecision()
          then
            $out.reject("DA_STACKING_CONFLICT");
          end

          rule "Long manual retention assignment requires approval"
          when
            $a : DiscountAssignmentFact(sourceChannel == "BACKOFFICE", reasonCode == "RETENTION_SAVE", durationDays > 90)
            $out : DiscountAssignmentDecision()
          then
            $out.setApprovalRequired(true);
            $out.setApprovalPolicyCode("DISCOUNT_ASSIGNMENT_RETENTION");
          end




 11. Error Codes
  Code                                                             Meaning

  DA_DISCOUNT_NOT_FOUND                                            Discount catalog item does not exist.

  DA_DISCOUNT_NOT_ACTIVE                                           Discount is inactive/retired.

  DA_TARGET_NOT_FOUND                                              Scope target does not exist.

  DA_TARGET_NOT_ELIGIBLE                                           Target violates discount eligibility.

  DA_DUPLICATE_ACTIVE_ASSIGNMENT                                   Duplicate active assignment blocked.

  DA_STACKING_CONFLICT                                             Existing assignment conflicts by stacking group.

  DA_APPROVAL_REQUIRED                                             Assignment cannot activate before approval.

  DA_APPROVAL_REQUEST_FAILED                                       EM-CFG-04 approval request could not be started.

  DA_APPROVAL_OUTCOME_MISMATCH                                     Approval callback does not match assignment/policy/request.

  DA_BATCH_PARTIALLY_FAILED                                        Bulk batch has failed rows.

  DA_CANNOT_CANCEL_TERMINAL_STATUS                                 Assignment is already expired/cancelled/rejected.

 13. Test Scenarios
 13.1 Manual Retention Discount
   - Care user previews subscription assignment.

   - Target is eligible.

   - Assignment is created active.

   - Runtime query returns assignment.

 13.2 Approval Required
   - User creates high-value discount.

   - Status is PENDING_APPROVAL.

   - Runtime query excludes it.

   - Supervisor approves through EM-CFG-04 task API.

   - EM-CFG-04 callback activates assignment.

   - Runtime query includes it.

 13.3 Duplicate Blocked
   - Active assignment exists for same discount/scope/window.

   - New create returns 409 DA_DUPLICATE_ACTIVE_ASSIGNMENT.

 13.4 Campaign Batch
   - Batch has 100 targets.

   - 96 assignments created.

   - 4 failed rows stored with failure code.

   - Batch status becomes PARTIALLY_FAILED.

 13.5 Cancellation
   - Assignment is cancelled.

   - Runtime query no longer returns it for future date.

   - Past invoice remains unchanged.



 14. Developer Checklist
   - Assignment validates against PLM-CFG-04.

   - Assignment target is validated through owning module API.

   - Runtime query returns assignments, not calculated amounts.

   - Approval is configured and executed by EM-CFG-04; SIP-03 stores only the local approval reference and final outcome.

   - Camunda is used only when EM-CFG-04 returns approvalMode = BPMN.

   - Drools covers configurable assignment eligibility/stacking/approval decisions.

   - Cancellation does not create invoice/wallet reversal.

   - Bulk processing is idempotent per target.
