 1. Purpose
 SIP-03 defines how SOPHIX assigns configured discounts to customers, accounts, subscriptions, orders, franchises, or
 campaign cohorts.

 The discount catalog defines what a discount is. SIP-03 defines who gets it, why they get it, for which scope, for which period,
 and how the assignment is cancelled or audited.

 Examples:

   - retention agent assigns 10% recurring discount to a subscription for 3 months;

   - sales campaign assigns free installation discount to new customers in a territory;

   - franchise manager assigns acquisition discount to leads converted by a franchise;

   - care supervisor assigns goodwill discount after approved complaint;

   - batch job assigns a campaign discount to eligible customers;

   - admin cancels a customer discount assignment because customer no longer qualifies.

 SIP-03 does not calculate invoice amounts at billing time. Billing-time application is owned by DIS-OP-01 and
 BIL-01/BIL-02. SIP-03 creates and governs assignment records that runtime billing reads.

 Rule: SIP-03 may create, approve, activate, cancel, and expire discount assignments. It must not apply money directly to
 invoices or wallets. Runtime financial impact is handled by billing modules.

 Approval rule: SIP-03 does not define approval steps locally. It calls EM-CFG-04 to evaluate and run the configured approval
 policy for actions such as DISCOUNT_ASSIGNMENT_CREATE, DISCOUNT_ASSIGNMENT_CANCEL, or
 DISCOUNT_ASSIGNMENT_OVERRIDE. EM-CFG-04 may execute the approval as auto-approval, single-step DB-driven
 approval, multi-step approval, or Camunda BPMN depending on operator policy.

 7.2 Preview Assignment
          POST /api/discount-assignments/preview
          Content-Type: application/json

 Returns whether the target is eligible and whether approval is required. SIP-03 determines this by calling EM-CFG-04
 approval evaluation with a business context such as discount code, duration, reason code, source channel, customer
 segment, franchise, estimated value, and requester role.

 Example EM-CFG-04 evaluation call:
          POST /api/approvals/evaluate
          Content-Type: application/json

          {
              "operatorCode": "WIK",
              "moduleCode": "SIP-03",
              "actionCode": "DISCOUNT_ASSIGNMENT_CREATE",
              "subjectType": "DISCOUNT_ASSIGNMENT",
              "context": {
                "discountCode": "RETENTION_10PCT_3M",
                "reasonCode": "RETENTION_SAVE",
                "sourceChannel": "BACKOFFICE",
                "scopeType": "SUBSCRIPTION",
                "durationDays": 92,
                "estimatedValue": 1500.00,
                "currencyCode": "KES"
              }
          }

 If EM-CFG-04 returns approvalRequired = true, SIP-03 creates the assignment in PENDING_APPROVAL, starts an
 approval request through EM-CFG-04, and stores approval_request_id.

 7.3 Approve Assignment
 Normal approver action happens through EM-CFG-04 task APIs:
          POST /api/approvals/tasks/{approval_task_id}/approve
          Content-Type: application/json

          {
              "decisionComment": "Approved retention discount for three months."
          }

 After EM-CFG-04 finalizes the approval request, it calls the SIP-03 callback:
          POST /internal/discount-assignments/{assignment_id}/approval-outcome
          Content-Type: application/json

          {
              "approvalRequestId": "apr-da-001",
              "outcome": "APPROVED",
              "decisionComment": "Approved retention discount for three months."
          }

 SIP-03 then marks discount_assignment_approval.status = APPROVED and activates the assignment. If outcome
 is REJECTED, SIP-03 marks the assignment REJECTED.

 10. Rule Engine Guidance
 SIP-03 should use Drools for operator-variable commercial decisions:

  Rule file                                                                Purpose

  discount-assignment-eligibility.drl                                      Validates target eligibility against discount, package, franchise, channel,
                                                                           customer segment, and reason code.

  discount-assignment-stacking.drl                                         Decides whether the new assignment conflicts with existing active assignments.

  discount-assignment-approval.drl                                         Decides when to call EM-CFG-04 and which approval policy code to request.


 Fixed checks such as non-null fields, date parsing, idempotency, and foreign id lookup remain normal application validation.

 Example rule:
              rule "Retention discount above 90 days requires approval"
              when
                $a : DiscountAssignmentFact(reasonCode == "RETENTION_SAVE", durationDays > 90)
                $out : DiscountAssignmentDecision()
              then
                $out.setApprovalRequired(true);
                $out.setApprovalPolicyCode("DISCOUNT_ASSIGNMENT_RETENTION");
              end

 12. Infra Recommendation
 For a medium budget deployment, run SIP-03 inside the same commercial/catalog API deployment as SIP package
 management or the billing discount submodule, depending on final code ownership. Do not create a separate pod at first.

  Component                                                         Recommendation

  API                                                               Existing catalog/commercial API pods expose
                                                                    /api/discount-assignments.

  DB                                                                Same PostgreSQL cluster as catalog/billing commercial config.

  Workers                                                           Existing worker pool runs expiry scan and bulk assignment jobs.

  Events                                                            Kafka/MSK topics under sophix.commercial.discount-assignment.*.

  Cache                                                             Runtime read model/cache for active assignments by customer/subscription.


 AWS deployment: use existing ECS/EKS service and RDS cluster, with separate schema if the team wants ownership clarity.
 Add CloudWatch alarms for failed bulk jobs, high duplicate rejection rate, expiry worker failure, and runtime query latency.

 14. Definition Of Done
   - Discount assignment tables and APIs exist.

   - Assignment validates against discount catalog and target owner modules.

   - Approval and batch assignment flows work.

   - EM-CFG-04 is used for configurable approval policies; SIP-03 does not hardcode approver steps.

   - Drools rule files exist for configurable eligibility, stacking, and approval decisions.

   - Runtime query API returns active assignments for DIS-OP.

   - Events are emitted for assignment state changes.

   - Backoffice can create, approve, cancel, and monitor assignments.

   - Sales app can show/request eligible discounts.

   - Tests cover manual, campaign, bulk, cancellation, and runtime query paths.
