 1. Purpose
 SIP-04 defines how SOPHIX launches commercial bundles and controls bundle-to-bundle migration paths.

 A bundle is a commercial offer made of one or more existing package references, optional one-off charges, optional discount
 assignment rules, and channel/region/franchise availability. Examples:

   - Fiber Internet + IPTV starter bundle;

   - Internet + Voice bundle for residential customers;

   - franchise acquisition bundle with free installation discount;

   - business bundle with static IP, higher SLA, and recurring add-on;

   - migration bundle replacing an older offer with a newer commercial offer.

 SIP-04 does not define low-level services. Services are owned by PLM-CFG-01. Packages are owned by SIP-01. Discounts
 are owned by PLM-CFG-04/SIP-03. SIP-04 coordinates these catalog items into a launchable commercial bundle and
 publishes rules that order capture, sales, subscription workflows, and billing can consume.

 Rule: SIP-04 publishes bundle catalog and migration rules. It must not directly change existing subscriptions or create
 invoices. SUB/FUL/BIL modules execute customer-facing operations using SIP-04 rules.

 Approval rule: SIP-04 does not define approval steps locally. Launch approval should call EM-CFG-04 for
 BUNDLE_LAUNCH_APPROVAL or similar action codes. Camunda is used only when the selected EM-CFG-04 policy is
 BPMN-backed.



 3. When To Use This DD
 Use SIP-04 when:

   - product team needs to launch a multi-package commercial offer;

   - sales team needs one selectable offer made of several packages;

   - existing customers need migration from old bundle to new bundle;

   - bundle availability differs by franchise, region, technology, channel, or customer segment;

   - launch requires pre-checks before becoming sellable.

 Do not use SIP-04 for:

  Scenario                                                                         Use

  Creating a single package and its price/version                                  SIP-01

  Creating a discount definition                                                   PLM-CFG-04

  Assigning a discount to a customer/order                                         SIP-03

  Running a promotion with dates, cohorts, and channels                            SIP-05

  Moving one customer's subscription                                               SUB-WF-MIGRATION/UPGRADE/DOWNGRADE

 10. Rule Engine Guidance
 Use Drools for bundle decisions that are operator-variable or combine several facts:

  Rule file                                                                Purpose

  bundle-launch-validation.drl                                             Launch readiness beyond fixed DB/API checks, such as minimum package mix
                                                                           or channel restrictions.

  bundle-availability.drl                                                  Dynamic availability by channel, franchise, region, customer segment, or date.

  bundle-migration-eligibility.drl                                         Whether a customer can move from one bundle to another and which SUB
                                                                           workflow owns execution.


 Fixed checks such as bundle code uniqueness, package existence, and date parsing remain normal application validation.

 Example rule:
              rule "Self-care migration requires consent"
              when
                $m : BundleMigrationFact(channelCode == "SELF_CARE", movementType == "MIGRATION")
                $out : BundleMigrationDecision()

 11. Frontend Usage
 11.1 FE-APP-01 Backoffice
 Backoffice must support:

   - create/edit bundle drafts;

   - add package components;

   - configure availability and discount rules;

   - run validation checks;

   - submit/approve launch;

   - activate/suspend/retire;

   - manage migration rules;

   - preview migration from a customer/subscription context.

 11.2 FE-APP-02 Sales App
 Sales app uses read-only availability APIs:

   - list available bundles for lead/HomePass/franchise/channel;

   - show bundle components and total offer summary;

   - show attached promotional terms;

   - submit selected bundle into lead/order conversion payload.

 Sales app must not define bundle rules locally. It displays bundle results returned by SIP-04/SIP-05 APIs.



 12. Infra Recommendation
 For a medium budget deployment, run SIP-04 inside the existing commercial/catalog API deployment. Do not create a
 separate pod initially.

  Component                                                        Recommendation

  API                                                              Existing catalog/commercial API pods expose /api/commercial-bundles.

  DB                                                               Same PostgreSQL cluster/schema family as SIP package/commercial catalog.

  Workers                                                          Existing worker pool handles scheduled activation, retirement, validation
                                                                   refresh.

  Events                                                           Kafka/MSK topics under sophix.commercial.bundle.*.

  Cache                                                            Read model/cache for available bundles by channel/franchise/region.


 AWS deployment: use existing ECS/EKS service and RDS cluster. Add alarms for activation worker failure, validation failures
 on approved bundles, stale availability cache, and migration preview error rate.

 14. Definition Of Done
   - Bundle tables and APIs exist.

   - Bundle lifecycle is implemented and auditable.

   - Bundle validation checks package, discount, availability, and billing compatibility.

   - Available bundle API is usable by Backoffice, Sales App, order capture, and self-care.

   - Migration rules exist and delegate execution to SUB workflows.

   - Drools rule files exist for configurable launch, availability, and migration decisions where operator policy requires them.

   - Events refresh downstream caches.

   - Tests cover launch, availability, retirement, and migration preview.
