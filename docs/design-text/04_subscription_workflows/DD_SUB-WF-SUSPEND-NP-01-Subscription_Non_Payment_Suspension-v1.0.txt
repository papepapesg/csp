 1. What this is
 The non-payment suspension operation. SUB-WF-SUSPEND-NP-01 is one of the 10 operation kinds in the framework.
 Triggered exclusively by BIL-04 when a subscription crosses its dunning suspension threshold (grace period expired on an
 unpaid invoice, prepaid wallet drained past reactivation window, level-3 dunning escalation reached). System-driven only —
 no human or self-service trigger is accepted.

 Outcomes: subscription status → SUSPENDED, all active restrictions cleared (per SUB-LM-01 R-RES-6), network access
 revoked (FUL-04 SUSPEND_SERVICE), suspension history row written with originIntent = SUSPEND_NP +
 systemManaged = true, customer notified by NOT-01, BIL-04 acknowledged via Kafka event.

 What this DD owns
   1. subscription_suspend_np_config table — per-operator config: customer-notification preference at suspension,
     debt-amount threshold reporting flags.

   2. BILLING_INTERNAL-only trigger gating — only BIL-04's service account may call the trigger endpoint.

   3. originIntent = SUSPEND_NP + systemManaged = true marker contract on the pause-history row (the row is
     owned by SUB-LM-01's pause-history table, but this DD defines the flags applied).

   4. Trigger REST endpoint — POST /api/subscriptions/{subscription_id}/suspend-np.

   5. Domain Kafka events — SubscriptionSuspendedForNonPayment + SubscriptionSuspendNPRejected.

   6. Suspend-NP workflow rules — 11 rules in §4.

 What this DD does NOT own
   - BPMN files — owned by per-operator satellites.

   - Worker implementations — catalogued in DD_SUB-WF-FRAMEWORK-01-WORKERS.

   - Subscription state machine + status transitions — owned by SUB-LM-01 (states, transitions, restriction-clear behavior
     on suspend per R-RES-6).

   - Pause-history table itself — owned by SUB-LM-01.

   - Dunning ladder orchestration — owned by BIL-04. This DD is a callee.

   - Network suspension implementation — owned by FUL-04 (SUSPEND_SERVICE intent).

   - Restriction additions before full suspension — owned by SUB-WF-RESTRICT-01 (BIL-04 may add restrictions at L2
     via that workflow before reaching L3 here).

   - Resume after debt settlement — owned by SUB-WF-RESUME-01 (DUNNING_RESUME trigger).

 4. Rules
 4.1 State precondition + transition


SOPHIX BSS Design Documents                                                                                                                Page 5
  Rule                               Description

  R-SUB-WF-SUSPEND-NP-01-S-1         Suspension requires the subscription's status_code = ACTIVE. Other
                                     statuses (already SUSPENDED, PENDING_*, TERMINATED, RETIRED,
                                     CREATED) return 409 INVALID_STATE_FOR_SUSPEND_NP. Idempotent
                                     re-submission of the same idempotency key returns the existing
                                     operation_id.

  R-SUB-WF-SUSPEND-NP-01-S-2         The transition is ACTIVE → PENDING_SUSPEND_NP → SUSPENDED.
                                     PENDING_SUSPEND_NP is a framework-internal transient state (per SUB-LM-01
                                     catalog) used during the saga; downstream consumers should see only the
                                     commit to SUSPENDED.

  R-SUB-WF-SUSPEND-NP-01-S-3         Per framework R-FW-1, this operation is mutually exclusive with other
                                     state-affecting operations on the same subscription. If another in-flight operation
                                     exists (e.g., a customer just triggered PAUSE), the workflow uses the
                                     framework's external-cancel-requested mechanism to cancel it before
                                     proceeding. RESTRICT operations are concurrent-safe per their own design
                                     and do not need cancellation.

  R-SUB-WF-SUSPEND-NP-01-S-4         The subscription's current_transition_type is set to SUSPEND_NP during
                                     PENDING_SUSPEND_NP. current_transition_reason_code is set to
                                     the caller-supplied dunningReasonCode.



 4.2 Trigger gating
  Rule                               Description

  R-SUB-WF-SUSPEND-NP-01-T-1         The trigger endpoint is callable only by the BILLING_INTERNAL role. Any other
                                     actor (human or service) returns 403 UNAUTHORIZED_TRIGGER with the
                                     allowed role for diagnostic clarity.

  R-SUB-WF-SUSPEND-NP-01-T-2         Request body MUST include dunningReasonCode (free-text from BIL-04's
                                     reason catalog), dunningCycleReference (BIL-04's internal correlation ID
                                     for the dunning wave), outstandingDebtAmount,
                                     outstandingDebtCurrency. Optional: dunningEscalationLevel
                                     (integer). Missing required fields → 400 MISSING_REQUIRED_FIELD.

  R-SUB-WF-SUSPEND-NP-01-T-3         Idempotency: BIL-04 generates the idempotency key per dunning cycle.
                                     Re-submission of the same key returns the existing operation_id per
                                     framework R-FW-3.



 4.3 Master fields + pause-history
  Rule                               Description

  R-SUB-WF-SUSPEND-NP-01-M-1         On commit, the subscription's master fields are updated:
                                     last_status_changed_at = NOW(). suspended_at (if SUB-LM-01 has
                                     this field; otherwise inferable from status_history) is set via
                                     sub-lm-put-master-fields.

  R-SUB-WF-SUSPEND-NP-01-M-2         A pause-history row is inserted into SUB-LM-01's pause-history table with
                                     originIntent = SUSPEND_NP, systemManaged = true,
                                     dunningReasonCode, dunningCycleReference,
                                     dunningEscalationLevel, outstandingDebtAmount,
                                     outstandingDebtCurrency, suspendedAt = commitAt. The row has no
                                     cycleAnchorPolicy (not applicable; SUSPEND-NP does not configure cycle
                                     behavior).

  R-SUB-WF-SUSPEND-NP-01-M-3         All entries in subscription.active_restrictions[] are cleared at the
                                     same time (per SUB-LM-01 R-RES-6 — restrictions are auto-removed when
                                     transitioning to SUSPENDED since suspension already revokes all service).
                                     Done via sub-lm-put-active-restrictions with
                                     restrictionsOperationKind = CLEAR_ALL. The pre-clear array is
                                     captured in the Kafka event for audit.



 4.4 Resume protection
  Rule                               Description

  R-SUB-WF-SUSPEND-NP-01-R-1         A subscription with an open SUSPEND_NP-flagged pause-history row can only
                                     be resumed via SUB-WF-RESUME-01's DUNNING_RESUME trigger (BIL-04
                                     after debt settlement) or ADMIN_FORCE_RESUME trigger (admin override).
                                     SUB-WF-RESUME-01's role gating enforces this; SUB-WF-SUSPEND-NP-01
                                     only ensures the flags are correctly set on the pause-history row.
