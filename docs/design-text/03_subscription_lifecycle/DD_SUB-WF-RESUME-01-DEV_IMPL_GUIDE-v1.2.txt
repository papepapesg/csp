 Resume
 1. Purpose
 This guide explains resume implementation as the flow executes at runtime.

 Use it with:

   - DD_SUB-WF-RESUME-01-Subscription_Resume-v1.2.md

 This guide is the parent-level implementation flow. Operator BPMN details are in the FLOW satellite.


 2. Runtime Actors
  Runtime component                                                What it does

  subscription-workflow-api pod                                    Receives resume request, validates, starts operation.

  SUB-LM module/API                                                Provides authoritative subscription status and mutation APIs.

  Pause/history persistence                                        Provides the open pause-history row and closes it after success.

  BIL-01                                                           Computes resume intent, reconnection fee, and debt-cleared validation.

  BIL-04                                                           Calls DUNNING_RESUME after non-payment debt is settled.

  FUL-03                                                           Reactivates network service.

  Camunda                                                          Runs resume BPMN.

  Drools                                                           Validates trigger, role, origin-intent, and billing decisions.

  Worker apps                                                      Execute BPMN service task topics.

  Scheduler                                                        Calls SCHEDULED_AUTO_RESUME when resume_scheduled_at is due.




 3. Before The Request Can Work
 Required:

   - subscription_resume_config seeded.

   - subscription_pause_history exists and has resume close-out fields.

   - subscription_operation_config has (operator_code=WIK, operation_kind=RESUME) ->
     sub-resume-wik.

   - Drools package rules.subscription.resume.wik.

   - BPMN process sub-resume-wik.

   - Worker apps subscribe to required topics.

   - FUL-03 can reactivate the service.

   - BIL-01 supports RESUME_INTENT and RESUME_NP_INTENT.

 5. Step 2 - API Validates Shape And Idempotency
 Validate request shape:

  Field                                                           Validation

  operatorCode                                                    Required.

  resumeTrigger                                                   One of CUSTOMER_REQUESTED_RESUME, ADMIN_FORCE_RESUME,
                                                                  DUNNING_RESUME, SCHEDULED_AUTO_RESUME.

  resumeReasonCode                                                Required for audit.

  dunningCycleReference                                           Required for DUNNING_RESUME.

  adminForceResumeReason                                          Required for ADMIN_FORCE_RESUME on SUSPEND_NP.


 Idempotency behavior:

   - Same key and same request hash returns existing operation response.

   - Same key and different request hash returns 409 IDEMPOTENCY_KEY_REUSED.

   - Check existing key and hash before inserting a new operation.

   - Use a DB unique constraint or transaction guard so concurrent duplicate calls cannot create two operations.

 7. Step 4 - API Applies Fast Rejections
 Before calling the framework:

  Check                                                             Failure

  Subscription status is SUSPENDED.                                 409 INVALID_STATE_FOR_RESUME

  No other state operation in progress.                             409 OPERATION_IN_PROGRESS

  Actor role matches trigger.                                       403 ROLE_NOT_AUTHORIZED_FOR_TRIGGER

  Open row exists.                                                  409 NO_OPEN_PAUSE_HISTORY

  Trigger matches open row origin_intent.                           403 error from origin-intent matrix

  Scheduler trigger has resume_scheduled_at.                        400 NO_SCHEDULED_RESUME_TIME


 This fast validation improves API response quality. The BPMN still re-checks the same rules with Drools after it starts.

 9. Drools Rules To Configure
 9.1 Subscription Must Be SUSPENDED
          rule "resume requires suspended subscription"
          when
            $req: ResumeRequestFact()
            $sub: SubscriptionStateFact(subscriptionId == $req.subscriptionId, statusCode != "SUSPENDED")
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("INVALID_STATE_FOR_RESUME")
            }
          end


 9.2 Open Pause Row Required
          rule "resume requires open pause history"
          when
            $req: ResumeRequestFact(eligible == null)
            not (PauseHistoryFact(subscriptionId == $req.subscriptionId, actualResumeAt == null))
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("NO_OPEN_PAUSE_HISTORY")
            }
          end


 9.3 Trigger Role Gating
          rule "customer requested resume allowed roles"
          when
            $req: ResumeRequestFact(
               resumeTrigger == "CUSTOMER_REQUESTED_RESUME",
               eligible == null,
               initiatingActorRole not in ("CUSTOMER_SELF_SERVICE", "CALL_CENTER", "SUBSCRIPTION_OPERATOR")
            )
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("ROLE_NOT_AUTHORIZED_FOR_TRIGGER")
            }
          end

          rule "dunning resume requires billing internal"
          when
            $req: ResumeRequestFact(
               resumeTrigger == "DUNNING_RESUME",
               eligible == null,
               initiatingActorRole != "BILLING_INTERNAL"
            )
          then
            modify($req) {
               setEligible(false);

 9.4 Origin-Intent Gating
          rule "customer cannot resume admin pause"
          when
            $req: ResumeRequestFact(resumeTrigger == "CUSTOMER_REQUESTED_RESUME", eligible == null)
            $pause: PauseHistoryFact(subscriptionId == $req.subscriptionId, actualResumeAt == null, originIntent == "ADMIN_PAUSE")
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("ADMIN_PAUSE_BLOCKS_CUSTOMER_RESUME")
            }
          end

          rule "customer cannot resume non payment suspension"
          when
            $req: ResumeRequestFact(resumeTrigger == "CUSTOMER_REQUESTED_RESUME", eligible == null)
            $pause: PauseHistoryFact(subscriptionId == $req.subscriptionId, actualResumeAt == null, originIntent == "SUSPEND_NP")
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("SYSTEM_MANAGED_SUSPENSION")
            }
          end

          rule "dunning resume only resumes non payment suspension"
          when
            $req: ResumeRequestFact(resumeTrigger == "DUNNING_RESUME", eligible == null)
            $pause: PauseHistoryFact(subscriptionId == $req.subscriptionId, actualResumeAt == null, originIntent != "SUSPEND_NP")
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("NOT_A_DUNNING_SUSPENSION")
            }
          end

          rule "scheduled auto resume requires scheduled time"
          when
            $req: ResumeRequestFact(resumeTrigger == "SCHEDULED_AUTO_RESUME", eligible == null)
            $pause: PauseHistoryFact(subscriptionId == $req.subscriptionId, actualResumeAt == null, resumeScheduledAt == null)
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("NO_SCHEDULED_RESUME_TIME")
            }
          end


 9.5 Billing Intent Decision
          rule "dunning resume uses resume non payment intent"
          when
            $req: ResumeRequestFact(resumeTrigger == "DUNNING_RESUME")
            $cfg: ResumeConfigFact(dunningResumeVerifyDebtCleared == true)
          then
            modify($req) {
               setBillingIntentKind("RESUME_NP_INTENT");
               setRequiresDebtClearedCheck(true);
               setRequiresReconnectionFeePayment(false)
            }
          end

          rule "customer resume reconnection fee"
          when
            $req: ResumeRequestFact(resumeTrigger == "CUSTOMER_REQUESTED_RESUME")
            $cfg: ResumeConfigFact(reconnectionFeeOnCustomerResume == true)

  3                                         Compute cycle window.                     sub-lm-compute-cycle-window

  Order                                     BPMN service task does this            Worker topic/message

  4                                         Ask billing for resume intent.         bil01-emit-intent

  5                                         Optional pay-first reconnection fee.   bil01-charge-pre-authorize,
                                                                                   payment-confirmed, bil01-confirm-charge

  6                                         Reactivate service.                    ful-call-activate

 These names are worker topics or BPMN message names, not shell commands.

 Implementation guidance:

   - If SUB-LM and pause-history persistence are in one module, write status audit fields and pause-history close-out in one
      transaction.

   - If they are split, call approved internal APIs or an orchestration service.

   - Do not close the row before FUL-03 reactivation succeeds.

   - Do not close the row if final state commit cannot be completed; route to manual recovery if needed.

 18. Step 14 - Success Event Is Emitted

           SubscriptionResumed

 Topic:
           sophix.subscription.subscription.resumed

 Emitted only after SUB-LM commits ACTIVE.

 20. Manual Smoke Test - Dunning Resume
   1. Seed subscription_resume_config.

   2. Seed operation config (WIK, RESUME) -> sub-resume-wik.

   3. Create a suspended subscription.

   4. Create open subscription_pause_history row with origin_intent = SUSPEND_NP.

   5. Send resume API request with DUNNING_RESUME using BIL-04 service token.

   6. Confirm operation row exists.

   7. Confirm BPMN process exists.

   8. Confirm subscription moves to PENDING_RESUME.

   9. Confirm BIL-01 receives RESUME_NP_INTENT.

   10. Simulate or receive FUL-03 fulfillment-completed.

   11. Confirm pause-history row has actual_resume_at populated.

   12. Confirm subscription becomes ACTIVE.

   13. Confirm SubscriptionResumed outbox row exists.

   14. Confirm operation final state is COMPLETED.


 21. Manual Smoke Test - Scheduled Auto Resume
   1. Create a suspended subscription with open pause row:

 origin_intent = CUSTOMER_REQUESTED_PAUSE, resume_scheduled_at <= now, actual_resume_at = NULL.

   2. Call resume API with scheduler service token and SCHEDULED_AUTO_RESUME.

   3. Confirm origin-intent gate accepts the request.

   4. Confirm BPMN skips reconnection fee for WIK default config.

   5. Confirm FUL-03 reactivates service.

   6. Confirm pause-history row closes.

   7. Confirm subscription becomes ACTIVE.


 22. Common Mistakes
   - Reading current subscription status from cache.

   - Starting BPMN without loading the open pause-history row.

   - Letting customers self-resume SUSPEND_NP.

   - Letting BIL-04 dunning-resume voluntary pauses.

   - Closing pause history before FUL-03 succeeds.

   - Creating separate worker deployments for every topic without an operations need.

   - Failing the whole operation because NOT-01 notification failed.
