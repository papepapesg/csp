 1. How To Read This Guide
 Bundle launch is a catalog/commercial flow.

 SIP-04 creates a sellable bundle from existing SIP-01 packages, validates availability, attaches optional discount assignment
 rules, publishes availability, and defines allowed bundle-to-bundle migration paths. It does not migrate customers by itself.

 6. Step 5 - Validate Bundle
 Run:
           POST /api/commercial-bundles/bun-001/validate

 Implementation checks:

   1. Bundle has at least one mandatory component.

   2. All packages exist and are active/launch-ready.

   3. Component packages support requested tech/franchise availability.

   4. Discount refs are active.

   5. Billing event compatibility exists for bundle components.

   6. No active bundle already uses same code.

                "bundleCode": "FIBER_TV_STARTER",
                "launchDate": "2026-07-01"
              }
          }

 Approver approves through EM-CFG-04 task API. EM-CFG-04 then calls SIP-04 callback:
          POST /internal/commercial-bundles/bun-001/approval-outcome
          Content-Type: application/json

          {
              "approvalRequestId": "apr-bun-001",
              "outcome": "APPROVED",
              "decisionComment": "Approved for Nairobi sales launch."
          }

 SIP-04 patches the bundle:
          update commercial_bundle
          set status = 'APPROVED',
              updated_at = now()
          where bundle_id = 'bun-001'
            and status = 'READY_FOR_REVIEW';

 If approval is not required, SIP-04 can apply the same status transition immediately after validation.



 8. Step 7 - Activate Bundle
 Scheduled worker or admin action activates on/after launch date:
          POST /api/commercial-bundles/bun-001/activate

 Patch:
          update commercial_bundle
          set status = 'ACTIVE',
              updated_at = now()
          where bundle_id = 'bun-001'
            and status = 'APPROVED'
            and launch_date <= current_date;

 9. Step 8 - Sales App Lists Available Bundles
 Sales app calls:
           GET /api/commercial-bundles/available?operatorCode=WIK&channelCode=SALES_APP&franchiseId=fr_01J_NRB_002&homepassId=HP-001&

 Backend filters:
           select b.*
           from commercial_bundle b
           join commercial_bundle_availability a on a.bundle_id = b.bundle_id
           where b.operator_code = 'WIK'
             and b.status = 'ACTIVE'
             and a.status = 'ACTIVE'
             and a.channel_code = 'SALES_APP'
             and a.franchise_id = 'fr_01J_NRB_002'
             and a.effective_from <= date '2026-07-02'
             and (a.effective_to is null or a.effective_to >= date '2026-07-02');

 Return components and discount rule summaries. Do not return internal launch approval notes.



 10. Step 9 - Order Capture Uses Bundle
 When a lead/order selects the bundle, FUL-02 order payload includes:
           {
               "bundleCode": "FIBER_TV_STARTER",
               "selectedComponents": [
                  {"packageRef": "pkg-fiber-100m"},
                  {"packageRef": "pkg-iptv-starter"}
               ],
               "sourceChannel": "SALES_APP",
               "franchiseId": "fr_01J_NRB_002"
           }

 FUL-02 calls SIP-04 to validate the bundle is still available. If discount rules exist, FUL/SIP-05/SIP-03 creates discount
 assignments at the appropriate step.

 12. Step 11 - Preview Customer Migration
 Backoffice calls:
           POST /api/commercial-bundles/migration-preview
           Content-Type: application/json

           {
               "operatorCode": "WIK",
               "subscriptionId": "SUB-700045",
               "sourceBundleCode": "OLD_FIBER_TV",
               "targetBundleCode": "FIBER_TV_STARTER",
               "channelCode": "BACKOFFICE"
           }

 SIP-04:

   1. resolves source and target bundles;

   2. checks an active migration rule;

   3. checks target bundle availability;

   4. returns workflow owner.

 Response:
           {
               "allowed": true,
               "movementType": "MIGRATION",
               "requiresCustomerConsent": true,
               "requiresWo": false,
               "feePolicyCode": "NO_FEE",
               "owningWorkflow": "SUB-WF-MIGRATION-01"
           }

 Backoffice then calls SUB workflow. SIP-04 does not change the subscription.



 13. Drools Rule Samples
 Use Drools when launch/availability/migration decisions are operator-variable.
           package rules.commercial.bundle

           rule "Bundle with discount rules requires launch approval"
           when
             $b : BundleLaunchFact(hasDiscountRules == true, status == "READY_FOR_REVIEW")
             $out : BundleLaunchDecision()
           then
             $out.setApprovalRequired(true);
             $out.setApprovalPolicyCode("BUNDLE_LAUNCH_APPROVAL");
           end

           rule "Sales app availability requires active franchise"
           when

 14. Suggested Worker Commands
          commercial-bundle:activate-due
          commercial-bundle:retire-due
          commercial-bundle:validation-refresh
          commercial-bundle:availability-cache-refresh

  Command                                                           Purpose

  commercial-bundle:activate-due                                    Activates approved bundles whose launch date has arrived.

  commercial-bundle:retire-due                                      Retires bundles with retire date reached.

  commercial-bundle:validation-refresh                              Re-checks package/discount refs for approved future launches.

  commercial-bundle:availability-cache-refresh                      Refreshes read model for sales/order/self-care lookups.




 15. Error Codes
  Code                                                              Meaning

  BUNDLE_CODE_DUPLICATE                                             Bundle code already exists.

  BUNDLE_COMPONENT_REQUIRED                                         No mandatory package component.

  BUNDLE_PACKAGE_NOT_FOUND                                          Component package does not exist.

  BUNDLE_PACKAGE_NOT_SELLABLE                                       Component package is not active/launch-ready.

  BUNDLE_AVAILABILITY_CONFLICT                                      Availability does not match component package availability.

  BUNDLE_DISCOUNT_NOT_ACTIVE                                        Discount rule references inactive discount.

  BUNDLE_VALIDATION_FAILED                                          Launch validation has FAIL checks.

  BUNDLE_APPROVAL_REQUIRED                                          Bundle cannot activate before EM-CFG-04 approval.

  BUNDLE_APPROVAL_REQUEST_FAILED                                    EM-CFG-04 approval request failed.

  BUNDLE_INVALID_STATUS_TRANSITION                                  Requested lifecycle transition is not allowed.

  BUNDLE_MIGRATION_RULE_NOT_FOUND                                   No active source-to-target rule.

  BUNDLE_NOT_AVAILABLE_FOR_CONTEXT                                  Channel/franchise/region/date cannot sell this bundle.

 17. Test Scenarios
 17.1 Launch Bundle
   - Create bundle draft.

   - Add two active package components.

   - Add sales app availability.

   - Validate, approve, activate.

   - Available bundles API returns the bundle.

 17.2 Invalid Package Blocks Launch
   - Add retired package as component.

   - Validation creates FAIL row.

   - Submit review returns 409 BUNDLE_VALIDATION_FAILED.

 17.3 Bundle Discount Rule
   - Attach ACQ_FREE_INSTALL.

   - Available API includes discount rule summary.

   - Order flow later creates SIP-03 assignment.

 17.4 Migration Preview
   - Active migration rule exists.

   - Preview returns allowed and SUB-WF-MIGRATION-01.

   - No subscription state changes inside SIP-04.



 18. Developer Checklist
   - Bundle uses SIP-01 package refs only.

   - Bundle launch does not change subscriptions.

   - Availability filters by channel/franchise/region/date.

   - Active bundle composition is immutable.

   - Launch approval is configured/executed in EM-CFG-04.

   - Drools covers configurable launch/availability/migration decisions where needed.

   - Migration preview delegates execution to SUB workflow.

   - Events refresh downstream caches.
