 1. What this is
 The migration operation. Triggered by: a customer requesting a HomePass change + Package change in one operation
 (CUSTOMER_REQUESTED_MIGRATION), or admin-driven tech cohort migration (ADMIN_TECH_MIGRATION). Admin-driven
 cross-technology migration requires FUL-10 to be enabled for the operator.

 Outcomes (at actual commit time): subscription homepass_id updated to target, previous_homepass_id snapshot
 retained, package_ref + package_version_id updated to target Package, previous_package_ref +
 previous_package_version_id snapshot retained, migration fee + signed proration delta (or RESET cycle pair) charged
 per BIL-01 v1.1, physical work via WO-01 SHIFTING flow (or self-move), FUL-07 bookkeeping updated on both
 HomePasses, source HomePass network-side de-provisioned + target HomePass provisioned for target Package via FUL-03
 + FUL-04, last_migrated_at master field updated, customer notified.

 For non-IMMEDIATE effectiveTiming, the subscription remains ACTIVE on source HomePass + source Package during
 the wait. A second pending-future migration is rejected; any state-affecting operation during the wait cancels the pending
 migration.

 What this DD owns
   1. subscription_migration_config table — per-operator config.

   2. Trigger taxonomy — 2 triggers with role gating.

   3. Target-Package validation rules — target Package must differ from source, status sellable.

   4. Target-HomePass validation rules — sellable, status active, service-family compatibility for TARGET Package,
     port-provisioned.

   5. equipmentPath taxonomy + auto-inference rules — taking target Package's equipment requirements into account.

   6. disconnectMode taxonomy + resolution rules.

   7. cycleAnchorPolicy taxonomy + resolution rules.

   8. effectiveTiming taxonomy + non-IMMEDIATE timer + cancellation paths.

   9. WO-01 SHIFTING integration sequencing — same as RELOCATION-01 v1.1, with extra MODIFY_SERVICE step
     post-activation for Package fan-out.

   10. Trigger + cancel REST endpoints.

   11. Domain Kafka events — SubscriptionMigrationScheduled, SubscriptionMigrated,
     SubscriptionMigrationRejected, SubscriptionMigrationCancelled.

 What this DD does NOT own
   - BPMN files — per-operator satellites.

   - Worker implementations — DD_SUB-WF-FRAMEWORK-01-WORKERS.

   - Subscription state machine — SUB-LM-01.

   - Package + Package Version catalog — SIP-01.

   - Service catalog + Provisioner interfaces — PLM-CFG-01.

   - HomePass row mutations — RLM-CFG-01. Read-only.

   - WO state machine, BPMN, contractor model, finalization mechanics — WO-01-FRAMEWORK +
     WO-01-FLOW-SHIFTING.

 4. Rules
 4.1 State precondition + transition
  Rule                                                                           Description

  R-SUB-WF-MIGRATION-01-S-1                                                      Migration requires subscription's status_code = ACTIVE at request time
                                                                                 AND at commit time. Other statuses return 409
                                                                                 INVALID_STATE_FOR_MIGRATION.

  R-SUB-WF-MIGRATION-01-S-2                                                      The transition at commit is ACTIVE → PENDING_MIGRATION → ACTIVE.
                                                                                 PENDING_MIGRATION entered only during commit window.

  R-SUB-WF-MIGRATION-01-S-3                                                      Per framework R-FW-1, migration COMMIT is mutually exclusive with other
                                                                                 state-affecting operations. Scheduled-future migration in wait state allows other
                                                                                 operations (which cancel the pending migration).

  R-SUB-WF-MIGRATION-01-S-4                                                      current_transition_type = MIGRATION during
                                                                                 PENDING_MIGRATION. current_transition_reason_code =
                                                                                 migrationTrigger. Not set during scheduled-future wait.

  R-SUB-WF-MIGRATION-01-S-5                                                      Restrictions on the subscription preserved post-migration. New HomePass +
                                                                                 new Package inherit the restriction set. Operator policy may decide to clear or
                                                                                 re-evaluate; this DD does not.

  R-SUB-WF-MIGRATION-01-S-6                                                      At most one pending-future migration per subscription. Second
                                                                                 non-IMMEDIATE returns 409 PENDING_MIGRATION_ALREADY_SCHEDULED.

                               MIGRATION_PRORATE_DELTA (signed, may be charge or credit);

  R-SUB-WF-MIGRATION-01-B-4    If pay_first_required = true AND totals.net > 0: pay-first gate at
                               COMMIT time. Workflow waits for payment-confirmed before creating
                               SHIFTING WO (or before proceeding past self-move acknowledgement).
                               Payment timeout (7 days operator default) → cancel migration.

  R-SUB-WF-MIGRATION-01-B-5    If totals.net <= 0 (net credit — possible with DOWNGRADE-flavored
                               migration + RESET cycle pair where credit exceeds new charge): POSTPAID
                               rejected with REQUIRES_CREDIT_NOTE_WORKFLOW per BIL-01 v1.1 R-SE-3 →
                               workflow emits Rejected with BILLING_REJECTED_NEGATIVE_NET.
                               PREPAID wallet absorbs the credit (top-up).
