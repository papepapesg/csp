 MVP simplification baseline: first release USSD scope is limited to language selection, customer lookup, balance/debt status,
 payment instructions/status, support ticket creation/status, and callback request. Do not implement package changes,
 subscription migration, complex Customer 360 views, or local business state in USSD v1.



 1. Purpose
 FE-CH-USSD-01 defines the USSD self-care channel for customers using feature phones or low-bandwidth mobile access.

 The USSD channel should support simple customer self-service such as account lookup, balance, invoice/debt status,
 package/subscription summary, payment instructions, ticket creation/status, language selection, and callback request.

 USSD is a channel adapter. It does not own customer, billing, payment, subscription, ticket, or notification logic.



 2. Scope And Boundaries
  Capability                                                         Owner

  USSD session, menu, screen rendering, telco gateway adapter        FE-CH-USSD-01

  Customer/account/contact lookup                                    ILM-CFG-01

  Subscription summary/status                                        SUB-LM-01

  Balance, invoice, payment status                                   BIL-01/BIL-02/BIL-04

  Payment initiation/instructions                                    PAY-GW-01 and BIL payment APIs

  Support ticket create/status                                       TCK-01

  Customer notifications                                             NOT-01

  Interaction history                                                CUST-INT-01

  Permissions/channel policies                                       EM-CFG-03 / channel config


 Boundary rules:

   - USSD does not apply payments locally.

   - USSD does not change subscription state locally.

   - USSD does not close tickets locally.

   - USSD must call owning module APIs with idempotency keys.

   - USSD screens must be short, language-aware, and timeout-safe.

 When to use it: create/update on every gateway request until session ends or times out.

 6. Gateway API
 The exact request format depends on the USSD aggregator. The internal normalized endpoint should be:
            POST /api/channels/ussd/sessions
            Content-Type: application/json

            {
                "operatorCode": "WIK",
                "gateway": "SAFARICOM_AGGREGATOR",
                "gatewaySessionId": "gw-abc-001",
                "gatewayRequestId": "gw-msg-001",
                "msisdn": "254700000001",
                "inputText": "1",
                "shortCode": "*123#",
                "requestedAt": "2026-08-30T08:01:00Z"
            }

 Response:
            {
                "responseType": "CON",
                "text": "Balance: KES 1200\n1 Pay now\n2 Main menu"
            }

 8. Security And Privacy
   - Use MSISDN-based lookup carefully; do not expose sensitive data before customer match.

   - For risky actions, require PIN/OTP or route to assisted support.

   - Do not show full ID/KYC values.

   - Keep screens short and avoid sensitive details in request logs where possible.

   - Apply rate limits by MSISDN, gateway, and short code.

   - Mask MSISDN in logs outside operational support views.

 10. Test Scenarios
   1. New session resolves customer by MSISDN.

   2. Unknown MSISDN shows safe registration/support message.

   3. Balance menu calls billing API and renders short response.

   4. Payment instruction menu calls PAY-GW/BIL API.

   5. Support menu creates TCK ticket with idempotency key.

   6. Duplicate gateway request returns same response.

   7. Timeout marks session TIMED_OUT.

   8. Interaction is written to CUST-INT-01.
