 1. Purpose
 FUL-09 defines the fulfillment-side service and provisioning work required when customer equipment is swapped, replaced,
 upgraded, recovered, or re-bound.

 OSR-RMA-01 owns the equipment swap/RMA operational workflow: source/target equipment, contractor route, recovery,
 RMA state, and stock movement. FUL-09 owns the fulfillment effect: service continuity, network rebinding, provisioning
 commands, customer subscription impact, HomePass updates, and final activation confirmation.

 Use FUL-09 when:

   - swap workflow needs old device unbound and new device provisioned;

   - HFC modem replacement must preserve or update slot/port authorization;

   - GPON ONT replacement must unbind old ONT and bind new ONT at the OLT/HomePass;

   - STB/smart card replacement must update entitlement bindings;

   - equipment swap is part of relocation/shifting or upgrade;

   - swap is completed physically but provisioning/network state needs reconciliation.

 Procurement is related only upstream. OSR-02 creates future stock supply. FUL-09 must not call procurement inside a
 customer swap. Customer jobs consume available/reserved OSR stock.



 2. Scope And Boundaries
  Capability                                                                    Owner

  Swap request, recovery logistics, RMA routing, source/target instance state   OSR-RMA-01

  SKU quantity reservation/movement                                             OSR-01

  Serialized instance identity/current state/lifecycle                          OSR-INSTANCE-01

  Upstream stock replenishment/procurement                                      OSR-02

  Work order technician execution                                               WO-01

  Network/service provisioning commands                                         FUL-09 / FUL-03 / PROV-INT-01

  HomePass topology/path update                                                 RLM-CFG-01 via FUL-09/FUL-07 where applicable

  Billing charges/deposit delta                                                 BIL-01 / BIL-02

  Configurable override approval                                                EM-CFG-04

  Operator-variable swap fulfillment rules                                      Drools


 Boundary rules:

   - FUL-09 does not create purchase orders or procure stock.

   - FUL-09 does not allocate inventory. It consumes target equipment selected/reserved by OSR-RMA/OSR.

   - FUL-09 does not mutate OSR tables directly. It calls OSR-INSTANCE lifecycle APIs and consumes OSR-RMA events.

   - FUL-09 does not replace FUL-03; it coordinates equipment-specific provisioning and may call FUL-03/PROV-INT
     adapters.

   - Approval is needed only for risky manual override, forced completion, or exception repair. Normal swap execution follows
     workflow/rules.

   - OSR-02 procurement is not in the runtime path.



 4. Fulfillment Status Model
  Status                                                           Meaning

  REQUESTED                                                        Swap fulfillment requested by OSR-RMA/WO/SUB flow.

  VALIDATED                                                        Service/equipment context validated.

  PROVISIONING_OLD_UNBIND                                          Old device unbind in progress.

  PROVISIONING_NEW_BIND                                            New device bind/provision in progress.

  RECONCILING                                                      Network/BSS state being checked.

  COMPLETED                                                        Fulfillment complete.

  FAILED                                                           Fulfillment failed and can be retried or repaired.

  PENDING_APPROVAL                                                 Manual override/force-complete approval open.

  CANCELLED                                                        Fulfillment cancelled before network change.




 5. Data Model
 5.1 equipment_swap_fulfillment
 What it is for: stores one fulfillment execution for an equipment swap request.

 When to use it: every OSR-RMA swap that requires provisioning/network/service-side changes should create one fulfillment
 row.

 Sample meaning: esf-001 is the fulfillment execution that unbinds old ONT inst-old-001 and binds new ONT

           Idempotency-Key: esf-swap-001
           Content-Type: application/json

           {
               "operatorCode": "WIK",
               "swapRequestId": "swap-001",
               "woId": "wo-001",
               "subscriptionId": "SUB-700045",
               "accountId": "ACC-900045",

               "technologyFamily": "GPON",
               "sourceInstanceId": "inst-old-001",
               "targetInstanceId": "inst-new-001",
               "homepassId": "HP-001"
           }


 6.2 Execute Fulfillment
           POST /api/equipment-swap-fulfillments/{fulfillment_id}/execute
           Content-Type: application/json

 Execution:

   - validate OSR-RMA swap and OSR-INSTANCE source/target state;

   - call PROV-INT/FUL-03 adapters for old unbind/new bind;

 9. Rule Engine Guidance
 Use Drools for configurable swap fulfillment decisions:

  Rule file                                                             Purpose

  equipment-swap-fulfillment-routing.drl                                Select provisioning steps by technology, SKU, service family, and operator.

  equipment-swap-make-before-break.drl                                  Decide whether old/new can overlap during swap.

  equipment-swap-exception-approval.drl                                 Decide when manual override needs EM-CFG-04 approval.


 Example:
              package com.sophix.fulfillment.equipment_swap

              rule "GPON target bind requires OLT reconciliation"
              when
                $f : EquipmentSwapFulfillmentFact(technologyFamily == "GPON")
                $d : EquipmentSwapFulfillmentDecision()
              then
                $d.addStep("GPON_UNBIND_OLD_ONT");
                $d.addStep("GPON_BIND_NEW_ONT");
                $d.addReconciliationCheck("TARGET_ONT_BOUND");
              end

 13. Acceptance Criteria
   - Swap fulfillment tables and APIs exist.

   - OSR-RMA can start fulfillment and receive outcome.

   - FUL-09 validates OSR-RMA and OSR-INSTANCE state through APIs.

   - Provisioning commands are executed through PROV-INT/FUL-03 adapters.

   - GPON/HFC/IPTV/VOICE technology rules are configurable.

   - Manual force-complete uses EM-CFG-04 when configured.

   - Procurement is explicitly not in the customer swap runtime path.

   - Tests cover success, provisioning failure, reconciliation failure, forced completion approval, and idempotent retry.
