 MVP simplification baseline: implement stock and equipment instance basics before full inventory audit. OSR-05 can start

 1. Purpose
 OSR-05 defines physical inventory audit, discrepancy investigation, stock adjustment, and write-off governance for SOPHIX
 equipment stock.

 It covers central warehouse counts, contractor van counts, serialized equipment checks, discrepancy review, approved stock
 adjustments, and write-offs for lost, stolen, damaged, obsolete, or unrecoverable equipment.

 Use OSR-05 when:

   - warehouse team performs a monthly/quarterly stock count;

   - contractor van inventory must be checked;

   - system stock differs from physical stock;

   - serial device physically exists but system says it is elsewhere;

   - system shows equipment but staff cannot find it;

   - inventory discrepancy requires investigation;

   - approved adjustment/write-off must update OSR-01 and OSR-INSTANCE.

 OSR-05 does not own stock balances or device lifecycle. It investigates differences and calls OSR-01/OSR-INSTANCE to
 apply approved corrections.



 2. Scope And Boundaries
  Capability                                                                    Owner

  Inventory audit plan, count tasks, count results, discrepancy investigation   OSR-05

  SKU quantity balance and adjustment movement                                  OSR-01

  Serialized equipment current state and lifecycle transition                   OSR-INSTANCE-01

  Procurement receipt source records                                            OSR-02

  Contractor/team location ownership                                            EM-02

  Audit permissions                                                             EM-CFG-03

  Configurable write-off/adjustment approval                                    EM-CFG-04

  Configurable discrepancy severity/routing                                     Drools

  Internal audit notifications                                                  ICN-01

  Audit reporting                                                               REP-01


 Boundary rules:

   - OSR-05 must not directly edit stock_balance.

   - Quantity corrections are applied by OSR-01 stock adjustment movements.

   - Serialized write-offs/state corrections are applied by OSR-INSTANCE lifecycle events.

   - EM-CFG-04 owns approval policies and tasks. OSR-05 stores approval references and applies final outcome.

   - Camunda is used only when EM-CFG-04 selected policy mode is BPMN.

 7. Business Rules
  Rule                                           Description                                            Reason

  R-OSR-05-01                                    Audit location must exist in OSR-01.                   Valid count scope.

  R-OSR-05-02                                    Audit expected quantity is frozen at task              Stable variance calculation.
                                                 generation/start.

  R-OSR-05-03                                    Count submitter cannot approve own discrepancy         Segregation of duties.
                                                 resolution unless EM-CFG-04 explicitly allows it.

  R-OSR-05-04                                    Non-zero variance creates discrepancy unless           Audit traceability.
                                                 tolerance policy suppresses low-risk variance.

  R-OSR-05-05                                    Stock adjustment/write-off must be approved            Governance.
                                                 through EM-CFG-04 when policy requires it.

  R-OSR-05-06                                    Camunda is used only when EM-CFG-04 policy             Operational simplicity.
                                                 mode is BPMN.

  R-OSR-05-07                                    Approved quantity correction must call OSR-01          Stock ownership.
                                                 movement API.

  R-OSR-05-08                                    Serialized write-off must call OSR-INSTANCE            Serial traceability.
                                                 lifecycle API.

  R-OSR-05-09                                    Applied resolution must be idempotent.                 Prevent double adjustment.

  R-OSR-05-10                                    Audit closure requires all discrepancies               Complete audit trail.
                                                 closed/rejected/no-action.




 8. Rule Engine Guidance
 Use Drools for configurable audit policy:

  Rule file                                                                  Purpose

  inventory-discrepancy-severity.drl                                         Assign severity based on value, quantity, SKU family, location, and contractor.

  inventory-resolution-approval.drl                                          Decide EM-CFG-04 approval policy for write-off/adjustment.

  inventory-recount-policy.drl                                               Decide when recount is mandatory before resolution.


 Example:
              package com.sophix.osr.inventory

              rule "High value write off requires finance approval"
              when
                $r : InventoryResolutionFact(action == "WRITE_OFF", estimatedValue >= 10000.00, currencyCode == "KES")
                $d : InventoryResolutionDecision()
              then
                $d.setApprovalRequired(true);
                $d.setApprovalPolicyCode("INVENTORY_WRITE_OFF_FINANCE");
                $d.addReason("HIGH_VALUE_WRITE_OFF");
              end

 11. Infrastructure Recommendations
 For medium deployment, run OSR-05 inside the OSR/equipment API and shared OSR worker deployment.

  Component                                                       Recommendation

  API                                                             Add audit/discrepancy endpoints to OSR API.

  Database                                                        PostgreSQL OSR schema.

  Workers                                                         Shared OSR worker for outbox, reminders, and resolution retry.

  Mobile offline                                                  Contractor app can cache assigned count tasks and sync submissions with
                                                                  idempotency.

  Approval                                                        EM-CFG-04 shared service.

  Rules                                                           Drools/KIE for configurable audit routing.


 AWS notes: use ECS/EKS OSR service, RDS PostgreSQL, S3 for audit evidence/photos/files, MSK/Kafka for events, and
 Secrets Manager for credentials.



 12. Acceptance Criteria
   - Audit plan/task/count/discrepancy/resolution tables exist.

   - Audit count freezes expected OSR-01 quantities.

   - Variance creates auditable discrepancy with severity.

   - Resolution approvals use EM-CFG-04; OSR-05 does not hardcode approval steps.

   - Approved stock correction calls OSR-01 movement API.

   - Approved serialized write-off calls OSR-INSTANCE lifecycle API.

   - Contractor mobile app can submit assigned counts where configured.

   - Tests cover count variance, approval, idempotent apply, OSR-01 adjustment, and OSR-INSTANCE write-off.
