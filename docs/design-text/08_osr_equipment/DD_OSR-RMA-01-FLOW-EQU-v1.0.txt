 1. What this flow is
 A customer requests a tech upgrade (DOCSIS 3.0 cable modem → DOCSIS 3.1, Huawei ONT v1 → v2, SD STB → 4K STB),
 OR the operator initiates a mandatory replacement campaign (e.g., end-of-life of an SKU forces fleet-wide replacement).
 Either way, a contractor visits, swaps the old device for the new upgraded one, and the old device returns to main warehouse
 for inspection (NOT defective — typically re-deployable after testing).

 The defining property of EQU compared to defect swaps (SWAP-HFC, SWAP-GPON): the source instance is *not* defective.
 After recovery, it goes through main-warehouse inspection; if good, it re-enters the available pool (IN_MAIN_WAREHOUSE).
 For SWAP-HFC/GPON, the source is defective and typically heads for RMA-to-vendor.

 EQU is *always* chargeable: there's an upgrade fee defined in the BIL-01 charge catalog, plus a possible deposit delta (if the
 upgraded SKU carries a higher equipment deposit, the customer pays the difference; lower deposit = customer gets a partial
 refund queued for post-completion). Per workshop 2026-04-28: "Customer emails Call Center → CC gives advice (price +
 package) → customer makes payment → BO Dispatcher operates the change in Broadhub → WO scheduled." The pay-first
 sequence is baked in.

 When the upgrade involves GPON, the HomePass network_path terminal node serial is updated at TARGET_PLACED
 (same as SWAP-GPON). For HFC EQU, no HomePass update (HFC equipment isn't in HomePass.network_path).

 What this flow does NOT do
   - Does not change the subscription package or service class. That's SUB-WF-UPGRADE-01 (subscription upgrade
     workflow). EQU is the equipment-side companion: when a subscription upgrade requires new hardware,
     SUB-WF-UPGRADE-01 creates an EQU swap-request. EQU then runs to completion; SUB-WF-UPGRADE-01 catches
     SwapRequestCompleted and proceeds with its own steps (price change, service activation, etc.). For pure equipment
     upgrades that don't change subscription (rare — e.g., voluntary modem refresh), EQU runs standalone.

   - Does not handle defective-equipment swaps. Use SWAP-HFC or SWAP-GPON.

   - Does not handle termination-time equipment retrieval. Use EQP.

   - Does not transition the source instance to IN_FIELD_DEFECTIVE. The source is healthy; on recovery, it goes to
     RECOVERED_BY_CONTRACTOR then IN_CONTRACTOR_STOCK (van) then RETURNED_TO_MAIN_WAREHOUSE for
     inspection.

 4. Rules (EQU-specific)


SOPHIX BSS Design Documents                                                                                                                 Page 5
  Rule                                                             Description

  R-EQU-1                                                          upgradeFromSku MUST equal source instance's sku_id. Eligibility worker
                                                                   enforces.

  R-EQU-2                                                          (upgradeFromSku, upgradeToSku) MUST be declared as a valid upgrade
                                                                   path in PLM-CFG-06 operator config. Eligibility worker rejects with
                                                                   failureCode=INVALID_UPGRADE_PATH otherwise. v1.0 KE WIK paths:
                                                                   DOCSIS 3.0 → DOCSIS 3.1 cable modem, ONT v1 → ONT v2, SD STB → 4K
                                                                   STB. Cross-tech (HFC→GPON or vice versa) NOT supported as upgrade in
                                                                   v1.0 (use subscription relocation instead).

  R-EQU-3                                                          chargeable=TRUE always. Pay-first gate is mandatory. Free EQU
                                                                   (operator-paid mandatory upgrade campaigns where the customer doesn't pay)
                                                                   handled out of v1.0 scope — would require a chargeable=FALSE override + a
                                                                   OPERATOR_CAMPAIGN_FREE reason code.

  R-EQU-4                                                          Source instance MUST be IN_FIELD_ACTIVE. EQU does not handle
                                                                   defective-source (that's SWAP-* with reason CUSTOMER_REPORTED_DEFECT).

  R-EQU-5                                                          After recovery, source instance transitions through
                                                                   RECOVERED_BY_CONTRACTOR → IN_CONTRACTOR_STOCK →
                                                                   RETURNED_TO_MAIN_WAREHOUSE (per main-warehouse re-inspection path).
                                                                   NOT IN_FIELD_DEFECTIVE. The transition to IN_MAIN_WAREHOUSE
                                                                   happens after main-warehouse inspection (out of EQU scope; main-warehouse
                                                                   ops handles).

  R-EQU-6                                                          When depositDelta > 0: included in the pay-first billable event amount
                                                                   (customer pays upgrade fee + deposit delta in one transaction). When
                                                                   depositDelta < 0: refund queued POST-completion via a separate BIL-01
                                                                   billable event with chargeCode=DEPOSIT_REFUND,
                                                                   amount=abs(depositDelta), direction=REFUND_TO_CUSTOMER.
                                                                   R-OSR-RMA-11c (framework) governs.

  R-EQU-7                                                          For HFC upgrade where both source and target are HFC and on the same
                                                                   CMTS: UC-PR4 slot/port preservation applies (same as SWAP-HFC R-HFC-5).
                                                                   For cross-CMTS HFC upgrade (rare — usually only when the customer's
                                                                   premises migrated to a different CMTS chassis), preservation does not apply
                                                                   and the rebind uses the target's new slot/port.

  R-EQU-8                                                          For GPON upgrade: HomePass network_path terminal-node update is
                                                                   mandatory (same as SWAP-GPON R-GPON-5). The new ONT serial replaces
                                                                   the old serial in the HomePass terminal node.

  R-EQU-9                                                          If caller is SUB-WF-UPGRADE-01 (subscription-driven upgrade),
                                                                   flow_payload.subscriptionUpgradeRef MUST be populated.
                                                                   SUB-WF-UPGRADE-01 waits for SwapRequestCompleted before proceeding
                                                                   with its own next step. EQU failure cascades to SUB-WF-UPGRADE-01 failure
                                                                   (subscription rolls back to previous tier; the equipment stays as-is).

  R-EQU-10                                                         The target instance after a successful EQU is IN_FIELD_ACTIVE bound to the
                                                                   customer's account, same as a fresh install. The customer's subscription
                                                                   package (if upgraded by SUB-WF-UPGRADE-01) catches up via separate
                                                                   provisioning steps; this flow is equipment-only.
