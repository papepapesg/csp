 Termination BPMN
 Developer implementation guide: DD_SUB-WF-TERMINATE-01-FLOW-WIK-DEV_IMPL_GUIDE-v1.0.md.


 1. Purpose
 This DD defines the WIK operator BPMN for subscription termination.

 Process key:
          sub-terminate-wik

 This BPMN implements the parent termination contract from
 DD_SUB-WF-TERMINATE-01-Subscription_Termination-v1.0.md for WIK.

 The WIK termination flow is:
          validate -> cancel in-flight operation -> PENDING_TERMINATION -> compute billing window -> settlement -> resolve equipment



 2. Ownership
 This DD owns:

   - WIK-specific termination BPMN process key.

   - WIK happy-path BPMN sequence.

   - WIK cooling-off supervisor task behavior.

   - WIK equipment disposition behavior.

   - WIK worker-topic composition.

 6. Happy Path BPMN
           Start
             -> update operation state VALIDATING
             -> drools-decide
             -> gateway: eligible?
                 no -> termination rejected path
                 yes
             -> gateway: in-flight operation exists?
                 yes -> sub-lm-cancel-in-flight-operation -> wait cancellation acknowledgement
                 no -> continue
             -> update operation state PENDING_STATE_FLIP
             -> sub-lm-put-pending-status
             -> sub-lm-compute-cycle-window
             -> update operation state BILLING_CALL
             -> bil01-emit-intent
             -> drools-decide resolve-equipment-disposition
             -> gateway: cooling-off supervisor required?
                 yes -> user task cooling-off-override-decision
                 no -> continue
             -> update operation state FULFILLMENT_CALL
             -> ful-call-terminate
             -> wait fulfillment-completed
             -> ful-call-release-homepass
             -> update operation state COMMITTING_FINAL_STATE
             -> sub-lm-put-master-fields
             -> sub-lm-commit-state
             -> update operation state EMITTING_EVENT
             -> kafka-emit SubscriptionTerminated
             -> notification-send
             -> subscription-operation-finalize COMPLETED
             -> End

 9. Drools Package
 Required package:
             rules.subscription.terminate.wik

 Required decisions:

  Decision                                                          Purpose

  validate-eligibility                                              Checks not terminated, trigger, role, and self-service config.

  compute-cooling-off-applicability                                 Computes cooling-off and active days.

  resolve-equipment-disposition                                     Resolves caller-supplied, default, dunning default, or write-off disposition.


 Example rule intent:
             rule "WIK termination rejects already terminated"
             when
               $req: TerminateRequestFact()
               $sub: SubscriptionStateFact(subscriptionId == $req.subscriptionId, statusCode == "TERMINATED")
             then
               modify($req) {
                  setEligible(false);
                  setEligibilityReasonCode("ALREADY_TERMINATED")
               }
             end

             rule "WIK customer requested termination allowed roles"
             when
               $req: TerminateRequestFact(
                  terminationTrigger == "CUSTOMER_REQUESTED",
                  eligible == null,
                  initiatingActorRole not in ("CUSTOMER_SELF_SERVICE", "CALL_CENTER", "SUBSCRIPTION_OPERATOR")
               )
             then
               modify($req) {
                  setEligible(false);
                  setEligibilityReasonCode("ROLE_NOT_AUTHORIZED_FOR_TRIGGER")
               }
             end

             rule "WIK dunning write-off disposition"
             salience 10
             when
               $req: TerminateRequestFact(terminationTrigger == "DUNNING_TERMINATION", equipmentDispositionRequested == null)
               $intent: BillingIntentDecisionFact(writeOffMarker == true)
             then
               modify($req) {
                  setEquipmentDisposition("WRITTEN_OFF")
               }
             end

  Failure point                                                     BPMN compensation

  Drools rejects request                                            Emit SubscriptionTerminationRejected; finalize FAILED.

  In-flight cancellation fails                                      Do not start termination; return OPERATION_INTERRUPTION_FAILED.

  Failure point                                                      BPMN compensation

  Pending status update fails                                        No committed mutation expected; emit rejected; finalize FAILED.

  Billing settlement fails                                           Run sub-lm-revert-to-prior; emit rejected; finalize FAILED.

  FUL-05 revoke fails before network change                          Run sub-lm-revert-to-prior; emit rejected; finalize FAILED.

  FUL-05 partial/unknown revoke                                      Manual recovery.

  HomePass release fails                                             Retry or manual recovery unless a durable release stub is accepted.

  Master fields or state commit fails                                Manual recovery.

  Kafka emit fails                                                   Outbox retries. BPMN should not mark event delivered synchronously.

  Notification fails                                                 Log and continue. Notification is reliability-isolated.




 11. Worked Example
 Kamau calls WIK Call Center to terminate because he is moving to a non-covered area.

 Request:
             POST /api/subscriptions/sub_01HZ_KAMAU_FIBER/terminate
             Idempotency-Key: term-sub_01HZ_KAMAU-20260720T143000-cc007
             Content-Type: application/json

             {
                  "operatorCode": "WIK",
                  "terminationTrigger": "CUSTOMER_REQUESTED",
                  "terminationReasonCode": "CUSTOMER_MOVED_NO_COVERAGE",
                  "equipmentDisposition": "PENDING_COLLECTION",
                  "customerNotes": "Moving to a non-covered area; no service available at new address",
                  "initiatingWorkflowKind": "BO_UI",
                  "initiatingWorkflowRef": "cc-ticket-2026-07-20-4421"
             }

 Runtime result:
             API validates request
               -> loads SUB-LM subscription summary: ACTIVE
               -> loads WIK termination config and equipment bindings
               -> Drools accepts CALL_CENTER CUSTOMER_REQUESTED termination
               -> framework creates operation subop_01HZ_KAMAU_TERM
               -> Camunda starts sub-terminate-wik
               -> subscription moves ACTIVE -> PENDING_TERMINATION
               -> billing receives TERMINATION_INTENT and computes prorated refund
               -> Drools resolves equipmentDisposition=PENDING_COLLECTION
               -> cooling-off supervisor task is skipped because subscription is past cooling-off window
               -> FUL-05 revokes service
               -> HomePass release worker releases/stubs release
               -> termination master fields are written
               -> subscription moves PENDING_TERMINATION -> TERMINATED
               -> SubscriptionTerminated event is emitted
               -> notification is sent
               -> operation is COMPLETED

 After success:

   - Subscription status is TERMINATED.

   - Customer service is revoked.

   - HomePass slot is released or has a durable release request.

   - SubscriptionTerminated includes settlement and equipment bindings.

   - OSR-RMA creates pickup work order because equipment disposition is PENDING_COLLECTION.
