 MVP simplification baseline: FUL-10 is phased after activation, payment, WO installation, OSR basics, and provisioning
 integration are stable. First implementation is admin-only cohort migration, not customer self-service cross-technology
 migration. FUL-10 calls WO only for field work and does not create a separate WO migration engine unless an operator
 process requires it.



 1. Purpose
 FUL-10 defines the fulfillment-side execution for a customer or network migration that changes the access technology used
 by an active subscription.

 Examples:

   - HFC to GPON migration;

   - GPON to HFC migration where an operator supports both access networks;

   - legacy access to fiber migration;

   - operator-driven area cutover from one network topology to another;

   - package migration that requires a different access technology or equipment profile.

 SUB-WF-MIGRATION-01 owns the subscription operation: commercial validation, target package, target HomePass, billing
 policy, customer-facing operation state, and final subscription state update. FUL-10 owns the technical fulfillment: migration
 validation against provisioning/network constraints, work-order creation, equipment plan, source technology teardown, target
 technology activation, network reconciliation, and fulfillment outcome callback.

 Use FUL-10 when:

   - source and target HomePass technologies are different;

   - the migration requires new access equipment or new network binding;

   - the subscription migration flow needs a technical cutover before it can commit;

   - an operator performs a planned technology retirement or area cutover;

   - manual force-complete, rollback, or exception repair may be needed after network provisioning.

 Procurement is related only upstream. OSR-02 replenishes stock before customer jobs start. FUL-10 must not call
 procurement during a migration. Runtime customer migrations consume equipment already available, reserved, or assigned
 through OSR/WO flows.

 Boundary rules:

   - FUL-10 does not approve the commercial migration. SUB-WF-MIGRATION-01 must start or authorize the operation.

   - FUL-10 does not directly update subscription master data. It calls back the migration outcome so SUB-WF can commit.

   - FUL-10 does not schedule technicians directly if the WO module is enabled. It creates or references a WO.

   - FUL-10 does not directly edit OSR stock or equipment instance tables. It uses OSR APIs and events.

   - FUL-10 may call FUL-09 when the migration includes an equipment replacement/swap.

   - FUL-10 may call FUL-03/PROV-INT to activate/deactivate access services.

   - EM-CFG-04 is used only for approval policies such as force-complete, forced rollback, risky serial correction, or
     non-standard cutover. Camunda is involved only when the configured approval policy mode is BPMN.



 3. Process Overview
               flowchart LR
                 A["SUB-WF migration requests technical fulfillment"] --> B["FUL-10 validates source/target technology"]
                 B --> C["Build equipment and work plan"]
                 C --> D["Create migration WO if field work required"]
                 D --> E["Technician installs target access"]
                 E --> F["FUL-10 executes source teardown and target activation"]
                 F --> G["FUL-10 reconciles BSS and network state"]
                 G --> H["FUL-10 sends outcome to SUB-WF"]
                 H --> I["SUB-WF commits subscription migration"]

 For an HFC to GPON migration:

   1. SUB-WF-MIGRATION validates the target package and target HomePass.

   2. FUL-10 validates that the target HomePass can serve the package on GPON.

   3. FUL-10 creates a WO with migration context.

   4. WO installs the ONT and captures serial, port, GPS, and evidence.

   5. FUL-10 calls provisioning to activate GPON service.

   6. FUL-10 tears down or suspends HFC service according to the cutover policy.

   7. FUL-10 reconciles network state.

   8. SUB-WF commits the subscription only after FUL-10 returns COMPLETED.

 What it is for: stores one technical fulfillment execution for a cross-technology migration.

 When to use it: create one row when SUB-WF-MIGRATION asks fulfillment to execute a migration where source and target

 shifting.

 7. Rules And Drools
 Use Drools for rules that vary by operator, region, technology, or commercial policy.

 Recommended packages:

   - rules.fulfillment.technology_migration.eligibility

   - rules.fulfillment.technology_migration.equipment

   - rules.fulfillment.technology_migration.cutover

   - rules.fulfillment.technology_migration.exception

 Example rules:
          package rules.fulfillment.technology_migration.eligibility

          rule "Reject migration when target technology does not support package services"
          when
            $f : TechnologyMigrationFact(targetSupportsAllRequiredServices == false)
            $d : TechnologyMigrationDecision()
          then
            $d.reject("TARGET_TECH_PACKAGE_INCOMPATIBLE");
          end

          package rules.fulfillment.technology_migration.cutover

          rule "HFC to GPON make-before-break"
          when
            $f : TechnologyMigrationFact(sourceTechnology == "HFC", targetTechnology == "GPON")
            $d : TechnologyMigrationDecision()
          then
            $d.setCutoverMode("MAKE_BEFORE_BREAK");
            $d.addStep("GPON_ACTIVATE_TARGET_ONT");
            $d.addStep("GPON_RECONCILE_TARGET");
            $d.addStep("HFC_SUSPEND_SOURCE_MODEM");
            $d.addStep("HFC_RECONCILE_SOURCE");
          end

          package rules.fulfillment.technology_migration.exception

          rule "Force complete requires approval when source teardown failed"
          when
            $f : TechnologyMigrationExceptionFact(exceptionType == "PROVISIONING_FAILED",
                                                 targetActivationVerified == true,
                                                 sourceTeardownVerified == false)
            $d : TechnologyMigrationExceptionDecision()

 10. Infrastructure Recommendations
 For a medium budget-conscious deployment:

   - Run FUL-10 APIs in the existing fulfillment service deployment.

   - Run FUL-10 logical workers in the shared fulfillment worker deployment; keep metrics by topic/handler.

   - Use the fulfillment PostgreSQL schema for FUL-10 tables.

   - Use the existing Kafka/outbox stack for events.

   - Use existing PROV-INT adapters for network commands; do not introduce direct NMS calls in business code.

   - Keep Camunda optional for this DD. Use it when the operator wants a visible long-running technical workflow. Use
     EM-CFG-04 for approvals regardless of whether the approval itself is simple or BPMN-backed.

 11. Test Scenarios
 Minimum tests:

   1. Start fulfillment is idempotent for the same subscription operation.

   2. Second active technology migration for same subscription returns 409.

   3. HFC to GPON validation passes when target HomePass supports package services.

   4. Validation fails when target HomePass lacks required service family.

   5. WO is created with kind=TECHNOLOGY_MIGRATION and correct origin context.

   6. Equipment plan calls FUL-09 only when equipment swap/rebind is required.

   7. Cutover executes target activation before source teardown for make-before-break policy.

   8. Reconciliation failure creates technology_migration_exception.

   9. Force-complete calls EM-CFG-04 when configured.

   10. Completed fulfillment calls SUB-WF outcome endpoint once.



 12. Implementation Notes
   - Treat FUL-10 as the missing technical satellite for cross-technology migration.

   - Keep the customer subscription active on the source technology until target activation has passed reconciliation, unless
     the operator explicitly configures break-before-make.

   - Do not update subscription package/homepass from FUL-10. SUB-WF commits after receiving the success outcome.

   - If a field visit is required, WO-01 remains the owner of assignment, technician evidence, and field finalization.

   - If equipment changes are required, FUL-10 coordinates with FUL-09 instead of duplicating equipment swap provisioning
      logic.

   - If procurement is missing stock, the operational answer is to stop before runtime fulfillment and let OSR replenishment
      happen through OSR-02. Do not insert purchase order logic into FUL-10.
