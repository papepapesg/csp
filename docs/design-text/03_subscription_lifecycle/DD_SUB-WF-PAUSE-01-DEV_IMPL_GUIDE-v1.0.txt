 2. Runtime Actors
  Runtime component                                                What it does

  subscription-workflow-api pod                                    Receives pause request, validates, starts operation.

  SUB-LM module/API                                                Provides authoritative subscription status and mutation APIs.

  BIL-01                                                           Computes pause intent and fee.

  FUL-04                                                           Suspends service/restriction fulfillment.

  Camunda                                                          Runs pause BPMN.

  Drools                                                           Validates pause policy and duration.

  Worker apps                                                      Execute BPMN service task topics.




 3. Before The Request Can Work
 Required:

   - pause_reason seeded.

   - subscription_pause_config seeded.

   - subscription_pause_history migrated.

   - subscription_operation_config has (WIK, PAUSE) -> sub-pause-wik.

   - Drools package rules.subscription.pause.wik.

   - BPMN process sub-pause-wik.

 8. Drools Rules To Configure
 8.1 Subscription Must Be ACTIVE
          rule "pause requires active subscription"
          when
               $facts : PauseFacts(subscription.statusCode != "ACTIVE")
               $decision : PauseDecision()
          then
               $decision.reject("INVALID_STATE_FOR_PAUSE", "Pause requires ACTIVE subscription.");
          end


 8.2 Role Trigger Gating
          rule "customer pause allowed roles"
          when
               $facts : PauseFacts(
                   request.pauseTrigger == "CUSTOMER_REQUESTED_PAUSE",
                   actor.role not in ("CUSTOMER_SELF_SERVICE", "CALL_CENTER", "SUBSCRIPTION_OPERATOR")
               )
               $decision : PauseDecision()
          then
               $decision.reject("ROLE_NOT_AUTHORIZED_FOR_TRIGGER", "Role cannot perform customer-requested pause.");
          end

          rule "admin pause allowed roles"
          when
               $facts : PauseFacts(
                   request.pauseTrigger == "ADMIN_PAUSE",
                   actor.role not in ("SUBSCRIPTION_ADMIN", "SUBSCRIPTION_OPERATOR")
               )
               $decision : PauseDecision()
          then
               $decision.reject("ROLE_NOT_AUTHORIZED_FOR_TRIGGER", "Role cannot perform admin pause.");
          end


 8.3 Reason Eligibility

          rule "pause reason must be active"
          when
               $facts : PauseFacts(reason == null || reason.isActive == false)
               $decision : PauseDecision()
          then
               $decision.reject("UNKNOWN_OR_INACTIVE_PAUSE_REASON", "Pause reason is unknown or inactive.");
          end

          rule "self service reason eligibility"
          when
               $facts : PauseFacts(
                   actor.role == "CUSTOMER_SELF_SERVICE",
                   reason.customerSelfServiceEligible == false
               )
               $decision : PauseDecision()
          then
               $decision.reject("PAUSE_REASON_NOT_CUSTOMER_SELF_SERVICE", "Reason cannot be used by customer self-service.");
          end


 8.4 Duration Resolution
          rule "fixed days duration"
          when
               $facts : PauseFacts(request.durationDays != null)
               $decision : PauseDecision(rejected == false)
          then
               $decision.setDurationMode("FIXED_DAYS");
               $decision.setDurationDays($facts.request.durationDays);
               $decision.setResumeScheduledAt($facts.runtime.now.plusDays($facts.request.durationDays));
          end

          rule "open ended not allowed"
          when
               $facts : PauseFacts(
                   request.openEnded == true,
                   reason.openEndedAllowed == false
               )
               $decision : PauseDecision()
          then
               $decision.reject("OPEN_ENDED_NOT_ALLOWED_FOR_REASON", "Open-ended pause is not allowed for this reason.");
          end

          rule "duration exceeds reason max"
          when
               $facts : PauseFacts(
                   request.durationDays != null,
                   reason.maxDurationDays != null,
                   request.durationDays > reason.maxDurationDays
               )
               $decision : PauseDecision()
          then
               $decision.reject("DURATION_EXCEEDS_REASON_MAX", "Requested duration exceeds reason maximum.");
          end



 9. Step 5 - API Starts Operation
 After API validation and Drools approval, the pause API asks the shared SUB-WF framework to create the operation and start
 Camunda.

 If Pause and the framework are in the same application, this is an in-process method call, for example:
          OperationStartService.start(StartOperationCommand command)

 If the framework is deployed as a separate service, this can be an internal HTTP call, for example:
          POST /internal/subscription-operations/start
          Authorization: Bearer <subscription-workflow-service-token>

 The payload below is the command/request body passed to that framework start contract. It is not the public customer/admin
 pause API request.

 11. Step 7 - BPMN Executes Worker Topics
  Order                                          BPMN service task does this                              Worker topic/message

  1                                              Validate/route policy.                                   drools-decide

  2                                              Put subscription in pending pause.                       sub-lm-put-pending-status

  3                                              Compute cycle window.                                    sub-lm-compute-cycle-window

  4                                              Ask billing for pause intent.                            bil01-emit-intent

  5                                              Optional pay-first fee.                                  bil01-charge-pre-authorize then
                                                                                                          payment-confirmed then
                                                                                                          bil01-confirm-charge

  6                                              Suspend service.                                         ful-call-restrict

  7                                              Wait for fulfillment result.                             fulfillment-completed or
                                                                                                          fulfillment-failed

  8                                              Clear active restrictions.                               sub-lm-put-active-restrictions

  9                                              Insert pause history row.                                sub-lm-put-master-fields

  10                                             Commit subscription suspended.                           sub-lm-commit-state

  11                                             Emit pause event.                                        kafka-emit

  12                                             Notify customer.                                         notification-send

  13                                             Finalize operation.                                      subscription-operation-finalize

 14. Manual Smoke Test
   1. Seed pause_reason.

   2. Seed subscription_pause_config.

   3. Seed operation config (WIK, PAUSE).

   4. Create active subscription.

   5. Send pause API request.

   6. Confirm operation row exists.

   7. Confirm BPMN process exists.

   8. Confirm subscription moves to PENDING_PAUSE.

   9. Simulate fulfillment completed.

   10. Confirm pause history row inserted.

   11. Confirm subscription becomes SUSPENDED.

   12. Confirm SubscriptionPaused outbox row exists.

   13. Confirm operation final state is COMPLETED.


 15. Common Mistakes
   - Treating pause and SUSPEND-NP as identical.

   - Not snapshotting pause reason.

   - Allowing multiple open pause rows.

   - Letting customer self-service use admin-only reasons.

   - Emitting success before SUB-LM commits SUSPENDED.

   - Forgetting scheduled resume scanner dependency.
