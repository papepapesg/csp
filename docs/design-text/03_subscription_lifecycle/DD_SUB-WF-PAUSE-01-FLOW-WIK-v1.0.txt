 DD_SUB-WF-PAUSE-01-FLOW-WIK - WIK Pause BPMN
 Developer implementation guide: DD_SUB-WF-PAUSE-01-FLOW-WIK-DEV_IMPL_GUIDE-v1.0.md.


 1. Purpose
 This DD defines the WIK operator BPMN for voluntary subscription pause.

 Process key:
          sub-pause-wik

 This BPMN implements the parent pause contract from DD_SUB-WF-PAUSE-01-Subscription_Pause-v1.0.md for
 WIK.

 The WIK pause flow is normally no-fee in v1.0:
          validate -> PENDING_PAUSE -> compute billing window -> emit billing intent -> optional fee payment -> suspend service -> c

 The optional pay-first gate exists in the BPMN, but it is dormant for the seeded WIK v1.0 pause reasons because no seeded
 reason has a pause fee.

 3.3 WIK Pause Reasons
 What this table is for:

 pause_reason is the pause reason catalog. It defines which reasons customers can use, which reasons are admin-only,
 duration bounds, billing impact, and whether network service must be suspended.

 When to use it:

 Load the requested reason before Drools validation, snapshot it into the operation variables, and store the snapshot in
 subscription_pause_history after the pause succeeds.

 Required seed data:

  code                customer_self_s    admin_only               max_duration_da       open_ended_allo    pauses_bill_cyc         suspends_fulfil
                      ervice_eligible                             ys                    wed                le                      lment

  CUSTOMER_VACATI     TRUE               FALSE                    90                    FALSE              TRUE                    TRUE
  ON

  CUSTOMER_TEMPOR     TRUE               FALSE                    30                    FALSE              TRUE                    TRUE
  ARY_AWAY

  CUSTOMER_FINANC     FALSE              FALSE                    60                    FALSE              TRUE                    TRUE

 Sample row meaning:

 to 90 days. The pause stops bill-cycle accrual and suspends network service.

 5. Worker Topics Used
 These are logical Camunda external-task topics, not separate deployments. One worker app may subscribe to many topics,
 but logs, retries, metrics, and contracts must remain visible per topic.

  Worker topic                                                       Why WIK pause uses it

  drools-decide                                                      Re-check pause policy, reason, role, active status, and duration.

  sub-lm-put-pending-status                                          Move subscription to PENDING_PAUSE.

  sub-lm-compute-cycle-window                                        Compute billing-cycle context for BIL-01.

  bil01-emit-intent                                                  Ask BIL-01 to evaluate PAUSE_INTENT.

  bil01-charge-pre-authorize                                         Optional payment gate when pause fee applies.

  bil01-confirm-charge                                               Optional confirmation after payment message.

  ful-call-restrict                                                  Ask FUL-04 to suspend service using SUSPEND_SERVICE.

  sub-lm-put-active-restrictions                                     Clear active restrictions after service suspension.

  sub-lm-put-master-fields                                           Write status audit fields and pause-history row.

  sub-lm-commit-state                                                Commit subscription to SUSPENDED.

  kafka-emit                                                         Write pause success/failure event to outbox.

  notification-send                                                  Send pause notification without failing BPMN on notification failure.

  subscription-operation-finalize                                    Set operation terminal state.

  bil01-revert-pending-charge                                        Compensation for pending pause fee charge.

  sub-lm-revert-to-prior                                             Compensation to return subscription to ACTIVE.




 6. Happy Path BPMN
             Start
               -> update operation state VALIDATING
               -> drools-decide
               -> gateway: eligible and duration valid?
                   no -> pause rejected path
                   yes
               -> update operation state PENDING_STATE_FLIP
               -> sub-lm-put-pending-status
               -> sub-lm-compute-cycle-window
               -> update operation state BILLING_CALL
               -> bil01-emit-intent
               -> gateway: pauseFeeApplicable?
                   yes -> bil01-charge-pre-authorize -> wait payment-confirmed -> bil01-confirm-charge
                   no -> continue
               -> update operation state FULFILLMENT_CALL
               -> ful-call-restrict
               -> update operation state AWAITING_FULFILLMENT_RESPONSE
               -> wait fulfillment-completed
               -> sub-lm-put-active-restrictions CLEAR_ALL
               -> update operation state COMMITTING_FINAL_STATE
               -> sub-lm-put-master-fields
               -> sub-lm-commit-state
               -> update operation state EMITTING_EVENT
               -> kafka-emit SubscriptionPaused
               -> notification-send
               -> subscription-operation-finalize COMPLETED
               -> End

 For WIK seeded v1.0 reasons this is normally false, so BPMN skips:

 9. Drools Package
 Required package:
              rules.subscription.pause.wik

 Required decisions:

  Decision                                                         Purpose

  validate-preconditions                                           Checks subscription status, open pause, trigger, role, and reason eligibility.

  resolve-duration-mode                                            Resolves fixed-day, scheduled-time, or open-ended pause and validates
                                                                   bounds.

  compute-pause-fee-applicability                                  Decides whether the optional payment gate runs.


 Example rule intent:
              rule "WIK pause requires active subscription"
              when
                $req: PauseRequestFact()
                $sub: SubscriptionStateFact(subscriptionId == $req.subscriptionId, statusCode != "ACTIVE")
              then
                modify($req) {
                   setEligible(false);
                   setEligibilityReasonCode("INVALID_STATE_FOR_PAUSE")
                }
              end

              rule "WIK customer self-service cannot use admin-only reason"
              when
                $req: PauseRequestFact(initiatingActorRole == "CUSTOMER_SELF_SERVICE", eligible == null)
                $reason: PauseReasonFact(code == $req.pauseReasonCode, adminOnly == true)
              then
                modify($req) {
                   setEligible(false);
                   setEligibilityReasonCode("ADMIN_ONLY_PAUSE_REASON")
                }
              end

              rule "WIK fixed days duration within bounds"
              when
                $req: PauseRequestFact(durationDays != null, durationValid == null)
                $reason: PauseReasonFact(code == $req.pauseReasonCode)
                $cfg: OperatorConfigFact()
                eval($req.getDurationDays() * 24 >= $cfg.getMinPauseHours()
                      && ($reason.getMaxDurationDays() == null || $req.getDurationDays() <= $reason.getMaxDurationDays())
                      && $req.getDurationDays() <= $cfg.getMaxFutureScheduledResumeDays())
              then
                java.time.Instant resumeAt = java.time.Instant.now().plusSeconds($req.getDurationDays() * 86400L);
                modify($req) {
                   setDurationMode("FIXED_DAYS");
                   setResumeScheduledAt(resumeAt.toString());
                   setDurationValid(true)
                }
              end



 10. Compensation Paths
  Failure point                                                    BPMN compensation

  Drools rejects request                                           Emit SubscriptionPauseRejected; finalize FAILED.

  Pending status update fails                                      No committed mutation expected; emit rejected; finalize FAILED.

  Billing intent fails                                             Run sub-lm-revert-to-prior; emit rejected; finalize FAILED.

  Payment timeout                                                  Run bil01-revert-pending-charge; run sub-lm-revert-to-prior;
                                                                   emit rejected; finalize FAILED.

 11. Worked Example
 Kamau calls the WIK call center and asks to pause fiber service for 31 days while travelling.

 Request:
             POST /api/subscriptions/sub_01HZ_KAMAU_FIBER/pause
             Idempotency-Key: pause-sub_01HZ_KAMAU-vacation-20260315
             Content-Type: application/json

             {
                  "operatorCode": "WIK",
                  "pauseTrigger": "CUSTOMER_REQUESTED_PAUSE",
                  "pauseReasonCode": "CUSTOMER_VACATION",
                  "durationDays": 31,
                  "notes": "Customer travelling to Mombasa for holiday season",
                  "initiatingWorkflowKind": "BO_UI",
                  "initiatingWorkflowRef": "cc-ticket-2026-03-15-3301"
             }

 Runtime result:
             API validates request
               -> loads SUB-LM subscription summary: ACTIVE
               -> loads WIK pause config and CUSTOMER_VACATION reason
               -> Drools resolves FIXED_DAYS and resumeScheduledAt
               -> framework creates operation subop_01HZ_KAMAU_PAUSE
               -> Camunda starts sub-pause-wik
               -> subscription moves ACTIVE -> PENDING_PAUSE
               -> billing receives PAUSE_INTENT and returns no fee
               -> FUL-04 suspends service
               -> pause history row is inserted
               -> subscription moves PENDING_PAUSE -> SUSPENDED
               -> SubscriptionPaused event is emitted
               -> notification is sent
               -> operation is COMPLETED

 After success:

   - Subscription status is SUSPENDED.

   - Customer service is suspended.

   - subscription_pause_history.actual_resume_at remains NULL.

   - Scheduler can later call RESUME with SCHEDULED_AUTO_RESUME when resume_scheduled_at arrives.
