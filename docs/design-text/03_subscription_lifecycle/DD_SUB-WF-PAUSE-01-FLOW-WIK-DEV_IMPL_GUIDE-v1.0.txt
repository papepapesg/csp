 DEV_IMPL_GUIDE - SUB-WF-PAUSE-01-FLOW-WIK
 1. Purpose
 This guide explains how to implement and test the WIK pause BPMN as the flow executes at runtime.

 Use it with:

   - DD_SUB-WF-PAUSE-01-FLOW-WIK-v1.0.md

   - DD_SUB-WF-PAUSE-01-Subscription_Pause-v1.0.md

   - DD_SUB-WF-FRAMEWORK-01-Subscription_Workflow_Framework-v1.0.md

   - DD_SUB-WF-FRAMEWORK-01-WORKERS-v1.0.md

 This guide is specific to the BPMN process file:
            sub-pause-wik.bpmn



 2. Runtime Actors
  Runtime component                                              Role in this flow

  subscription-workflow-api pod                                  Receives WIK pause request and calls the shared operation framework.

  SUB-LM service/module                                          Provides authoritative subscription summary and status mutation APIs.

  Pause workflow persistence                                     Owns pause reason/config/history reads and writes, unless implemented inside
                                                                 the same module as SUB-LM.

  Drools                                                         Evaluates rules.subscription.pause.wik.

  Camunda                                                        Runs process sub-pause-wik.

  Worker apps                                                    Execute external task topics from the BPMN. One app can handle many topics.

  BIL-01                                                         Evaluates PAUSE_INTENT and optional pause fee.

  FUL-04                                                         Suspends service.

  Message correlators                                            Correlate payment and fulfillment messages back to Camunda.

  NOT-01                                                         Sends customer notification after success.

 5. Step 2 - API Pod Validates Shape And Idempotency
 The subscription-workflow-api pod validates:

  Field                                                          Validation

  operatorCode                                                   Required and must be WIK for this BPMN.

  pauseTrigger                                                   CUSTOMER_REQUESTED_PAUSE or ADMIN_PAUSE.

  pauseReasonCode                                                Required.

  openEnded, durationDays, resumeScheduledAt                     At most one mode selector supplied.

  durationDays                                                   Positive integer when supplied.

  resumeScheduledAt                                              Future timestamp when supplied.


 Idempotency behavior:

   - First request inserts the operation and starts BPMN.

   - Same Idempotency-Key with same request hash returns the existing operation response.

   - Same Idempotency-Key with a different request hash must return 409 IDEMPOTENCY_KEY_REUSED.

 Implementation note:

 Do not insert a new operation before checking existing key and request hash. Use a transaction or unique constraint on the
 idempotency key plus operator/operation scope so concurrent duplicate requests cannot create two operations.

 8. Drools Rules To Configure
 8.1 Active Subscription
          rule "WIK pause requires ACTIVE subscription"
          when
            $req: PauseRequestFact()
            $sub: SubscriptionStateFact(subscriptionId == $req.subscriptionId, statusCode != "ACTIVE")
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("INVALID_STATE_FOR_PAUSE")
            }
          end


 8.2 No Open Pause
          rule "WIK pause requires no open pause history"
          when
            $req: PauseRequestFact(eligible == null)
            exists (PauseHistoryFact(subscriptionId == $req.subscriptionId, actualResumeAt == null))
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("ALREADY_PAUSED")
            }
          end


 8.3 Trigger Role Gating
          rule "WIK customer requested pause allowed roles"
          when
            $req: PauseRequestFact(
               pauseTrigger == "CUSTOMER_REQUESTED_PAUSE",
               eligible == null,
               initiatingActorRole not in ("CUSTOMER_SELF_SERVICE", "CALL_CENTER", "SUBSCRIPTION_OPERATOR")
            )
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("ROLE_NOT_AUTHORIZED_FOR_TRIGGER")
            }
          end

          rule "WIK admin pause allowed roles"


SOPHIX BSS Design Documents                                                                                   Page 4
          when
            $req: PauseRequestFact(
               pauseTrigger == "ADMIN_PAUSE",
               eligible == null,
               initiatingActorRole not in ("SUBSCRIPTION_ADMIN", "SUBSCRIPTION_OPERATOR")
            )
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("ROLE_NOT_AUTHORIZED_FOR_TRIGGER")
            }
          end


 8.4 Reason Eligibility
          rule "WIK pause reason must exist and be active"
          when
            $req: PauseRequestFact(eligible == null)
            not (PauseReasonFact(code == $req.pauseReasonCode, isActive == true))
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("UNKNOWN_OR_INACTIVE_PAUSE_REASON")
            }
          end

          rule "WIK customer self-service cannot use admin-only reason"
          when
            $req: PauseRequestFact(initiatingActorRole == "CUSTOMER_SELF_SERVICE", eligible == null)
            $reason: PauseReasonFact(code == $req.pauseReasonCode, adminOnly == true)
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("ADMIN_ONLY_PAUSE_REASON")
            }
          end

          rule "WIK customer self-service requires eligible reason"
          when
            $req: PauseRequestFact(initiatingActorRole == "CUSTOMER_SELF_SERVICE", eligible == null)
            $reason: PauseReasonFact(code == $req.pauseReasonCode, customerSelfServiceEligible == false, adminOnly == false)
          then
            modify($req) {
               setEligible(false);
               setEligibilityReasonCode("PAUSE_REASON_NOT_CUSTOMER_SELF_SERVICE")
            }
          end


 8.5 Duration Resolution
          rule "WIK fixed days duration within bounds"
          when
            $req: PauseRequestFact(durationDays != null, durationValid == null)
            $reason: PauseReasonFact(code == $req.pauseReasonCode)
            $cfg: OperatorConfigFact()
            eval($req.getDurationDays() * 24 >= $cfg.getMinPauseHours()
                  && ($reason.getMaxDurationDays() == null || $req.getDurationDays() <= $reason.getMaxDurationDays())
                  && $req.getDurationDays() <= $cfg.getMaxFutureScheduledResumeDays())
          then
            java.time.Instant resumeAt = java.time.Instant.now().plusSeconds($req.getDurationDays() * 86400L);
            modify($req) {
               setDurationMode("FIXED_DAYS");
               setResumeScheduledAt(resumeAt.toString());
               setDurationValid(true)
            }
          end

          rule "WIK fixed days duration out of bounds"
          when
            $req: PauseRequestFact(durationDays != null, durationValid == null)
            $reason: PauseReasonFact(code == $req.pauseReasonCode)
            $cfg: OperatorConfigFact()
            eval(!($req.getDurationDays() * 24 >= $cfg.getMinPauseHours()
                    && ($reason.getMaxDurationDays() == null || $req.getDurationDays() <= $reason.getMaxDurationDays())
                    && $req.getDurationDays() <= $cfg.getMaxFutureScheduledResumeDays()))
          then
            modify($req) {
               setDurationValid(false);
               setDurationReasonCode("DURATION_OUT_OF_BOUNDS")
            }
          end




SOPHIX BSS Design Documents                                                                                             Page 5
 8.6 Fee Applicability
          rule "WIK pause fee applies when customer reason has default fee"
          when
            $req: PauseRequestFact(pauseTrigger == "CUSTOMER_REQUESTED_PAUSE")
            $reason: PauseReasonFact(code == $req.pauseReasonCode, defaultFeeBillableEventCode != null)
          then
            modify($req) {
               setPauseFeeApplicable(true)
            }
          end

          rule "WIK pause fee default false"
          salience -100
          when
            $req: PauseRequestFact(pauseFeeApplicable == null)
          then
            modify($req) {
               setPauseFeeApplicable(false)
            }
          end

 14. Step 10 - BPMN Evaluates Optional Payment Gateway
 Gateway condition:
          ${pauseFeeApplicable == true}

 For WIK v1.0 seeded reasons:
          pauseFeeApplicable == false

 So the BPMN skips payment and continues to fulfillment.

 If a future reason has a fee, the BPMN runs:
          bil01-charge-pre-authorize
          wait payment-confirmed with boundary timer P7D
          bil01-confirm-charge

 Payment timeout route:
          bil01-revert-pending-charge
          sub-lm-revert-to-prior
          kafka-emit SubscriptionPauseRejected
          subscription-operation-finalize FAILED

 These names are worker topics or BPMN message names, not shell commands.

 23. Compensation Flow Details
 23.1 Drools Rejection
 No mutation should have happened yet.

 Flow:
           kafka-emit SubscriptionPauseRejected
           subscription-operation-finalize FAILED


 23.2 Billing Or Payment Failure
 If billing intent fails before a charge exists:
           sub-lm-revert-to-prior
           kafka-emit SubscriptionPauseRejected
           subscription-operation-finalize FAILED

 If a fee charge exists or payment times out:
           bil01-revert-pending-charge
           sub-lm-revert-to-prior
           kafka-emit SubscriptionPauseRejected
           subscription-operation-finalize FAILED


 23.3 Fulfillment Failure
 If FUL-04 returns fulfillment-failed:
           bil01-revert-pending-charge if billableEventId exists
           sub-lm-revert-to-prior
           kafka-emit SubscriptionPauseRejected
           subscription-operation-finalize FAILED


 23.4 Commit Failure After Network Suspension
 If pause history write or sub-lm-commit-state repeatedly fails, route to manual recovery.

 Reason:

 The network may already be suspended. Automatic rollback can be unsafe because the workflow may not know whether
 downstream suspension fully completed.

 25. Common Mistakes
   - Treating worker-topic names as shell commands.

   - Removing the optional payment gate because WIK v1.0 has no fee.

   - Reading current subscription status from cache.

   - Letting customer self-service use admin-only reasons.

   - Forgetting the open pause check.

   - Not snapshotting the pause reason into history.

   - Emitting SubscriptionPaused before sub-lm-commit-state.

   - Failing the whole operation because NOT-01 notification failed.

   - Assuming scheduled resume works before RESUME supports SCHEDULED_AUTO_RESUME.
