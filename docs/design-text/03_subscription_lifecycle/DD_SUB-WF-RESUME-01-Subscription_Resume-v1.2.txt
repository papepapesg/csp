 DD_SUB-WF-RESUME-01 - Subscription Resume
 Developer implementation guide: DD_SUB-WF-RESUME-01-DEV_IMPL_GUIDE-v1.2.md.


 1. Purpose
 SUB-WF-RESUME-01 defines how a suspended subscription is restored to active service.

 Resume moves a subscription from:
           SUSPENDED -> ACTIVE

 The technical saga uses a transient status:
           SUSPENDED -> PENDING_RESUME -> ACTIVE

 Use this operation when:

   - A customer asks to resume a voluntary pause.

   - A call-center user resumes a customer pause.

   - A BO admin force-resumes any suspension.

   - BIL-04 resumes after non-payment debt is cleared.

   - The scheduler auto-resumes a fixed-duration or scheduled pause.


 2. What Resume Closes
 Resume closes an open row in subscription_pause_history.

 An open row is:
           actual_resume_at IS NULL

 Resume updates the row with:

   - actual_resume_at

   - resume_reason_code

   - resume_actor_user_id

   - resume_actor_role

   - reconnection_fee_billable_event_id, when a reconnection fee applies

   - admin-force audit fields, when ADMIN_FORCE_RESUME is used

 The open row tells resume why the subscription is suspended. That value is called origin_intent.

 Resume is not a standalone service.

   - Resume route/controller in SUB-WF API.

   - Resume config migration.

   - Resume BPMN, such as sub-resume-wik.

 7. Data Model
 7.1 subscription_resume_config
 What this table is for:

 subscription_resume_config stores operator-level resume behavior. It controls customer self-service, whether
 customer resumes require a reconnection fee, whether dunning resume re-checks debt with billing, and whether success
 notification is enabled.

 Use this table when:

   - Validating CUSTOMER_SELF_SERVICE resume.

   - Deciding whether CUSTOMER_REQUESTED_RESUME may charge reconnection fee.

   - Deciding whether DUNNING_RESUME should ask BIL-01 to re-check debt.

   - Deciding whether BPMN should call notification-send.

 Do not use this table for:

   - Per-customer debt balance.

   - Current subscription state.

   - Pause reason eligibility.

   - Network provisioning decisions.
           CREATE TABLE subscription_resume_config (
              operator_code                        TEXT PRIMARY KEY,
              customer_self_service_enabled        BOOLEAN NOT NULL DEFAULT FALSE,
              reconnection_fee_on_customer_resume  BOOLEAN NOT NULL DEFAULT FALSE,
              dunning_resume_verify_debt_cleared   BOOLEAN NOT NULL DEFAULT TRUE,
              customer_notification_enabled        BOOLEAN NOT NULL DEFAULT TRUE,
              updated_at                           TIMESTAMPTZ NOT NULL DEFAULT NOW(),
              updated_by                           TEXT NOT NULL
           );

 Column descriptions:

  Column                                                                     Purpose

  operator_code                                                              Operator this config applies to.

  customer_self_service_enabled                                              Allows customer portal/app to start CUSTOMER_REQUESTED_RESUME.

  reconnection_fee_on_customer_resume                                        Enables pay-first reconnection fee for customer-triggered resume.

  dunning_resume_verify_debt_cleared                                         Adds BIL-01 debt-cleared verification for DUNNING_RESUME.

  customer_notification_enabled                                              Enables customer notification after successful resume.

  updated_at                                                                 Last update timestamp.

  updated_by                                                                 User/service that last updated the row.

 7.2 subscription_pause_history Close-Out Fields
 What this data is for:

 Resume uses the open pause-history row as the business source for why the subscription is suspended. Resume then closes
 that row after network reactivation and state commit succeed.

 Use this data when:

   - Validating origin-intent gating.

   - Showing support why a resume is blocked.

   - Closing the suspension period.

   - Auditing admin force resume.

   - Letting BIL-02 compute cycle accrual after resume.

 Resume reads these fields before starting:

  Column                                           Purpose                                              Sample

  pause_id                                         Row to close.                                        pause_01HZ_KAMAU_SUSPNP

  subscription_id                                  Suspended subscription.                              sub_01HZ_KAMAU_FIBER

  origin_intent                                    Why suspension exists.                               SUSPEND_NP

  system_managed                                   Whether suspension was system-managed.               true

  resume_scheduled_at                              Scheduler resume time, if any.                       2026-04-15T10:00:00Z

  suspended_at                                     When suspension started.                             2026-06-15T02:00:18Z

  actual_resume_at                                 Must be NULL before resume.                          NULL

  dunning_cycle_reference                          Billing dunning reference, if non-payment            bil04-dunning-wave-2026-06-15-L3
                                                   suspension.

  outstanding_debt_amount                          Debt snapshot at suspension time.                    3500.00

 8. Business Rules
 8.1 State Rules
  Rule                                                       Description

  R-RESUME-S-1                                               Resume requires subscription status SUSPENDED. Other statuses return 409
                                                             INVALID_STATE_FOR_RESUME.

  R-RESUME-S-2                                               Transition is SUSPENDED -> PENDING_RESUME -> ACTIVE.

  R-RESUME-S-3                                               Resume is mutually exclusive with other state-changing operations on the same
                                                             subscription.

  R-RESUME-S-4                                               During PENDING_RESUME, current_transition_type = RESUME and
                                                             current_transition_reason_code = resumeTrigger.



 8.2 Trigger Rules
  Rule                                                       Description

  R-RESUME-T-1                                               Trigger must be one of the four values in section 5.

  R-RESUME-T-2                                               Actor role must match the trigger role set.

  R-RESUME-T-3                                               CUSTOMER_SELF_SERVICE requires operator config enabled.

  R-RESUME-T-4                                               SCHEDULED_AUTO_RESUME requires an open row with
                                                             resume_scheduled_at IS NOT NULL.



 8.3 Origin-Intent Rules
  Rule                                                       Description

  R-RESUME-OI-1                                              Resume must read the open pause-history row before starting BPMN.

  R-RESUME-OI-2                                              No open row returns 409 NO_OPEN_PAUSE_HISTORY.

  R-RESUME-OI-3                                              Trigger and origin_intent must match the matrix in section 6.

  R-RESUME-OI-4                                              ADMIN_FORCE_RESUME on SUSPEND_NP preserves origin_intent =
                                                             SUSPEND_NP and writes admin-force audit fields.



 8.4 Billing Rules
  Rule                                                       Description

  R-RESUME-B-1                                               BPMN sends RESUME_INTENT for customer/admin resume and
                                                             RESUME_NP_INTENT for dunning resume.

  R-RESUME-B-2                                               If reconnection_fee_on_customer_resume = true and trigger is
                                                             CUSTOMER_REQUESTED_RESUME, BPMN waits for reconnection fee payment.

  R-RESUME-B-3                                               If dunning_resume_verify_debt_cleared = true, DUNNING_RESUME
                                                             asks BIL-01 to confirm debt is cleared.

  R-RESUME-B-4                                               ADMIN_FORCE_RESUME normally has no fee, but still sends billing intent for
                                                             audit and cycle handling.



 8.5 Restrictions And Cycle Rules
  Rule                                                       Description

  R-RESUME-RC-1                                              Restrictions are not automatically reapplied on resume. If needed, call
                                                             RESTRICT after resume.

  R-RESUME-RC-2                                              Cycle anchor and cycle model are unchanged by resume.

  R-RESUME-RC-3                                              BIL-02 resumes cycle accrual from the SubscriptionResumed event.

 12. Drools Package

             rules.subscription.resume.<operator>

 For WIK:
             rules.subscription.resume.wik

 Required decisions:

  Decision                                                         Purpose

  validate-preconditions                                           Status suspended, open pause row exists, no in-flight operation.

  validate-trigger-role                                            Trigger and actor role are compatible.

  validate-origin-intent                                           Trigger is allowed for the open pause row's origin_intent.

  compute-resume-billing-intent                                    Chooses RESUME_INTENT or RESUME_NP_INTENT and fee/debt checks.




 13. Auth
 Rules:

   - Resolve actor from token, not request body.

   - Customer self-service requires operator config enabled.

   - Dunning resume requires a BIL-04 service account.

   - Scheduled auto-resume requires a scheduler service account.

   - Admin force resume requires admin/operator role and a reason note.
