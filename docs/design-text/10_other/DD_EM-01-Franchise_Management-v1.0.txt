 1. Purpose
 This DD defines the Franchise Management process for SOPHIX BSS.

 EM-01 is the business source of truth for commercial franchises: who the franchise is, where it operates, what commercial
 scope it has, whether it is active, and how other modules resolve a customer, HomePass, sale, ticket, or report to a franchise.

 The goal is not just to store a list of franchises. The goal is to make franchise context consistent across:

   - HomePass and serviceability;

   - outdoor sales assignment;

   - backoffice filters and user scope;

   - order and subscription attribution;

   - billing and reporting segmentation;

   - contractor/franchise staff identity;

   - future campaigns, discounts, and commissions.

 Kenya/WIK is the first deployment. The design must also support future operators where franchises may be called zones,
 branches, regions, dealers, partners, territories, or commercial areas.

 Use EM-01 when the system needs to answer questions like:

 5. Core Concepts
  Concept                                                                       Meaning

  Operator                                                                      The deployed company/tenant, for example WIK.

  Franchise                                                                     Commercial/operational area or partner scope used for sales, reporting,
                                                                                supervision, and sometimes installation/support ownership.

  Franchise type                                                                Deployment-configured category such as INTERNAL, EXTERNAL_PARTNER,
                                                                                B2C, B2B, MIXED, DIRECT_BRANCH.

  Boundary                                                                      Optional GeoJSON polygon or metadata describing the franchise commercial
                                                                                footprint.

  HomePass assignment                                                           Link between a HomePass and one or more franchises allowed to sell or
                                                                                support it.

  Primary franchise                                                             The default franchise used when only one commercial attribution can be stored.

  Secondary franchise                                                           Additional franchise in overlap areas, B2B/B2C dual coverage, or transition
                                                                                periods.

  Franchise lifecycle                                                           Draft/active/suspended/retired state of the franchise.

 8. Franchise Lifecycle
  Status                                   Meaning                                                Allowed next statuses

  DRAFT                                    Franchise is being configured. It cannot receive new   ACTIVE, RETIRED
                                           sales or HomePass assignments in production
                                           flows.

  ACTIVE                                   Franchise can be used by sales, HomePass, order        SUSPENDED, RETIRED
                                           attribution, and reporting.

  SUSPENDED                                Franchise remains visible historically but cannot      ACTIVE, RETIRED
                                           receive new sales or assignments. Existing
                                           orders/subscriptions remain linked.

  RETIRED                                  Franchise is no longer used for new activity.          terminal
                                           Historical links remain readable.


 Rules:

  Rule                                                                  Description

  EM01-LC-1                                                             Only ACTIVE franchises can receive new HomePass assignments.

  EM01-LC-2                                                             Only ACTIVE franchises can be selected during lead conversion/order
                                                                        attribution.

  EM01-LC-3                                                             SUSPENDED franchises remain visible in reports and historical customer/order
                                                                        data.

  EM01-LC-4                                                             Retiring a franchise requires confirmation that no active HomePass assignment,
                                                                        open lead, pending order, or open WO still depends on it, unless an approved
                                                                        migration plan exists.

  EM01-LC-5                                                             Status changes must create a lifecycle event and emit a Kafka event through
                                                                        outbox.

 11. Business Rules
  Rule                                                              Description

  EM01-R-1                                                          Franchise code is immutable after activation unless an approved migration
                                                                    correction is run.

  EM01-R-2                                                          New sales/order attribution can only use ACTIVE franchises.

  EM01-R-3                                                          Historical orders/subscriptions/tickets must keep their original franchise
                                                                    snapshot even if the franchise is renamed later.

  EM01-R-4                                                          A HomePass must not be assigned to a retired franchise.

  EM01-R-5                                                          A HomePass can have multiple franchise assignments only when overlap is
                                                                    explicitly configured.

  EM01-R-6                                                          Only one active PRIMARY assignment is allowed for the same HomePass and
                                                                    commercial segment.

  EM01-R-7                                                          Suspending a franchise blocks new leads and new order conversions but does
                                                                    not cancel existing subscriptions.

  EM01-R-8                                                          Retiring a franchise requires either zero active dependencies or a migration
                                                                    plan approved by the configured approval workflow.

  EM01-R-9                                                          EM-01 must publish changes through outbox so RLM, SALES, REP, and
                                                                    frontend caches can refresh.

  EM01-R-10                                                         No module should hardcode franchise names like Nairobi 002; use
                                                                    franchise_id or franchise_code.

 15. Developer Implementation Notes
 Implementation should be straightforward if built as a CRUD/read-model module with event publishing.

 Recommended sequence:

   1. Create the em schema tables for franchise, boundary, HomePass assignment, external refs, contacts, and lifecycle
     events.

   2. Implement repositories and service methods with operator-scoped uniqueness checks.

   3. Implement create/read/update/lifecycle APIs.

   4. Implement HomePass assignment APIs; validate homepass_id through RLM-CFG-01 API, not direct DB joins.

   5. Implement franchise resolution service:

   - first by active HomePass assignment;

   - then by active boundary match if GIS/PostGIS is enabled;

   - then by sales territory if SALES-01 provides a territory context;

   - otherwise return UNRESOLVED with warnings.

   6. Add outbox events for every lifecycle and assignment change.

   7. Add cache/read model for low-latency franchise scope lookup.

   8. Patch SALES-01 and frontend docs to reference EM-01 after review.

 Do not implement franchise resolution by querying RLM or SALES database tables directly. Use approved internal API
 clients.
