 1. Purpose
 SIP-05 defines promotional campaign lifecycle, eligibility, targeting, channel governance, and campaign-driven discount
 assignment.

 A campaign is a time-bound commercial program with a goal, target population, offer terms, channels, limits, approvals, and
 reporting attribution.

 Examples:

   - acquisition campaign for new customers in Nairobi franchise territories;

   - retention campaign for customers at churn risk;

   - upsell campaign from Fiber 50M to Fiber 100M;

   - win-back campaign for recently terminated customers;

   - recovery campaign for customers suspended due to non-payment;

   - seasonal promotion with free installation discount;

   - campaign limited to door-to-door sales app and selected franchises.

 SIP-05 does not define discount amounts; PLM-CFG-04 does. SIP-05 does not create invoice discounts directly; SIP-03
 creates assignment records and DIS-OP/BIL applies them at runtime.

 created. It does not apply money to invoices or wallets.

 Approval rule: SIP-05 does not define approval steps locally. Campaign launch approval should call EM-CFG-04 for action
 codes such as CAMPAIGN_LAUNCH_APPROVAL. Camunda is used only when the selected EM-CFG-04 policy is
 BPMN-backed.



 3. Campaign Types
  Campaign type                                                             Use

  ACQUISITION                                                               New customer acquisition, often via sales app/franchise.

 10. Rule Engine Guidance
 Use Drools for campaign eligibility because campaign targeting changes often and combines many facts.

  Rule file                                                              Purpose

  campaign-eligibility.drl                                               Evaluate campaign target rules by channel, franchise, territory, package,
                                                                         bundle, lead/customer state, payment state, date, and caps.

  campaign-redemption.drl                                                Decide whether redemption is allowed and which offer should create SIP-03
                                                                         assignments.

  campaign-approval.drl                                                  Decide whether campaign launch requires EM-CFG-04 approval based on
                                                                         budget, type, channel, and discount value.


 Fixed checks such as campaign code uniqueness, date parsing, and idempotency remain application validation.

 Example rule:
              rule "Sales acquisition campaign requires matching franchise and package"
              when
                $c : CampaignEligibilityFact(campaignType == "ACQUISITION", channelCode == "SALES_APP")
                $ctx : CampaignContextFact(franchiseAllowed == true, packageAllowed == true, capReached == false)
                $out : CampaignEligibilityDecision()
              then
                $out.addEligibleCampaign($c.getCampaignCode());
              end

 12. Infra Recommendation
 For a medium budget deployment, run SIP-05 inside the commercial/catalog API deployment. Do not create a separate
 campaign service initially.

  Component                                                          Recommendation

  API                                                                Existing commercial/catalog API pods expose
                                                                     /api/promotional-campaigns.

  DB                                                                 Same PostgreSQL cluster/schema family as commercial catalog.

  Workers                                                            Existing worker pool handles activation/end, cap sync, cache refresh.

  Events                                                             Kafka/MSK topics under sophix.commercial.campaign.*.

  Cache                                                              Read model/cache for active campaigns by channel/franchise/region.


 AWS deployment: use existing ECS/EKS service and RDS cluster. Add CloudWatch alarms for failed activations, eligibility
 API latency, redemption duplicate spikes, cap overrun attempts, and SIP-03 assignment failures from campaign redemption.

 14. Definition Of Done
   - Campaign tables and APIs exist.

   - Campaign lifecycle, approval, validation, activation, pause, and end are implemented.

   - EM-CFG-04 is used for configurable campaign approval policies.

   - Drools rule files exist for configurable eligibility, redemption, and approval decisions.

   - Eligibility API evaluates channel/franchise/package/customer/date.

   - Redeem API creates participation and calls SIP-03 for assignment when needed.

   - Backoffice can configure and monitor campaigns.

   - Sales app can display and redeem eligible campaigns.

   - Events are emitted for reporting and cache refresh.

   - Tests cover acquisition, retention, channel restrictions, caps, and redemption.
