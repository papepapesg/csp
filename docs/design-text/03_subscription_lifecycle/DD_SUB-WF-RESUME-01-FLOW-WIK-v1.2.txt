 1. Purpose
 This DD defines the WIK operator BPMN for subscription resume.

 Process key:
          sub-resume-wik

 This BPMN implements the parent resume contract from DD_SUB-WF-RESUME-01-Subscription_Resume-v1.2.md for
 WIK.

 The WIK resume flow handles all four resume triggers:
          CUSTOMER_REQUESTED_RESUME
          ADMIN_FORCE_RESUME
          DUNNING_RESUME
          SCHEDULED_AUTO_RESUME

 The flow is:
          validate -> PENDING_RESUME -> compute billing window -> emit billing intent -> optional reconnection fee payment -> reacti

 The optional pay-first gate exists in the BPMN, but it is dormant for WIK v1.2 default config because
 reconnection_fee_on_customer_resume = false.

 6. Happy Path BPMN
           Start
             -> update operation state VALIDATING
             -> drools-decide
             -> gateway: eligible and origin allowed?
                 no -> resume rejected path
                 yes
             -> update operation state PENDING_STATE_FLIP
             -> sub-lm-put-pending-status
             -> sub-lm-compute-cycle-window
             -> update operation state BILLING_CALL
             -> bil01-emit-intent
             -> gateway: requiresReconnectionFeePayment?
                 yes -> bil01-charge-pre-authorize -> wait payment-confirmed -> bil01-confirm-charge
                 no -> continue
             -> gateway: DUNNING_RESUME debt cleared?
                 no -> resume rejected path
                 yes or not dunning -> continue
             -> update operation state FULFILLMENT_CALL
             -> ful-call-activate
             -> update operation state AWAITING_FULFILLMENT_RESPONSE
             -> wait fulfillment-completed
             -> update operation state COMMITTING_FINAL_STATE
             -> sub-lm-put-master-fields
             -> sub-lm-commit-state
             -> update operation state EMITTING_EVENT
             -> kafka-emit SubscriptionResumed
             -> notification-send
             -> subscription-operation-finalize COMPLETED
             -> End

 7.4 Optional Reconnection Fee Gate
 The payment gate runs only if:
           {
               "requiresReconnectionFeePayment": true
           }

 For WIK v1.2 default config this is normally false, so BPMN skips:
           bil01-charge-pre-authorize -> payment-confirmed -> bil01-confirm-charge

 Keep the gateway in the BPMN because future WIK policy may enable a reconnection fee for
 CUSTOMER_REQUESTED_RESUME.

 7.5 ful-call-activate
 Inputs:
           {
               "subscriptionId": "sub_01HZ_KAMAU_FIBER",
               "intent": "RESUME_SERVICE",
               "policy": "RESUME_FROM_SUSPENSION",
               "fulfillmentCorrelationId": "subop_01HZ_KAMAU_RESUME:resume"
           }

 FUL-03 reactivates the customer service, for example broadband authentication and voice profile. The BPMN waits for
 fulfillment-completed or fulfillment-failed correlated by fulfillmentCorrelationId.

 7.6 sub-lm-put-master-fields
 This step closes the open pause-history row and writes resume audit fields before the state is committed.

 8. Message Catches
  Message                                       Correlation key                               Used when

  payment-confirmed                             billableEventId                               Only if reconnection fee was pre-authorized.

  fulfillment-completed                         fulfillmentCorrelationId                      FUL-03 successfully reactivated service.

  fulfillment-failed                            fulfillmentCorrelationId                      FUL-03 failed or rejected reactivation.


 Payment wait has a 7-day boundary timer. On timeout, BPMN compensates and finalizes the operation as FAILED.


 9. Drools Package
 Required package:
             rules.subscription.resume.wik

 Required decisions:

  Decision                                                          Purpose

              when

                $pause: PauseHistoryFact(subscriptionId == $req.subscriptionId, actualResumeAt == null, originIntent != "SUSPEND_NP")

                   setOriginGatingReasonCode("NOT_A_DUNNING_SUSPENSION")
                }
              end

              rule "WIK scheduled auto resume requires scheduled time"
              when
                $req: ResumeRequestFact(resumeTrigger == "SCHEDULED_AUTO_RESUME", eligible == null)
                $pause: PauseHistoryFact(subscriptionId == $req.subscriptionId, actualResumeAt == null, resumeScheduledAt == null)
              then
                modify($req) {
                   setEligible(false);
                   setEligibilityReasonCode("NO_SCHEDULED_RESUME_TIME")
                }
              end

              rule "WIK reconnection fee only for configured customer resume"
              when
                $req: ResumeRequestFact(resumeTrigger == "CUSTOMER_REQUESTED_RESUME")
                $cfg: OperatorConfigFact(reconnectionFeeOnCustomerResume == true)
              then
                modify($req) {
                   setReconnectionFeeApplicable(true)
                }
              end



 10. Compensation Paths
  Failure point                                                      BPMN compensation

  Drools rejects request                                             Emit SubscriptionResumeRejected; finalize FAILED.

  Pending status update fails                                        No committed mutation expected; emit rejected; finalize FAILED.

  Billing intent fails                                               Run sub-lm-revert-to-prior; emit rejected; finalize FAILED.

  Debt-cleared check fails                                           Run sub-lm-revert-to-prior; emit rejected with DEBT_NOT_CLEARED;
                                                                     finalize FAILED.

  Payment timeout                                                    Run bil01-revert-pending-charge; run sub-lm-revert-to-prior;
                                                                     emit rejected; finalize FAILED.

  Fulfillment fails                                                  Revert pending charge if any; run sub-lm-revert-to-prior; emit rejected;
                                                                     finalize FAILED.

  Pause-history close-out fails                                      Route to manual recovery; network may already be active.

  State commit fails                                                 Route to manual recovery.

  Kafka emit fails                                                   Outbox retries. BPMN should not mark event delivered synchronously.

  Notification fails                                                 Log and continue. Notification is reliability-isolated.




 11. Worked Example - Dunning Resume
 Kamau was suspended for non-payment on 2026-06-15. His open pause-history row has:
              {
                  "pauseId": "pause_01HZ_KAMAU_SUSPNP",
                  "originIntent": "SUSPEND_NP",
                  "systemManaged": true,
                  "dunningCycleReference": "bil04-dunning-wave-2026-06-15-L3",
                  "outstandingDebtAmount": 3500.00,
                  "outstandingDebtCurrency": "KES"
              }

 At 2026-06-22 09:55, Kamau pays. BIL-04 calls resume.

 Request:
              POST /api/subscriptions/sub_01HZ_KAMAU_FIBER/resume
              Idempotency-Key: resume-sub_01HZ_KAMAU-bil04-payment-cleared-20260622
              Content-Type: application/json

              {


SOPHIX BSS Design Documents                                                                                                                Page 7
              "operatorCode": "WIK",
              "resumeTrigger": "DUNNING_RESUME",
              "resumeReasonCode": "DEBT_CLEARED_VIA_MPESA",
              "dunningCycleReference": "bil04-resume-2026-06-22",
              "notes": "Customer paid INV_01HZ KES 3,500 via M-Pesa",
              "initiatingWorkflowKind": "BIL_04_DUNNING",
              "initiatingWorkflowRef": "bil04-resume-2026-06-22"
          }

 Runtime result:
          API validates request
            -> loads SUB-LM subscription summary: SUSPENDED
            -> loads WIK resume config and open SUSPEND_NP pause row
            -> Drools accepts DUNNING_RESUME on SUSPEND_NP
            -> framework creates operation subop_01HZ_KAMAU_RESUME
            -> Camunda starts sub-resume-wik
            -> subscription moves SUSPENDED -> PENDING_RESUME
            -> billing receives RESUME_NP_INTENT and confirms debt cleared
            -> reconnection fee gate is skipped
            -> FUL-03 reactivates service
            -> pause-history row is closed with resumeReasonCode=DEBT_CLEARED_VIA_MPESA
            -> subscription moves PENDING_RESUME -> ACTIVE
            -> SubscriptionResumed event is emitted
            -> notification is sent
            -> operation is COMPLETED

 After success:

   - Subscription status is ACTIVE.

   - Customer service is restored.

   - Open pause-history row now has actual_resume_at.

   - BIL-02 resumes cycle accrual from the resume event.

   - BIL-04 closes the dunning loop.


 12. Worked Example - Scheduled Auto Resume
 Njeri paused her WIK subscription for 30 days. The pause row has:
          {
              "pauseId": "pause_01HZ_NJERI_VAC",
              "originIntent": "CUSTOMER_REQUESTED_PAUSE",
              "resumeScheduledAt": "2026-07-01T00:00:00+03:00",
              "actualResumeAt": null
          }

 When resume_scheduled_at is due, the scheduler calls:
          POST /api/subscriptions/sub_01HZ_NJERI_FIBER/resume
          Idempotency-Key: scheduler-resume-pause_01HZ_NJERI_VAC-20260701
          Content-Type: application/json

          {
              "operatorCode": "WIK",
              "resumeTrigger": "SCHEDULED_AUTO_RESUME",
              "resumeReasonCode": "SCHEDULED_PAUSE_EXPIRED",
              "initiatingWorkflowKind": "FOUNDATION_SCHEDULER",
              "initiatingWorkflowRef": "pause_01HZ_NJERI_VAC"
          }

 Runtime result:
          Drools confirms scheduler role and non-null resume_scheduled_at
            -> origin-intent CUSTOMER_REQUESTED_PAUSE is allowed
            -> billing receives RESUME_INTENT with no fee
            -> payment gate skipped
            -> FUL-03 reactivates service
            -> pause-history row closes
            -> subscription becomes ACTIVE

 If scheduler accidentally targets SUSPEND_NP, reject with NOT_A_SCHEDULED_RESUME.

 If scheduler targets a row with resume_scheduled_at = NULL, reject with NO_SCHEDULED_RESUME_TIME.
